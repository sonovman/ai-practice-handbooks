AI 세 개를 한 팀으로 — AI DEV DIRECTOR 점검·설치·운용

AI 코딩 도구 하나에 일을 맡기면 그 도구가 쓴 코드를 그 도구가 채점합니다. AI DEV DIRECTOR는 Claude Code·OpenAI Codex·Google Antigravity 세 CLI를 지휘(HEAD)·구현(BUILDER)·검수(REVIEWER)로 나누고, 격리 작업본·스코프 가드·실제 테스트·fail-closed 검수를 코드로 강제하는 무료(MIT) 로컬 오케스트레이터입니다. 이 편은 소스를 직접 받아 보안을 점검하고 저장소의 시험을 돌린 결과를 바탕으로, 쓸 만한 곳과 조심할 곳, 설치·연동, 네 가지 AI 앱에서의 스킬 운용, Antigravity에서 같은 개념을 쌓는 법까지 초보자 순서로 정리합니다.

독자Claude·ChatGPT·Gemini 구독 중 두 개 이상을 쓰며 AI 코딩을 더 믿을 수 있게 돌리고 싶은 실무자, 코딩 입문자 분량읽기 약 25분 · 템플릿(사전 점검·반영 관문·역할 배치 도구, 학습용 mini_triad, 검수 스킬, 프롬프트 4종, 점검 기록·시범 결과) 판1.0 · 2026. 11. 10.
한 줄 결론

써도 됩니다 — 다만 “격리된 PC·믿는 프로젝트·자동 반영 끄기·반영 직전 한 번 더 확인” 네 가지를 지킬 때입니다.

작업 중단 사유(외부 유출, 권한 우회, 원격 노출)는 찾지 못했습니다. 콘솔은 127.0.0.1에만 열리고 외부로 보내는 코드가 없으며, 권한 우회 플래그도 쓰지 않습니다. 대신 ① AI가 쓴 테스트 코드가 내 PC에서 실행되고, ② 작업 명세가 넓게 열리면 AI 설정 파일(.claude/·.mcp.json)이 통과하며, ③ 기본값이 ‘자동 반영’이라는 점은 직접 막아야 합니다. 이 편의 키트가 그 빈틈을 메웁니다.

무엇을 확인했나 — 공식 저장소(커밋 d2541ad, v3.1.8)를 받아 외부 통신·서버 노출·인증·CLI 호출 플래그·셸 실행·키 처리를 코드로 확인했고, 저장소의 시험 604개를 리눅스에서 돌렸습니다(593 통과, 실패는 대부분 윈도우 경로 전제). 스코프 가드는 직접 호출해 어떤 경로가 통과하는지 실측했습니다(2·3장). 키트 도구 4종은 시험 27개를 통과했습니다. 실제 세 CLI의 구독 로그인 세션으로 끝까지 돌리지는 못했습니다 — 그 부분은 저장소 스텁 시험과 가짜 CLI 시범으로 대신했습니다. 링크된 유튜브 영상은 제목·설명란·챕터 수준으로 확인했고(자막 전문은 확보하지 못함), 내용은 공개 저장소·제품 페이지와 일치했습니다.

02보안 점검 결과 — 중단할 이유는 없었다

요청 조건은 “보안상 문제가 있거나 오히려 성능에 악영향이면 중단”이었습니다. 아래 항목을 코드에서 확인한 결과, 중단 사유에 해당하는 것은 없었고 조건부로 쓰는 것이 맞다고 판단했습니다.

점검 항목결과판정
외부로 보내는 코드127.0.0.1 외 송신 코드·텔레메트리 없음. 외부 통신은 각 CLI가 자기 회사 서버와만안전
콘솔 노출127.0.0.1 고정(다른 주소면 실행 거부), Host·Origin 검사, 상태 변경 API는 토큰 요구 → 다른 웹사이트가 내 콘솔을 조종하기 어려움안전
권한 우회--dangerously-skip-permissions·--yolo·전체 권한 샌드박스 사용 없음. Codex는 읽기 전용, BUILDER는 ‘제안’ 방식안전
종량제 과금API 키 5종을 지우고 호출. 단 CODEX_API_KEY·Bedrock/Vertex 전환 변수는 남음주의 → 사전 점검
AI가 쓴 코드 실행검증 단계에서 AI가 만든 테스트를 내 계정 권한으로 실행(모든 코딩 에이전트 공통)주의 → 격리 환경
넓은 명세의 빈틈** 명세면 .claude/settings.json·.mcp.json·.github/workflows가 스코프 가드를 통과(실측)주의 → 반영 관문
자동 반영 기본값auto_apply: on_pass, head_proxy: true주의 → 처음엔 끄기
솔로몬(AI CEO)본체는 공개 저장소에 없고 브리지만 있음. 허용 프로젝트 목록 기본값은 비어 있음안전(쓰지 않으면 꺼짐)
성능 악영향작은 수정에는 세 번 호출하는 만큼 느리고 한도를 더 씀. 큰 변경은 ‘파일 전체 JSON’이라 출력 한도에 걸릴 수 있음용도 선택(4장)
저장소 시험 — 리눅스에서 604개 중 593 통과·11 실패·1 오류였습니다. 실패는 윈도우 드라이브 경로·codex.cmd를 전제한 시험이 대부분으로, 제작자가 밝힌 “윈도우 우선, 맥·리눅스 미검증”과 같은 경향입니다. 다만 리눅스에서 ‘자식 프로세스까지 종료’ 시험이 실패했으므로 맥·리눅스에서는 정지 버튼이 끝까지 끊는지 직접 확인하세요. 시험 하나가 쓰는 requests가 requirements.txt에 빠져 있어 함께 설치해야 시험이 끝까지 돕니다. 자세한 기록: verification-log.md.

03처음 접근과 바뀐 점

AI 코딩을 맡기는 방식이 어떻게 진화했고, 그 진화에서도 어디를 조심해야 하는지 차례로 짚습니다.

① “AI 하나가 짜고 스스로 검사” → 다른 회사 모델이 검수

처음에는 한 도구가 코드를 쓰고 “테스트 통과했습니다”라고 보고하는 방식이었습니다. 같은 모델은 자기 실수를 같은 방식으로 놓치기 쉬워, 구현과 검수를 다른 회사 모델로 나누고 그 사이에 AI가 아닌 검증기를 넣었습니다.

주의 — CLI가 두 개뿐이거나 한도 소진으로 공급자가 바뀌면 같은 회사 모델이 두 역할을 맡을 수 있습니다. Director는 이때 “독립성 낮음(REDUCED_INDEPENDENCE)” 표시를 붙이고 통과는 시킵니다. 표시를 보면 사람이 한 번 더 보세요. 키트의 role_matrix.py는 BUILDER와 REVIEWER가 같은 회사면 아예 막습니다.

② “결과를 바로 원본에” → 격리 작업본 후 반영

원본 폴더에서 바로 고치게 하던 방식은 실패하면 되돌리기 어려웠습니다. 그래서 git worktree로 만든 격리 작업본에서만 고치고, 테스트·검수를 통과한 결과만 원본에 반영하도록 바뀌었습니다.

주의 — 공개된 설정의 기본값은 auto_apply: on_pass(통과하면 자동 반영)입니다. 처음 몇 번은 off로 두고 작업본을 직접 열어 본 뒤 반영하세요. 명령줄에서는 --no-apply를 붙입니다.

③ “프롬프트로 금지” → 코드로 강제하는 스코프 가드

“이 폴더만 고쳐”라는 지시는 AI가 어길 수 있어, 허용 경로·파일 수·diff 상한을 Director가 직접 검사하도록 바뀌었습니다. .git·.agents·작업본 폴더는 명세와 무관하게 막힙니다.

주의(실측) — 그러나 HEAD가 명세를 **처럼 넓게 쓰면 .claude/settings.json(훅)·.mcp.json·.codex/·.github/workflows/·conftest.py가 통과했고, 이런 명세가 사람 승인 없이 진행됐습니다. Claude Code 공식 문서에 따르면 -p 비대화 실행은 그 폴더의 훅과 MCP 서버를 확인 창 없이 실행·연결합니다. REVIEWER(claude)가 작업본 폴더에서 돌기 때문에, 이 파일들은 반영 전에 사람이 봐야 합니다.
개선 — 키트의 apply_gate.py로 반영 직전에 걸러 내고(5장), 원하면 core/safety.py 두 줄을 고쳐 이 경로들을 아예 막을 수 있습니다(선택 패치 — 시험 회귀 없음 확인, 대신 Director가 CLAUDE.md·워크플로를 고치는 작업도 막힘). 학습용 mini_triad.py는 REVIEWER를 작업본 밖 빈 폴더에서 돌려 이 문제를 구조적으로 피합니다.

④ “API 키로 호출” → 구독 로그인 CLI만

API 키를 쓰면 호출할 때마다 요금이 붙습니다. 그래서 이미 결제 중인 구독의 공식 CLI 로그인 세션을 쓰고, 호출 직전에 환경 변수에서 API 키를 지우도록 바뀌었습니다.

주의 — 지우는 키는 5종(OPENAI·ANTHROPIC·GEMINI·GOOGLE·AZURE_OPENAI_API_KEY)입니다. CODEX_API_KEY, Claude Code의 Bedrock·Vertex·Foundry 전환 변수, 회사 PC의 다른 인증 설정은 남아 종량제로 호출될 수 있습니다. director_preflight.py가 이런 변수를 찾아 줍니다. 또 비용은 0원이 아니라 구독 한도를 세 배 가까이 더 쓰는 것이라는 점도 기억하세요.

⑤ “AI의 ‘통과했다’를 믿음” → 실제 테스트 실행

AI의 말 대신 검증기가 테스트를 실제로 돌리고, 검증 명령은 BUILDER가 손댈 수 없는 Director 설정에 둡니다.

주의 — 그 테스트는 AI가 쓴 코드이고 내 계정 권한으로 내 PC에서 실행됩니다. 비밀값(.env, 인증서)이 없는 프로젝트에서, 가능하면 별도 사용자 계정·Windows Sandbox·가상 머신에서 돌리세요. 남이 만든 저장소를 대상으로 하면 그 저장소의 .claude/settings.json·.mcp.json도 실행될 수 있으니 먼저 내용을 읽으세요.

⑥ “사람이 매번 지시” → AI CEO(솔로몬)의 발주

더 나아가 상위 AI가 무엇을 만들지 정하고 미션을 발주하는 구조(솔로몬)로 확장할 수 있게 브리지가 마련돼 있습니다.

주의 — 솔로몬 본체는 공개 저장소에 포함돼 있지 않고, Director에는 발주를 받는 브리지(토큰 인증·허용 프로젝트 목록)만 있습니다. 쓰지 않는다면 companion.json의 allowed_projects를 비워 두고 config.yaml의 solomon.allowed_roots도 비우세요. 사람 없이 목표를 정하고 반영까지 하는 구조는 편리한 만큼, 무엇이 원본에 들어갔는지 매일 확인하는 습관이 필요합니다.

04유용성과 한계 — 언제 쓰고 언제 쓰지 않나

잘 맞는 일

테스트로 확인되는 중간 크기 기능

  • 모듈 하나 + 테스트 추가
  • 버그 수정과 회귀 테스트
  • 밤새 여러 단계를 돌리는 미션(사람은 아침에 결과 확인)
  • 코드를 직접 못 읽는 사람이 ‘독립 검수’를 확보하고 싶을 때
맞지 않는 일

작거나, 크거나, 테스트가 없는 일

  • 한두 줄 수정 — 단독 에이전트가 훨씬 빠름
  • 수십 개 파일 리팩터링 — 파일 수·diff 상한과 출력 한도에 걸림
  • 테스트가 없는 UI·문서 작업 — 검증기가 할 일이 없음
  • 비밀값·실제 결제가 얽힌 코드
한계내용대응
출력 한도큰 변경도 ‘파일 전체 JSON’으로 주고받음목표를 작게 쪼개기, quick 프로필
구독 한도세 CLI의 한도에 그대로 묶이고, 소진 시 다른 CLI로 넘어감역할별 대체 순서를 미리 정하기(role_matrix.py)
플랫폼윈도우 우선, 맥·리눅스는 v3.1.8부터 코드만 지원(미검증), 콘솔은 한국어맥은 첫 실행 때 정지 버튼 동작 확인
모델 선택각 CLI 계정의 기본 모델을 씀(모델 플래그를 넘기지 않음)각 CLI 설정에서 기본 모델 지정

06세 LLM 연동과 역할 배치

Director는 모델을 직접 부르지 않고 각 회사의 공식 CLI를 부릅니다. 그래서 “LLM 연동”은 곧 CLI 설치·로그인·역할 지정입니다.

CLI회사·로그인Director가 쓰는 방식기본 역할
claudeAnthropic · Claude 구독claude --print --output-format json (승인 필요한 도구는 거부)HEAD
agyGoogle · Google 계정agy --input-format stream-json … --sandboxBUILDER
codexOpenAI · ChatGPT 계정codex exec --sandbox read-only -REVIEWER
config.yaml — 역할 바꾸기(예: agy가 없을 때)
head:
  provider: claude
builder:
  mode: proposal
  provider: codex        # agy 대신 codex
reviewer:
  provider: claude       # BUILDER와 다른 회사

콘솔의 역할 교환 버튼으로도 바꿀 수 있습니다. 어떤 배치가 안전한지는 키트 도구로 확인하세요.

역할 배치 점검
python tools\role_matrix.py --available claude,codex,agy
python tools\role_matrix.py --head claude --builder codex --reviewer codex   # → BLOCK(자기 채점)
모델 이름은 역할로 기억하세요 — 각 CLI가 쓰는 모델은 계정의 기본 모델이고, 이름은 몇 달 단위로 바뀝니다. “지휘는 계획을 잘 쓰는 모델, 구현은 코드를 빨리 쓰는 모델, 검수는 구현과 다른 회사 모델”이라는 원칙만 지키면 됩니다. CLI가 두 개뿐이면 HEAD와 BUILDER를 같은 회사로, REVIEWER만 다른 회사로 두는 편이 낫습니다(추천 결과 예시).

07플랫폼별 스킬·프로젝트로 운용하기

Director 자체는 CLI 프로그램이라 웹 채팅 앱 안에서 돌릴 수는 없습니다. 대신 ‘지휘·검수’ 역할을 스킬로 만들어 네 앱 어디서나 같은 기준으로 ORDER를 쓰고 독립 검수를 받을 수 있습니다. 키트의 triad-dev-review 스킬이 그것입니다.

웹 앱만으로 해 보는 릴레이

CLI 설치 전이라면 세 앱을 탭 세 개로 열고 결과를 손으로 옮겨 같은 원칙을 연습할 수 있습니다. HEAD는 Claude, BUILDER는 Gemini, REVIEWER는 ChatGPT처럼 구현과 검수를 다른 회사로 나눕니다. 프롬프트는 web-app-relay.md.

주의 — 웹 앱은 내 PC에서 테스트를 돌려 주지 않습니다. 구현 결과를 내 PC에 저장해 테스트를 직접 돌리고 그 출력을 검수 앱에 넣어야 “말로만 통과”를 막을 수 있습니다. 스킬 업로드 메뉴 이름과 요금제 조건은 자주 바뀌니 처음 할 때 각 회사 도움말을 확인하세요.

08Google Antigravity로 구축하기

Antigravity는 두 가지로 씁니다. 하나는 Director의 역할 하나(BUILDER)로 붙이는 것, 다른 하나는 Antigravity 안에서 AI 도움으로 같은 개념의 작은 파이프라인을 쌓아 보는 것입니다.

A. Director의 BUILDER로 붙이기

5장 2단계로 agy를 설치·로그인하면 Director가 자동으로 찾습니다(config.yaml의 executable: null). 설치 직후 agy --version이 되는지, 그리고 Director 폴더에서 python scripts\cli_diagnostics.py가 세 CLI를 모두 인식하는지 확인합니다.

주의 — 기본 ‘제안(proposal)’ 방식에서는 agy가 임시 폴더에서 읽기만 합니다. 설정을 바꿔 agy가 작업본에 직접 쓰게 하면 Director가 사용자 전역 설정(~/.gemini/antigravity-cli/settings.json)을 실행 동안 고쳤다가 되돌리는데, 비정상 종료되면 바뀐 권한이 남을 수 있습니다. 기본값인 proposal을 유지하세요.

B. Antigravity에서 mini_triad 쌓기

키트의 mini_triad.py는 Director의 원칙 일곱 가지(격리 작업본·스코프 가드·반영 관문·외부 검증 명령·작업본 밖 독립 검수·fail-closed·API 키 제거)만 남긴 200줄 남짓의 학습용 오케스트레이터입니다. Antigravity에서 starter 폴더를 작업 공간으로 열고 antigravity-build.md를 붙여 넣으면 점검 → 역할 배치 → 연습 저장소 미션 → 보고서 요약까지 단계별로 진행합니다.

mini_triad 실행 예 (BUILDER=agy, REVIEWER=codex)
python tools\mini_triad.py --project work\demo --order work\order.json ^
  --builder "[\"agy\", \"-p\", \"{prompt}\"]" ^
  --reviewer "[\"codex\", \"exec\", \"--sandbox\", \"read-only\", \"--skip-git-repo-check\", \"-\"]" ^
  --test "python -m pytest -q"

BUILDER가 파일을 쓰려면 CLI 쪽 권한 설정이 필요할 수 있습니다(각 CLI의 --help와 권한 설정에서 작업본 쓰기만 허용). 권한 우회 플래그는 쓰지 않습니다.

시범(가짜 CLI)결과
정상 구현작업본·스코프·관문·테스트·검수 모두 통과 → PASS, 원본은 그대로, git merge 안내 (로그)
BUILDER가 .mcp.json을 심음스코프 가드에서 FAIL(허용 경로 밖·파일 수 초과) (로그)
검수 응답이 JSON이 아님FAIL(fail-closed) — 시험으로 확인
테스트 실패 · 허용 밖 쓰기각각 FAIL — 시험으로 확인
Director와의 차이 — mini_triad는 미션 반복·공급자 자동 교체·콘솔·정지 버튼이 없고, 원본 반영도 사람이 git merge로 합니다. 개념을 손으로 익히고 작은 일을 돌리는 용도입니다. 큰 일은 Director를 쓰되 이 편의 점검 도구를 함께 쓰세요.
