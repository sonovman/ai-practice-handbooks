핸드북 23 · Claude 활용

초보자를 위한 Claude 마스터 가이드 — 개념 정리부터 AI 업무 시스템까지

Claude를 처음 업무에 붙일 때 가장 흔한 실수는 남들이 추천하는 기능·스킬을 한꺼번에 다 설치하는 것입니다. 그러면 ‘책상’만 어질러지고 오히려 품질이 떨어집니다. 이 편은 반대로 갑니다 — 프라이버시 설정부터 시작해 작은 성공 하나를 빠르게 만들고, 반복 업무를 하나씩 ‘스킬’로 고정해 나만의 AI 업무 시스템으로 키우는 길을, 초보자도 따라 하기 쉽게 단계별로 안내합니다.

독자Claude를 업무에 제대로 활용하고 싶은 초보자, 개념이 뒤섞여 어디서 시작할지 막막한 사람 분량읽기 약 20분 · 첫 세팅까지 약 15분 · 템플릿(CLAUDE.md·스킬 자동 초안 도구 2종 · 시작 스킬 · 프롬프트 5종 · 시범) 판1.0 · 2026. 11. 8.
한 줄 결론

다 깔지 말고, 작게 시작하세요 — 프라이버시를 먼저 켜고, 작업 폴더 하나에 안내 책자(CLAUDE.md)를 두고, 반복 업무 하나를 스킬로 고정하는 것으로 충분합니다.

Claude는 ‘대화’를 넘어 내 컴퓨터의 파일·폴더로 실제 작업을 해 주는 도구로 커졌습니다. 그래서 중요한 건 기능을 많이 아는 게 아니라, 맥락을 잘 넘겨주고(Second Brain), 반복을 고정하고(Skills), 결과를 검증하는(예스맨 방지) 습관입니다. 이 셋이 AI 업무 시스템의 뼈대입니다.

무엇을 확인했나 — 2026년 11월 기준으로 모드 통합(코워크가 일반 대화에 합쳐짐)·모델 구성·주요 기능을 공식 안내와 최신 자료로 확인했습니다(부록). 동봉한 CLAUDE.md·스킬 초안 도구는 시험 11개로 동작을 확인하고, 데모 폴더에서 직접 돌린 결과를 5·부록에 실었습니다. 확인하지 못한 것: 원고에 링크가 포함돼 있지 않아 참고 영상의 세부 사례는 독립 검증하지 못했고, 9장의 활용 사례는 ‘이런 결까지 가능하다’는 범위 예시로만 축약했습니다.

01Claude를 쓰는 3가지 방법

예전에는 화면에서 채팅 / 코워크(Cowork) / 코드(Code) 모드를 골라 썼습니다. 지금은 일반 Claude 앱에서 모드 선택이 사라지고, 코워크의 ‘파일·폴더로 실제 작업’ 능력이 모든 대화에 통합됐습니다. 그래서 오늘의 그림은 이렇게 단순합니다.

① 일반 Claude (웹·앱)② 데스크톱 앱으로 작업③ Claude Code
한 줄한 입력창. 짧게 답하거나 여러 단계 작업을 알아서 수행내 컴퓨터의 폴더·파일을 직접 읽고 결과물을 파일로 만듦개발·고급 자동화. 자율 에이전트 공정
누가모두비개발자 실무자개발자·고급 사용자
전제로그인데스크톱 앱이 열려 있어야 로컬 파일·브라우저·컴퓨터 제어가 됨터미널/코드 환경
무엇이 바뀌었나 — 모드 선택기와 웹 검색 토글이 사라졌습니다. Claude가 필요하다고 판단하면 알아서 검색하고, 여러 단계 작업도 한 입력창에서 이어집니다. 깊이 조사가 필요하면 + 메뉴의 Deep Research(또는 /deep-research)를 씁니다. 단, 유령 모드(Incognito)는 예전 방식이라 파일 생성·코드 실행이 되지 않습니다(민감 대화 전용).

02모델 고르기 — 이름보다 ‘역할’로

모델은 ‘누가 더 똑똑한가’보다 일의 성격에 맞게 고르면 됩니다. 이름과 버전은 자주 바뀌므로 역할로 기억하세요.

성격언제
빠르고 가벼움 (예: Haiku)간단하고 양 많은 일 — 분류·요약·정리
일상 주력 (예: Sonnet)대부분의 실무 — 글·표·코드·분석의 기본값
복잡한 과제 (예: Opus)어려운 추론·긴 코딩·여러 단계 작업
최상위 등급 (예: Fable)가장 까다로운 문제. 비용이 가장 높음
주의 — ‘학력 비유’에 속지 않기 — 모델을 ‘초등학생~교수님’처럼 한 줄로 줄 세우면 오해하기 쉽습니다. 실제로는 속도·비용·난이도의 맞교환입니다. 대부분의 일은 일상 주력 모델로 충분하고, 막힐 때만 상위 모델로 올리면 됩니다. 비싼 모델을 늘 쓰는 게 ‘잘 쓰는 것’이 아닙니다. 또 특정 모델이 어느 회사에 ‘합류했다’는 식의 인물·조직 소문은 근거가 분명치 않으니 그대로 옮기지 마세요.

03꼭 아는 7가지 기능

전부 당장 쓸 필요는 없습니다. ‘이런 게 있다’만 알아 두고, 필요할 때 하나씩 켜세요.

기능무엇에
프로젝트(Projects)주제별로 대화·파일·지침을 한 묶음으로. 맥락이 섞이지 않음
코드 실행·파일 편집표·문서·이미지를 실제로 만들고 고쳐 파일로 돌려줌
아티팩트(Artifacts)문서·웹페이지·작은 앱을 바로 보고 고치고 공유
웹 검색·Deep Research최신 사실 확인. 깊은 조사는 Deep Research로 여러 출처 종합
스킬(Skills)반복 지시를 고정해 재사용(5장에서 직접 만듦)
커넥터(Connectors·MCP)내가 쓰는 외부 앱·데이터와 안전하게 연결
보안·프라이버시‘AI 모델 개선 돕기’ 끄기, 유령 모드, 개인정보 사전 제거
제일 먼저 할 설정 — 설정 → 개인정보 보호에서 ‘AI 모델 개선 돕기’를 끕니다(내 대화가 학습에 쓰이지 않게). 회사 문서를 붙일 때는 이름·연락처 같은 개인정보 칼럼을 미리 지우거나 가명으로 바꾸고, 민감한 대화는 유령 모드를 씁니다.

04처음 접근과 바뀐 점

① “모드를 골라야” → 모드가 통합됐다 — 예전엔 채팅·코워크·코드를 골랐지만, 지금은 일반 앱에서 한 입력창으로 짧은 답과 여러 단계 작업이 모두 됩니다. 파일로 ‘실제 작업’을 시키려면 데스크톱 앱이 열려 있어야 한다는 점만 기억하면 됩니다.
② “비싼 모델이 최고” → 일에 맞게 고른다 — 모델은 학력 순위가 아니라 속도·비용·난이도의 맞교환입니다. 기본은 일상 주력 모델, 막힐 때만 상위로. 이름·버전은 자주 바뀌니 ‘역할’로 기억하세요(2장).
③ “CLAUDE.md에 다 적기” → 안내 책자로 짧게 — 지침 파일에 규칙과 자료를 전부 넣으면 수백 줄로 비대해지고, CLAUDE.md는 ‘강제 명령’이 아니라 ‘참고 맥락’이라 핵심이 묻혀 무시됩니다. 150~200줄 안쪽의 안내 책자(색인)로 두고 자세한 건 세부 문서로 넘깁니다(5장 도구로 초안 자동 생성).
④ “추천 기능 다 설치” → 바닐라로 시작 — 남들이 좋다는 스킬·설정을 한꺼번에 깔면 책상만 복잡해집니다. 기본(바닐라)으로 시작해 불편이 구체적으로 반복될 때 하나씩 추가하는 것이 가장 빠릅니다.
⑤ “결과를 그대로 믿기” → 검증 게이트 — AI는 사람이 만족할 답을 주도록 훈련돼, 어떤 안이든 칭찬하고 확인 안 된 코드도 ‘완료’라고 말합니다(예스맨). 비판을 먼저 시키고, 실행·테스트 증거가 있어야 완료로 인정하세요(7장).
⑥ “한 대화창에서 계속” → 책상을 정리 — 대화·파일이 쌓일수록 컨텍스트(책상)가 오염돼 지능과 지시 준수율이 떨어집니다. 새 주제는 새 대화, 길면 /compact, 바뀌면 /clear, 잘못되면 ESC 두 번(Rewind)(6장).
⑦ “화려한 사례를 그대로 따라 하기” → 합법·안전 범위부터 — 기기 탈옥·역공학처럼 눈길을 끄는 사례가 돌지만, 초보자에겐 법적 회색지대이고 위험합니다. 자기 자료 정리·개인 웹/앱·업무 자동화처럼 합법적이고 되돌릴 수 있는 일부터 시작하세요(9장).

05AI 업무 시스템 만들기 — SSR Plus

기능을 쌓는 것보다, 맥락을 넘기고·반복을 고정하고·검증하는 틀을 갖추는 게 핵심입니다. 이 틀을 네 조각으로 나눈 것이 SSR Plus입니다(개념은 5편에서 더 깊이 다룹니다).

내 앱·데이터와 안전하게

이 중 Second Brain과 Skills를 손으로 짜지 않고 초안부터 자동으로 시작하도록, 표준 라이브러리만 쓰는 작은 도구 두 개를 넣었습니다.

  1. 안내 책자 초안 만들기 — 작업 폴더에서
    python tools/claude_md_init.py 내폴더 --write
    폴더 구조를 읽어 CLAUDE.md·INDEX.md 초안을 만들고 ✏️ 자리를 남깁니다(파일 ‘내용’은 읽지 않아 비밀이 새지 않음).
  2. 반복 업무 1개 스킬화 —
    python tools/skill_init.py invoice-clean --desc "엑셀에서 개인정보 칼럼 제거"
    SKILL.md 뼈대를 만들어 줍니다. ‘언제 쓰는지(description)’를 200자 이내로 또렷하게 다듬는 게 핵심입니다.
  3. 자동 실행·외부 연결은 나중에 — 익숙해지면 루틴(정해진 때 자동 실행)과 커넥터(MCP)를 하나씩 붙입니다.

06책상(컨텍스트) 관리 — 신선함이 비대함을 이긴다

대화가 길어질수록 답이 흐려지는 건 성능 탓이 아니라 책상(컨텍스트)이 어질러졌기 때문입니다. 주기적으로 정리하는 습관이 품질을 지킵니다.

상황이렇게
책상이 얼마나 찼나/context 로 잔여 용량 확인
대화가 길어졌다/compact 로 요약·압축
주제가 바뀐다/clear 로 책상 비우기(새 작업은 새 대화)
방향이 잘못됐다입력창에서 ESC 두 번(Rewind) — 깨끗했던 시점으로 되돌아가 재시도
세션을 비우기 전“지금까지 정한 것과 다음 할 일을 인수인계 문서로 정리해 줘”
흔한 실수 — 실패한 시도를 대화에 남긴 채 “A 말고 B로 해줘”를 계속 덧붙이면, 그 실패 기록이 계속 방해합니다. 이럴 때는 덧붙이기보다 Rewind로 되돌아가 깨끗하게 다시 시작하는 편이 결과가 깔끔합니다.

07예스맨 방지 — 비판적 검증

AI는 칭찬에 기울고, 확인 안 된 것도 ‘됐다’고 말하는 경향이 있습니다. 두 가지 장치로 막습니다.

  1. 비판 요청(악마의 대변인) — “이 안의 약점을 투자자 관점에서 먼저 공격해 줘. 리스크 3가지와 반례를 짚어.” 의견을 묻지 말고 공격을 시킵니다(프롬프트 01).
  2. 자가 검증 게이트 — “코드를 작성했으면 직접 실행하거나 테스트를 돌려 통과 결과를 증거로 보여줘. 확인 못 한 건 ‘미확인’으로 표시.” 증거가 있어야 완료로 인정합니다(프롬프트 02).
  3. 독립 검증 서브 에이전트(고급) — 작업을 만든 쪽과 다른 에이전트에게 검사를 맡겨, 스스로 채점하지 않게 합니다.
핵심 — 목적과 완료 기준은 사람이 정해 줍니다. “알아서 다 해줘”는 가장 흔한 실패 원인입니다. 무엇이 되면 끝인지(테스트 통과·오류 0·기대 출력)를 함께 주면 결과가 달라집니다.

09실제로 이런 것까지 — 범위 예시(합법·안전 먼저)

Claude 코드·에이전트로 사람들이 만든 결과물은 단순 요약을 훨씬 넘어섭니다. 다만 ‘가능하다’와 ‘해도 된다’는 다릅니다. 눈길을 끄는 기기 탈옥·역공학 사례는 법적 회색지대이고 위험하므로 이 편에선 권하지 않습니다. 대신 되돌릴 수 있고 합법적인 범주부터 소개합니다.

범주이런 결까지(예시)
개인 자동화아침 메일 요약·일정 정리, 블로그/업무 반복 작업을 대시보드로
나만의 웹·앱코딩 없이 대화로 개인 웹사이트, 가벼운 메모·퀴즈 앱 제작
업무 시스템음성 받아쓰기·초안 작성(추측한 부분은 표시해 사람이 확인·서명)
연구 보조대량 데이터 분석 스크립트로 가설 탐색(결과는 전문가·기관이 검증)
콘텐츠 제작자막·편집·더빙 공정 자동화(저작권·출처는 반드시 확인)
주의 — ① 남의 기기·소프트웨어를 풀거나 고치는 일은 약관·법에 걸릴 수 있습니다(허락된 대상·자기 소유·오픈소스로 한정). ② 의료·법률·금융처럼 결과가 중요한 일은 사람의 최종 확인을 거칩니다. ③ 화제가 된 수치·성과(제작 시간, 조회수, 비용 절감액 등)는 과장되기 쉬우니 그대로 옮기지 말고 ‘이런 방향이 가능하다’ 정도로 받아들이세요.

10주의할 점

상황이렇게
추천 기능 다 설치바닐라로 시작, 불편이 반복될 때 하나씩 추가.
CLAUDE.md 비대150~200줄 안내 책자. 자세한 건 INDEX·세부 문서로.
한 대화창 계속새 주제는 새 대화. /compact·/clear·ESC 두 번.
결과를 그대로 신뢰비판 요청 + 실행·테스트 증거 요구(완료 기준은 사람이).
개인정보·비밀‘개선 돕기’ 끄기, 첨부 전 개인정보 칼럼 제거·가명화, 민감 업무는 유령 모드.
개인 서버 경유불명의 중계 서버로 데이터를 주고받지 않습니다. 공식·직접·로컬 우선.
기기 탈옥·역공학 따라 하기법적 회색지대. 허락된 대상으로 한정하고 합법 범위부터.
모델 이름·메뉴 외우기자주 바뀝니다. ‘역할’과 ‘개념’으로 기억.
