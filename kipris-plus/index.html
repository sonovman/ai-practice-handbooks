KIPRIS Plus 특허 API 활용과 Python 연동

KIPRIS Plus(지식재산정보 활용 서비스)는 한국특허정보원이 운영하는 특허·산업재산권 정보 제공 서비스로, 개방된 특허정보를 Open API와 대량(Bulk) 데이터로 내려 줍니다. 공공데이터 개방·공유·활용 체계의 하나로 특허기술거래정보·국유판매기술·이전희망기술·기관보유기술 같은 기술거래 데이터도 공개되어 있습니다. 서비스의 구성, 요금 체계, 신청 방법, Python 호출을 공식 이용 가이드와 공공데이터포털 정보로 정리했습니다.

독자특허 데이터를 직접 받아 분석하려는 IP 담당자, 기술이전·사업화 담당자, 중소기업 실무자, 연구자 분량읽기 약 20분 · 템플릿(Python 클라이언트·오프라인 시험·API 목록) 판1.0 · 2026. 11. 7.
한 줄 결론

키는 환경변수에, 호출은 공식 주소로, 열 이름은 실제 응답에서.

KIPRIS Plus는 공식 기관이 직접 여는 API라서 중간 서버 없이 내 컴퓨터에서 바로 부르면 됩니다. 무료 이용은 계정당 월 1,000건(상품 합산)이고 초당 50건 이상 부르면 제한되므로, 처음부터 호출량을 세며 쓰는 습관이 중요합니다.

01KIPRIS Plus란

특허청(2025년 지식재산처로 개편)이 만든 특허·실용신안·디자인·상표·심판 정보를 한국특허정보원이 매일 넘겨받아 Open API·Bulk 데이터로 제공합니다. 같은 데이터를 두 창구에서 받을 수 있습니다.

plus.kipris.or.kr

KIPRIS Plus

상품 전체, 유료·대량 이용, Bulk 다운로드, 무료 학습 데이터. 회원가입 → 상품 신청 → 관리자 승인 → 마이페이지에서 인증키(REST AccessKey).

data.go.kr

공공데이터포털

KIPRIS Plus 상품 다수와 IP-Market 기술거래 API가 등록되어 있음. 개발계정은 대부분 자동승인. 무료 한도를 넘거나 Bulk가 필요하면 KIPRIS Plus로 안내됩니다.

공공데이터포털의 KIPRIS Plus 상품 페이지 제공기관은 ‘지식재산처’, 담당은 한국특허정보원 IP정보확산실로 표시됩니다(2026. 11. 7. 확인).

03기술거래 데이터 4종

기술거래 시장 확대와 중소기업의 정보 접근성 개선을 위해 공개된 데이터입니다. 원천은 한국발명진흥회가 운영하는 지식재산거래정보시스템 IP-Market이고, 국유특허 목록은 KIPRIS Plus 상품으로도 제공됩니다.

05신청 방법

  1. 회원가입plus.kipris.or.kr 오른쪽 위 회원가입 → 일반회원 / 단체회원 선택 → 약관 동의 → 이메일 인증 → 회원정보 입력. 단체회원은 관리자 승인 후 사용.
  2. 상품 확인데이터목록 → 서비스 유형별 → API에서 상품을 고르고, REST 기능별 명세서(입력·출력값)와 샘플을 봅니다.
  3. 서비스 신청상품 화면의 서비스 신청(여러 상품이면 서비스 일괄 신청) → 활용 용도·목적·이용 기간·회원 분류 입력 → 약관 동의 → 이용 신청.
  4. 승인 확인결재 유형(무료·유료·기타)에 따라 관리자 승인 → 마이페이지 → 서비스 구매내역에서 승인된 상품과 API 유형 확인.
  5. 인증키 확인마이페이지 → API KEY 관리에서 SOAP·REST 인증키 확인(필요 시 재발급). REST 기능에는 REST AccessKey를 씁니다.
  6. 브라우저로 시험상품 화면의 샘플 입력값으로 아래 주소를 열어 XML이 나오면 정상입니다.
브라우저 시험 주소 (공식 가이드 예시)
http://plus.kipris.or.kr/kipo-api/kipi/patUtiModInfoSearchSevice/getBibliographySumryInfoSearch?applicationNumber=출원번호&ServiceKey=본인의_REST_AccessKey

주소에 인증키가 그대로 들어가므로 이 화면을 캡처해 공유하지 않습니다. 공공데이터포털은 데이터 페이지에서 활용신청 → 마이페이지의 인증키(Encoding/Decoding)를 씁니다.

06Python으로 호출하기

공식 샘플은 requests·xmltodict를 씁니다. 이 편의 kipris_client.py는 같은 일을 표준 라이브러리만으로 하면서, 실무에서 자주 겪는 문제(키 노출, 1건이면 형식이 달라짐, 한도 초과)를 미리 막았습니다.

준비

  1. Python 3.8 이상명령 프롬프트에서 python --version.
  2. 인증키를 환경변수로코드나 프롬프트에 키를 적지 않습니다.
Windows 명령 프롬프트 (Mac·Linux는 export)
set KIPRIS_KEY=본인의_REST_AccessKey
python kipris_client.py biblio 1020050050026
python kipris_client.py search --title 자율주행 --rows 10 --csv result.csv
python kipris_client.py raw /kipo-api/kipi/patUtiModInfoSearchSevice/getBibliographySumryInfoSearch applicationNumber=1020050050026 --show-xml
python kipris_client.py usage
명령하는 일
biblio 출원번호공식 샘플과 같은 서지요약정보(getBibliographySumryInfoSearch)
search --title 단어발명의 명칭으로 항목별 검색(getAdvancedSearch). 입력값 이름(inventionTitle·numOfRows·pageNo)은 상품 명세서로 확인하고, 다르면 raw로
raw 경로 이름=값 …명세서의 기능 경로와 입력값을 그대로 넣어 아무 기능이나 호출
datagokr 주소/오퍼레이션 …공공데이터포털 API 호출(키는 DATA_GO_KR_KEY). 예: 국유판매기술정보 End Point + 상세기능의 오퍼레이션
--csv 파일 · --show-xml엑셀에서 바로 열리는 CSV 저장 · XML 원문 출력(태그 이름 확인용)
usage이 컴퓨터에서 이번 달 부른 횟수. 800건부터 경고

핵심 코드 — 응답을 표로

kipris_client.py 발췌
def parse_items(xml_bytes):
    root = ET.fromstring(xml_bytes)
    check_error(root)                       # 인증키 오류·한도 초과 등 오류 응답이면 멈춤
    rows = []
    for item in root.iter():
        if _local(item.tag) != "item":
            continue
        row = {}
        for child in item:                  # 열 이름을 미리 정하지 않고 받은 태그 그대로
            kids = list(child)
            if kids:
                for g in kids:
                    row[f"{_local(child.tag)}.{_local(g.tag)}"] = _text(g)
            else:
                row[_local(child.tag)] = _text(child)
        rows.append(row)                    # 1건이어도 항상 목록
    return rows

공식 Java 샘플의 주석도 “웹 페이지에 기재된 출력값은 잘못 기재된 경우가 있을 수 있으니 샘플 호출 결과로 확인된 태그를 쓰라”고 권합니다. 그래서 이 클라이언트는 열 이름을 가정하지 않고, 처음에는 --show-xml로 실제 태그를 본 뒤 필요한 열을 고르게 했습니다.

07데이터 수집 패턴

공식 FAQ가 안내하는 세 가지 방법은 모두 “먼저 출원번호 목록을 얻고, 그 번호로 필요한 기능을 다시 부른다”는 구조입니다.

Case 1

변동정보

변동정보 기능으로 날짜별 출원번호 확인 → 그 번호로 필요한 기능 재호출. 매일 새로 바뀐 것만 따라갈 때.

Case 2

항목별 전체검색

전체검색으로 출원번호와 기본 정보 → 부족한 정보만 재호출.

Case 3

자유검색

자유검색으로 출원번호 → 필요한 기능 재호출. 키워드 중심 조사.

호출량을 먼저 계산하세요 — 검색 결과 300건마다 서지·IPC·대표도면을 하나씩 더 부르면 300 + 300×3 = 1,200건으로 무료 한도를 넘습니다. 목록 검색에 이미 있는 열은 다시 부르지 않고, 대량이면 Bulk 데이터를 검토합니다.

08주의할 점

주제주의할 점바르게 이해하기
주소 철자서비스 경로의 patUtiModInfoSearchSevice를 ‘Service’로 고치지 않는다공식 주소가 ‘Sevice’ 철자다. 고치면 호출이 안 된다
인증키 이름예전 자료의 /openapi/rest/…?accessKey= 형식을 그대로 쓰지 않는다현재 매뉴얼의 REST 주소는 /kipo-api/kipi/…?ServiceKey=. 상품 명세서 주소를 따른다
결과 1건결과가 1건일 때 목록이 아닌 하나의 값으로 오는 경우를 놓치지 않는다항상 목록으로 바꿔 처리(클라이언트가 자동 처리)
출력 태그웹 명세서의 출력값 이름만 믿고 열을 고정하지 않는다실제 응답(--show-xml)에서 태그를 확인
인증키 보안키를 코드·스크린샷·AI 대화창에 넣지 않는다환경변수에 두고, 로그·오류 메시지에서는 가린다(클라이언트가 자동 처리)
무료 한도상품마다 1,000건씩이라고 생각하지 않는다모든 상품 합산 월 1,000건, 매월 1일 초기화
호출 속도반복문으로 쉬지 않고 부르지 않는다초당 50건 이상이면 제한, 비정상 호출로 판단되면 해제에 소명 필요. 클라이언트 기본값은 초당 5건
사내망접속 실패를 키 문제로 단정하지 않는다외부 인터넷·plus.kipris.or.kr 접속이 막혔는지 먼저 확인
데이터 누락API 결과만으로 “없음”이라고 결론 내리지 않는다KIPRIS 검색 화면과 비교하고, 이상하면 KIPRIS Plus에 문의
응답 속도느린 응답을 모두 내 코드 문제로 보지 않는다KIPRIS Plus의 API 상태 화면에서 시간대별 응답시간 확인
개발 지원 범위내가 짠 코드의 수정까지 고객센터에 기대하지 않는다공식 지원은 단순 호출 오류 안내까지라고 FAQ에 적혀 있다

09AI와 함께 쓰기

KIPRIS Plus는 공식 기관 API이므로 내 컴퓨터의 스크립트가 직접 부르고, 그 결과만 AI에게 넘기는 방식이 가장 깔끔합니다. 인증키는 AI에게 주지 않습니다.

  1. 수집은 스크립트로kipris_client.py … --csv result.csv로 내 컴퓨터에 저장합니다. Claude Code를 쓴다면 같은 명령을 Claude Code에게 실행시켜도 키는 환경변수에만 있습니다.
  2. 분석은 AI로CSV를 Claude·ChatGPT 등에 올려 연도별 출원 추이, 출원인 분포, 등록 상태 비율을 표·그림으로 요청합니다.
  3. 검증은 원문으로보고서에 쓰는 특허는 KIPRIS 공보로 다시 확인합니다(07편의 인용 확인 원칙).
중계 서버를 거치는 도구는 피하세요 — KIPRIS용 MCP 서버나 수집 서비스 가운데는 개인이나 제3자가 운영하는 서버를 거쳐 인증키와 검색어를 보내는 것도 있습니다. 공식 API에 직접 붙을 수 있으므로 그런 방식은 쓸 이유가 없습니다(08편과 같은 원칙).
