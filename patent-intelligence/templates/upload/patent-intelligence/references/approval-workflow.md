# 승인 워크플로와 상태관리

## 1. 상태 (tools/pi_gate.py가 work/state.json에 기록)
`INPUT_VALIDATION → ANALYSIS_DRAFTED → ANALYSIS_APPROVED → REPORT_DRAFTED → REPORT_APPROVED → FINAL_REPORT_COMPLETED → CANDIDATES_PROPOSED → CANDIDATES_APPROVED → HANDOFF_READY`
- 관문: ANALYSIS · REPORT · CANDIDATES. 앞 관문이 승인되지 않으면 다음 단계 submit이 거부된다.
- 대화가 끊기거나 다음 회차 세션에서 이어 갈 때는 먼저 `pi_gate.py status`로 어디까지 왔는지 확인한다(채팅 기억에 의존하지 않음).
- 파일을 실행할 수 없는 환경(웹 앱 일부)에서는 같은 내용을 `work/state.md`에 표로 적고 매 답변 끝에 현재 상태를 한 줄로 보여 준다.

## 2. 승인 해석
| 사용자 답 | 기록 | 다음 |
|---|---|---|
| `승인`·`동의`·`확정` | 명시 승인 | 다음 단계 |
| `계속`만 | 묵시 승인('계속') — **"계속을 ○○ 관문 승인으로 기록합니다"라고 말한다** | 다음 단계 |
| 수정·삭제·추가 지시 | 승인 아님(수정 후 재제출) | 반영 → 같은 관문 재제출(v2, v3…) |
| 추가자료 제공 | 승인 아님(추가자료 반영) | 1단계부터 필요한 만큼 다시 |
| 무응답 | 승인 아님(대기) | 멈춤 |
| 불명확 | 승인 아님 | 한 가지 질문으로 확인 |
- 프로젝트 설정 `accept_continue_as_approval: false`이면 `계속`도 불명확으로 본다(여러 사람이 같은 프로젝트를 쓸 때 권장).

## 3. 분석결과서와 기준선
- 분석결과서 구성: 자료검증, 확정사실, 미확인사항, 신규 관측, 기술동향, 경쟁사 전략, 회피설계 신호, 시장 신호, 주요 문헌, 정밀분석 예비후보, 한계와 신뢰도. 판단 문장마다 `[B01]`, `[B02]`… 태그.
- 승인되면 `승인된 분석 기준선` = 파일·판(v)·승인 방식·시각·사용자 수정사항. state.json의 `baseline`.
- 이후 새 증거가 기준선을 바꾸면 차이와 영향을 표로 보이고 재승인. 보고서에서 기준선에 없는 태그를 쓰면 `report_lint.py`가 R10 오류를 낸다.

## 4. 보고서·후보 관문
- 초안의 각 결론이 기준선 태그와 연결되는지 점검(`report_lint.py --baseline`).
- 최종 보고서 뒤 후보를 최대 5건 제안. 사용자가 선택·제거·추가하거나 분석목적을 고친 결과만 승인 대상. 승인 전 정밀분석 금지.

## 5. 정기·수시 운영
- 회차마다 새 `work/` 폴더(예: `rounds/2026-R4/`)를 만들고 직전 회차 목록을 `--previous`로 준다.
- 예약 실행(정기 작업)은 자료 수집·검증·집계·분석결과서 초안까지만 자동으로, **관문은 사람이 답할 때까지 멈춘다**.
