핸드북 34 · 구축·운영 가이드

처음 쓰는 사람을 위한 경쟁기술 인텔리전스 구축·운영 가이드

34편 본문이 왜 이렇게 설계했는지를 설명한다면, 이 가이드는 어디서부터 무엇을 누르고 무엇을 붙여 넣는지만 다룹니다. 경로를 하나 고르고, 시범 자료로 30분 동안 한 바퀴 돌려 본 뒤, 실제 WIPSON 자료로 넘어가는 순서입니다.

독자34편 키트를 처음 설치하는 IP·R&D 기획 담당자, 파이썬을 써 본 적 없는 입문자 분량읽기 약 20분 · 따라 하기 약 30분(시범 자료 한 바퀴) 판1.0 · 2026. 11. 11. (34편 1.1과 함께)
한 줄 결론

세는 일은 파이썬 도구가, 판단은 AI 초안을 사람이 확정하고, 승인은 사람이 합니다. 플랫폼은 이 분담을 어디서 실행하느냐만 다릅니다. 처음이라면 시범 자료로 “문헌 20 · 신규 7 · 동향대상 16 · 오류 1 · 경고 4”가 나오는지부터 확인하세요.

이 숫자가 나오면 도구가 제대로 설치된 것이고, 그다음은 자료만 바꿔 같은 순서를 반복하면 됩니다.

무엇을 확인했나 — 작성자가 준비한 플랫폼별 구축·운영 가이드 원고를 기초로 삼았습니다(같은 내용의 파일 두 개가 제출되어 하나로 반영). 원고의 명령과 인자는 34편 키트 소스와 하나씩 대조했고, 시범 자료로 시험 → 회차 시작 → 자료 검증 → 집계 → 관문 A 승인 → 보고서 점검(오류 0) → 관문 B 제출 → 인쇄용 HTML → Copilot용 내보내기까지 직접 돌려 이 가이드의 기대 결과를 적었습니다. Microsoft 365 Copilot·ChatGPT·Antigravity의 기능은 2026년 11월 기준 공식 안내로 확인했습니다. 예시 회사·번호·내용은 모두 가상입니다. 유튜브 링크는 제공되지 않았습니다.

02처음 접근과 바뀐 점

34편 본문은 설계 이유와 판단 기준을 촘촘히 담았습니다. 그런데 처음 읽는 분들에게서 “어디서부터 시작해야 할지 모르겠다”는 의견이 나왔습니다. 그래서 같은 키트를 따라 하는 순서로 다시 엮었습니다.

① 설계 설명 중심이던 흐름 — 처음에는 등급·점수·시장 신호 같은 판단 기준을 먼저 설명하고 설치는 뒤에 두었습니다. 입문자에게는 이 순서가 무겁습니다. 이 가이드는 경로 고르기 → 준비물 → 시범 자료 한 바퀴 → 플랫폼별 운영 순서로 바꿨고, 판단 기준은 필요할 때 본문 장으로 연결합니다.
② 낯선 말이 설명 없이 나오던 점 — 관문, 기준선, 회차, 패밀리, 공개 지연 구간 같은 말이 본문 곳곳에 나옵니다. 3장에 열두 개를 한 표로 모았습니다.
③ 기대 결과가 없던 명령 — 명령만 있으면 제대로 됐는지 알 수 없습니다. 5장의 각 명령 아래에 시범 자료로 실제로 나온 출력 줄을 적었습니다. 같은 줄이 나오면 다음으로 넘어가면 됩니다.
④ Copilot 경로의 상태 파일 위치 — 동기화 폴더에서 회차 폴더 안(rounds\2026-R4\work)에 결과를 둘 때, 관문 기록 도구도 같은 곳을 보게 해야 합니다. pi_gate.py는 기본으로 실행 위치의 work/state.json을 쓰므로, 회차를 시작할 때 init에 --state로 회차 폴더 경로를 함께 주는 줄을 넣었습니다. 이것을 빼면 나중에 reply에서 “상태 파일이 없습니다”가 나옵니다.
⑤ 에이전트와 Notebook이 읽는 파일 형식의 차이 — Copilot 에이전트는 SharePoint의 .html을 읽지만, Copilot Notebook의 참조 파일 형식에는 .html이 없습니다. Notebook을 쓸 때는 03_검증집계의 .xlsx·.txt를 쓰거나 .html을 PDF로 저장해 넣도록 적었습니다.

04공통 준비물 — 어느 경로든 같습니다

준비물은 다섯 가지입니다. 키트, WIPSON 자료, 회차 설정, 별칭표 두 개, 그리고 분석 중에 만드는 표 두 개. 아래 표의 성질 열이 중요합니다. 사실은 원자료에서 그대로, 판단은 AI 초안을 사람이 확정, 기밀은 회사가 승인한 계정에만 올립니다.

4-1. 키트 받기

  1. 전체 키트 ZIP 받기patent-intelligence-kit.zip을 받아 압축을 풉니다. starter 안에 숨김 폴더 .agents가 있어 파일을 하나씩 받으면 빠지기 쉽습니다.
  2. 시험 돌리기PC에 Python 3.9 이상이 있으면 starter 폴더에서 python tools/test_pi_tools.py. 마지막에 Ran 33 tests … OK가 나오면 됩니다. 환경에 따라 OK (skipped=2)처럼 건너뛴 시험이 표시될 수 있는데, 실패(FAILED)가 아니면 괜찮습니다.
  3. 웹 앱에 올릴 묶음Claude·ChatGPT에 올릴 스킬은 patent-intelligence.zip을 그대로 씁니다. 직접 만들려면 python build_upload.py → dist/patent-intelligence.zip(폴더가 맨 위), dist/patent-intelligence-flat.zip(SKILL.md가 맨 위), dist/patent-intelligence/(펼친 폴더).

4-4. 별칭표 두 개 — 회차가 쌓일수록 다시 씁니다

  • config/applicant_aliases.csv — 열: variant, canonical, group, english_official, english_status, source. 가나전자(주), GANA ELECTRONICS CO LTD 같은 표기를 정식 이름·그룹으로 묶습니다. 계열사도 같은 group에 넣어야 ‘독립 출원인’ 수가 부풀지 않습니다. english_status에는 확인 상태, source에는 확인 출처(공시·홈페이지·공보 영문 서지)를 적습니다. AI가 번역한 영문명을 official로 적지 않습니다.
  • config/column_aliases.csv — 열: field, alias. WIPSON 열 이름을 도구 표준 필드(app_no, pub_no, reg_no, applicant, applicant_en, priority_date, family_id, ipc, abstract, claim 등)에 잇습니다. 검증 결과에 모르는 열이 나오면 한 줄 추가합니다.

4-5. 분석 중에 만드는 표 두 개 — AI 초안, 사람 확정

  • work/clusters.csv — 열: id, cluster. id는 01_intake.json의 문헌 ID(예: D004), 기술군 이름은 focus_areas 이름을 먼저 씁니다.
  • work/scores.csv — 열: id, relevance(0~25), proximity(0~20), design_around(0~20), persistence(0~15), expansion(0~10), info_value(0~10), strategic_exception(Y/빈칸), reason. 당사 청구항이 없으면 proximity는 비웁니다(0을 넣지 않음). 범위를 벗어나면 도구가 S04 오류를 냅니다.

기밀 구분 — 공개특허 자체는 공개 정보입니다. 그러나 당사 청구항·제품 로드맵·관심 경쟁사 목록은 기밀입니다. 회사가 승인한 계정(학습 제외·데이터 보호 설정)에서만 올리고, 개인이 운영하는 공개 중계 서버나 확장 프로그램을 거치지 않습니다.

0530분 첫 실행 — 시범 자료로 한 바퀴

실제 자료를 넣기 전에 키트에 들어 있는 가상 시범 자료(sample/inbox, 5개국 20건)로 한 바퀴 돌립니다. 아래 명령은 starter 폴더에서 실행합니다. 코드 실행이 되는 AI 앱이라면 명령 대신 “아래 순서대로 실행해 줘”라고 붙여 넣어도 됩니다.

시범 한 바퀴 (Mac·Linux · Windows는 각 줄을 그대로 한 줄씩)
# 0) 시험                      → Ran 33 tests … OK
python tools/test_pi_tools.py

# 1) 회차 시작                 → 회차 2026-R4 · 상태 INPUT_VALIDATION
python tools/pi_gate.py init --round 2026-R4

# 2) 자료 검증                 → 문헌 20 · 패밀리 16 · 기술신호 15 · 신규 7 · 동향대상 16 · … · 오류 1 · 경고 4
python tools/pi_intake.py sample/inbox/this_round.xlsx --project config/project.json --previous sample/inbox/prev_round.csv --pdf-dir sample/inbox/pdf --out work/01_intake.json

# 3) 집계 (시범용 분류·점수표) → 범위 16건 · 연도 5개(미완결 시작 2025) · … · 추천 5건
python tools/pi_stats.py work/01_intake.json --clusters sample/inbox/clusters.csv --scores sample/inbox/scores.csv --out work/02_stats.json

# 4) 분석결과서 제출과 승인     → 승인된 관문: ANALYSIS
cp sample/work/03_analysis.md work/
python tools/pi_gate.py submit ANALYSIS --file work/03_analysis.md
python tools/pi_gate.py reply "승인"

# 5) 보고서 점검과 제출         → 오류 0 · 경고 0
mkdir -p work/reports
cp sample/work/reports/report.md work/reports/
python tools/report_lint.py work/reports/report.md --intake work/01_intake.json --stats work/02_stats.json --baseline work/03_analysis.md
python tools/pi_gate.py submit REPORT --file work/reports/report.md

# 6) 인쇄용 HTML               → 저장: out/report.html
python tools/render_report.py work/reports/report.md --out out/report.html

# 7) 지금 어디까지 왔나        → 승인 대기: REPORT v1
python tools/pi_gate.py status
Windows에서 — python이 안 되면 py로 바꿉니다. cp는 copy로, 경로의 /는 \로, mkdir -p는 mkdir로 바꿉니다. 오류 1건(번호 없는 문헌)과 경고 4건은 시범 자료에 일부러 넣어 둔 것이니 정상입니다.

실제 회차로 바꿀 때

시범 자료 자리에 내 자료를 넣고, 3단계 앞에서 AI가 clusters.csv·scores.csv 초안을 만들고 사람이 확인하는 단계가 들어갑니다. 4단계의 분석결과서와 5단계의 보고서도 AI가 씁니다.

실제 회차 기본 명령
python tools/pi_gate.py init --round 2026-R4
python tools/pi_intake.py inbox/this_round.xlsx --project config/project.json --previous inbox/prev_round.xlsx --pdf-dir inbox/pdf --out work/01_intake.json
# (AI가 clusters.csv · scores.csv 초안 → 사람이 확인)
python tools/pi_stats.py work/01_intake.json --clusters work/clusters.csv --scores work/scores.csv --out work/02_stats.json
# (AI가 work/03_analysis.md 작성)
python tools/pi_gate.py submit ANALYSIS --file work/03_analysis.md
python tools/pi_gate.py reply "승인"
# (AI가 work/reports/report.md 작성)
python tools/report_lint.py work/reports/report.md --intake work/01_intake.json --stats work/02_stats.json --baseline work/03_analysis.md

python tools/render_report.py work/reports/report.md --out out/report.html

AI 앱 안에서 돌릴 때 지시하는 세 가지 원칙

  1. 도구 이름과 산출물을 지정“pi_intake.py로 자료를 검증하고 01_intake.md의 오류·경고를 표로 보여 줘.”
  2. 세지 말라고 명시“숫자는 직접 세지 말고 02_stats.json 값만 인용해.” AI는 수십 건이 넘으면 건수를 틀리기 쉽습니다.
  3. 멈출 곳을 명시“ANALYSIS 관문에 제출하고 멈춰.”
첫 확인 프롬프트 (모든 앱 공통)
tools/test_pi_tools.py를 실행해 결과를 보여 줘. 다음으로 make_sample.py로 시범 자료를 만들고 pi_intake.py를 돌려 문헌 수·신규·동향대상·오류·경고 수를 알려 줘. 숫자는 도구 출력만 인용해.

“문헌 20 · 신규 7 · 동향대상 16 · 오류 1 · 경고 4”가 나오면 그 앱에서 도구가 제대로 돕니다.

06Claude — Skill + Project

Claude 앱에서는 도구 실행, 관문 진행, DOCX 최종본까지 한 곳에서 끝낼 수 있습니다. 구성은 스킬(작업 절차·도구) + 프로젝트(오케스트라 지침·고정 자료)입니다.

처음 한 번 설정

  1. 코드 실행 켜기설정 → 기능(Capabilities)에서 코드 실행과 파일 생성을 켭니다. 꺼져 있으면 도구가 돌지 않습니다.
  2. 스킬 올리기사용자 지정(Customize) → Skills → 스킬 만들기 → 업로드 → patent-intelligence.zip → 목록에서 켜기. 이미 올려 둔 적이 있으면 판 번호만 확인합니다. 메뉴 이름은 바뀔 수 있으니 현재 화면에서 찾습니다.
  3. 프로젝트 만들기Projects → 새 프로젝트. 이름 예: 경쟁기술 인텔리전스.
  4. 프로젝트 지침 넣기PROJECT_INSTRUCTIONS.md 전문을 지침(Instructions) 칸에 붙여 넣습니다. 이 지침이 AI를 자료 검증 → 분석가 → 보고서 작성자 → 편집자 순서로 바꿔 가며 일하게 하고 관문에서 멈추게 합니다.
  5. 고정 자료만 프로젝트에회차와 상관없이 다시 쓰는 것만 올립니다: project.json(기본값), applicant_aliases.csv, column_aliases.csv. 회차 자료는 대화에 첨부해 회차가 섞이지 않게 합니다.
  6. 시험프로젝트 안 새 대화에서 5장의 첫 확인 프롬프트를 실행합니다.

E. Copilot Notebook — 회차별 작업 노트

Claude·ChatGPT의 프로젝트에 해당하는 것이 Copilot Notebooks입니다. 파일뿐 아니라 SharePoint 사이트·문서 라이브러리·폴더를 참조로 추가할 수 있습니다. 역할은 이렇게 나누면 편합니다. 에이전트 = 규칙을 지키는 반복 작업자, Notebook = 회차별 작업 노트.

  1. 노트북 만들기Copilot 앱 → Notebooks → 새 노트북 → 이름 PatentIntel 2026-R4.
  2. 참조 추가SharePoint 회차 폴더를 참조로 추가합니다. 폴더 참조가 보이지 않는 환경이면 03_검증집계의 파일을 하나씩 추가합니다.
  3. 읽히는 형식 확인Notebook 참조는 .docx·.pptx·.xlsx·.pdf·.txt 등을 읽고 .html은 목록에 없습니다. scores.xlsx·clusters.xlsx·state.txt를 쓰고, 01_intake.html·02_stats.html은 브라우저에서 열어 PDF로 저장해 넣습니다.
  4. 지침지침 칸이 있으면 COPILOT_AGENT_INSTRUCTIONS 요약을 넣고, 없으면 첫 메시지로 붙여 넣습니다.
  5. 공유회차가 끝나면 노트북은 IP팀 그룹과 공유하고, 경영진에게는 최종 PDF만 배포합니다.
달라질 수 있는 것 — Notebook의 폴더 참조·지침 기능은 테넌트·라이선스·배포 시점에 따라 보이지 않을 수 있습니다. 메뉴가 없으면 에이전트 방식만 씁니다. Notebook 내용은 만든 사람이 소유한 저장 공간에 보관된다는 점도 사내 보관 정책과 함께 확인합니다.

F. 회차 운영과 관문 기록

  1. 새 회차rounds/2026-R4를 복사해 2027-R1로 바꾸고, 에이전트 지식 주소도 새 회차로 바꿉니다. 상위 rounds/를 통째로 지정하면 회차가 섞이기 쉽습니다.
  2. 초안 저장Copilot이 쓴 Word 초안을 04_분석/·05_보고서/에 저장합니다.
  3. 관문 기록에이전트는 상태 파일을 직접 쓰지 못할 수 있습니다. 담당자가 아래처럼 기록하고 export를 다시 돌려 state.txt를 갱신합니다. 파이썬을 쓸 수 없으면 state.txt를 손으로 고칩니다.
  4. 보고서 점검Word 초안을 report.md로 저장(복사해 붙여 넣기)해 report_lint.py로 확인합니다.
  5. 배포에이전트는 질문한 사람이 볼 권한이 있는 파일만 근거로 씁니다. 권한이 다른 사람은 같은 질문에 다른 답을 받을 수 있으니, 경영진에게는 최종 PDF를 고정해 배포합니다.

08ChatGPT — Skill 등록 후 Project에서

Skills가 켜진 워크스페이스라면 같은 ZIP을 그대로 올리고, 아니면 프로젝트 지침과 파일 업로드로 대신합니다. 어느 쪽이든 먼저 시험을 돌려 도구가 실행되는지 확인하는 것이 출발점입니다.

A. 먼저 확인

  • 요금제·권한: Skills는 Business·Enterprise·Healthcare·Edu 같은 업무용 워크스페이스에서 쓸 수 있고, 관리자가 권한·역할(Permissions & roles)에서 스킬 사용과 스킬 업로드를 켜 두어야 합니다.
  • 검사: 올린 스킬은 검사를 거친 뒤 쓸 수 있습니다. ‘검토 필요’로 표시되면 안내를 확인하고, ‘차단’이면 쓸 수 없습니다. 검사가 내 검토를 대신하지는 않습니다.
  • 보인다는데 쓸 수 없을 때: 설치한 스킬이 ‘이 세션에서 사용할 수 없음’으로 보인 사례가 커뮤니티에 보고되었습니다. Mac·Linux에서 ZIP을 직접 만들었다면 파일 권한을 chmod -R 644(폴더는 755)로 맞춘 뒤 다시 압축해 봅니다. 키트에 든 ZIP을 그대로 쓰면 이 문제를 피하기 쉽습니다.

B. 경로 1 — Skills가 켜진 경우

  1. 스킬 올리기사이드바 Plugins → Skills 탭 → 만들기(Create) → 내 컴퓨터에서 업로드 → patent-intelligence.zip.
  2. 활성화검사가 끝나면 켭니다.
  3. 프로젝트Projects → 새 프로젝트 → 지침에 PROJECT_INSTRUCTIONS.md 붙여 넣기 → 파일에 고정 자료(project.json 기본값, 별칭표 두 개).
  4. 시험새 대화에서 “patent-intelligence 스킬의 tools/test_pi_tools.py를 실행해 결과를 보여 줘.”

C. 경로 2 — Skills가 없을 때(프로젝트만)

  1. 지침새 프로젝트 → 지침 칸에 PROJECT_INSTRUCTIONS.md.
  2. 파일SKILL.md, references/ 8개 문서, tools/ 파이썬 9개(또는 묶은 tools.zip 하나), config/ 3개를 올립니다.
  3. 지침 끝에 한 줄“작업 시작 시 프로젝트 파일의 SKILL.md와 references를 먼저 읽고, tools.zip은 실행 공간에 풀어 실행한다.”
  4. 시험“tools.zip을 /mnt/data/kit에 풀고 test_pi_tools.py를 실행해.” → 통과하면 5장의 첫 확인 프롬프트.

D. 회차 운영

6장의 6단계 표와 프롬프트(00~06)를 그대로 씁니다. ChatGPT에서 특히 챙길 점은 세 가지입니다.

상황대응
엑셀을 보고 직접 집계하려 함프롬프트마다 “직접 세지 말고 pi_intake.py·pi_stats.py만 실행해”를 붙입니다
대화가 길어져 실행 공간이 초기화됨관문마다 work/를 ZIP으로 받아 두고, 새 대화에 첨부해 “state.json부터 이어서”
최종 DOCX파일 생성 기능으로 report.md → DOCX. 만든 뒤 쪽마다 번호·영문명 잘림 확인

09Google Antigravity — 내 PC 작업 공간 (+ Gemini 앱)

Antigravity는 starter 폴더를 작업 공간으로 열면 .agents/skills/(스킬), .agents/rules/(요청 시 규칙), AGENTS.md(항상 규칙)를 자동으로 읽습니다. 파일이 PC에 남으므로 세션이 끊겨도 work/state.json이 그대로 있다는 것이 가장 큰 장점입니다.

A. 설치와 작업 공간

  1. 설치·로그인Antigravity를 설치하고 로그인합니다. 회사 데이터 처리 정책(학습 제외 여부)을 먼저 확인합니다.
  2. Python 확인터미널에서 python --version → 3.9 이상.
  3. 폴더 열기키트 ZIP을 풀고 starter 폴더 이름을 예컨대 PatentIntel-Workspace로 바꾼 뒤 Antigravity에서 ‘폴더 열기’.
  4. 여러 작업 공간에서 함께 쓰려면스킬 폴더를 ~/.gemini/config/skills/에 복사합니다.

B. 에이전트에게 차례로 말하기

  1. 시험“AGENTS.md와 patent-intelligence 스킬을 읽고 tools 시험을 실행해 결과를 보여 줘.” → 명령 실행 승인 창에서 내용을 보고 승인.
  2. 설정“config/project.json을 이번 회차에 맞게 같이 채우자. 모르는 칸은 하나씩 물어봐.” → 4-3 표를 보며 답합니다.
  3. 자료 검증“pi_intake로 자료 검증하고 오류·경고를 표로 보여 준 뒤 멈춰.”
  4. 분석“1차 선별로 clusters.csv·scores.csv 초안을 만들고 pi_stats 결과로 분석결과서를 써. ANALYSIS 관문에 제출하고 멈춰.” CSV는 편집기에서 직접 고칠 수 있습니다.
  5. 보고서 → 최종본관문마다 “승인” 또는 수정 의견 → report_lint 오류 0 → render_report로 HTML/PDF.
  6. 다음 회차“rounds/2026-R4를 복사해 2027-R1을 만들고 직전 목록을 --previous로 써.”
