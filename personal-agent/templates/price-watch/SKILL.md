# 변동 알림 감시

## When to Use
- "○○ 가격이 바뀌면 알려 줘", "매일 ○○ 공지를 확인해 줘"처럼 같은 대상을 반복해서 확인하는 요청.
- `/cron add "every 6h" "..." --skill price-watch` 처럼 예약 작업에 붙여서 쓴다.

## Procedure
1. 요청에서 감시 대상(이름, 주소), 확인할 값, 알림 기준(예: 0.5% 이상 변동)을 정리한다. 빠진 것이 있으면 처음 한 번만 사용자에게 묻는다.
2. 웹 검색·브라우저 도구로 대상 페이지를 열어 현재 값을 확인한다. 막힌 사이트면 같은 정보를 주는 다른 공식 출처를 찾고, 어디서 확인했는지 적는다.
3. 작업 폴더의 `watch-log/<대상 이름>.md` 파일에서 지난번 값을 읽는다. 파일이 없으면 이번이 첫 확인이다.
4. 이번 값과 확인 시각, 출처 주소를 같은 파일 맨 아래에 한 줄로 덧붙인다.
5. 판단한다.
   - 첫 확인이면: "감시를 시작합니다. 현재 값: …" 한 줄로 답한다.
   - 알림 기준 이상 바뀌었으면: 이전 값 → 현재 값, 변동 폭, 출처를 세 줄 이내로 답한다.
   - 바뀌지 않았거나 기준 미만이면: 최종 답을 정확히 `[SILENT]` 한 단어로 끝낸다. 다른 글자를 붙이지 않는다.

## Pitfalls
- 페이지의 광고·추천 상품 가격을 감시 대상 가격으로 착각하지 않는다. 값 바로 옆의 상품명·항목명을 함께 확인한다.
- 값을 확인하지 못했으면 지난 값을 그대로 쓰지 말고, 실패했다고 짧게 보고한다. (조용히 넘어가면 사용자는 감시가 멈춘 줄 모른다.)
- 로그인·결제가 필요한 페이지는 열지 않는다.
- `[SILENT]` 는 "변화 없음"일 때만 쓴다.

## Verification
- `watch-log/<대상 이름>.md` 에 이번 확인 줄이 추가되었는가.
- 알림을 보냈다면 이전 값·현재 값·출처가 모두 들어 있는가.
- 변화가 없을 때 최종 답이 `[SILENT]` 한 단어인가.
