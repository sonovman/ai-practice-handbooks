# 청구항 구성요소 분해 → 한정 원장

결론(침해·무효)을 먼저 내지 않는다. 청구항을 **원자적 범위제한 명제**로 나눠 한정 원장에 올리는 것이 첫 일이다.
원자적 명제 = [대상] + [행위/속성] + [관계/조건] + [대안]이 묶인, 단일·유의미한 대응 판단이 가능한 최소 완결 한정.

## 용어 (섞어 쓰지 않는다)
- 청구항 용어(term): 문언을 이루는 단어. 해석의 재료.
- 청구한정(limitation): 해석된 청구항이 권리범위에 거는 조건. 차트의 왼쪽 열.
- 대응 요소(element): 대상 제품·선행기술에서 찾은 구체적 구성. 차트의 오른쪽 열.
- 한국 실무 대응: 청구항 용어 / 구성요소(또는 구성) / 확인대상발명·실시제품의 대응 구성.

## 7단계
1. 법적 골격: 전제부·전환구(comprising=개방, consisting of=폐쇄, consisting essentially of=반폐쇄)·본문·종속관계를 나눈다.
   개방형 전환구는 추가 구성을 허용할 뿐, 본문의 배타적 선택·부정한정을 무력화하지 못한다.
2. 범위제한 명제 추출: 대상·속성·위치/순서 관계·작동 조건·수치범위·부정한정·대안 구조를 모두 뽑는다.
3. 문법·논리 추적: 수식 대상, or/and의 연결 범위(포괄/배타), 선행사(the/said/상기)를 추적한다.
4. 최소 완결 단위로 묶기: 단어 단위로 쪼개지 않는다("controller"/"configured to"/"transmit" ✗ → "조건에 따라 데이터를 전송하도록 구성된 제어기" ○).
5. 관계·순서·대안 보존: between·after·when·or를 부품으로 만들지 말고 명제 안의 조건으로 둔다.
6. 내재적 기록 검증: 명세서·도면·출원경과에서 근거를 찾고, 거절 극복을 위해 보정·강조된 한정을 표시한다.
7. 원장 매핑: 각 명제를 원장 필드에 올리고 문언·균등·유효성 열에 연결한다(`references/ledger-schema.md`).

## 3대 시험 (분해가 맞는지)
- 삭제시험: 이 명제를 지우면 범위가 의미 있게 넓어지는가? 아니면 독립 한정이 아니다 → 통합.
- 대응시험: "대상물이 이 명제를 충족하는가?"가 단일·유의미한 질문인가? "피고 제품에 or가 있는가?"처럼 무의미하면 과분해.
- 전체성시험: 명제를 합치면 발명 전체가 누락·왜곡 없이 재현되는가? 크게 뭉쳐 한정별 심사를 피했다면 다시 나눈다.
- 주의: 분해 단계의 '삭제시험'과 균등론 단계의 '한정 형해화(vitiation)'는 다른 개념이다. 섞어 부르지 않는다.
