# Claim Chart 작성·점검

전제: claim-decompose로 만든 한정 원장(행 ID)이 있어야 한다. 없으면 먼저 분해한다.
차트는 '요지'를 비교하는 문서가 아니다. 원장의 **모든 한정 × 모든 주장 청구항 × 모든 대상물**을 하나씩 대응시킨다(Each × 3).

## 1. 차트 유형부터 정한다
| 유형 | 오른쪽 열에 오는 것 | 핵심 요건 |
|---|---|---|
| 침해(infringement) | 피고 제품의 사실 | 모든 한정 충족(문언 또는 한정별 균등) |
| 비침해 | 피고 제품의 사실 | 한정 하나의 결여면 충분 — 대신 무엇을 쓰는지 적극 설명 |
| 신규성(§102) | 단일 선행문헌 | 한 문헌이 모든 한정을 명시·내재적으로, 청구된 배열대로 개시 |
| 진보성(§103) | 복수 문헌 | 차이점 + 결합 동기 + 합리적 성공 기대를 따로 |
| 국내산업(ITC) | 특허권자·실시권자 제품 | 기술적 요건: 특허당 청구항 하나 이상 실시 |

## 2. 왼쪽 열(LHC)
- 원장의 행 ID·문언을 그대로 쓴다. 하위 한정을 한 칸에 뭉치지 않는다.
- 해석이 쟁점이거나 기능식이면 **3열**: [청구 문언] | [해석·명세서 SAM] | [대응 사실]. 가운데 열에 해석을 써 놓고 오른쪽에서 원래 문언으로 돌아가 비교하지 않는다.

## 3. 오른쪽 열(RHC) — 행마다 3박자
- **[주장]** `<대상물>`의 `<고유 부품·모듈명>`이 [ID]를 충족(불충족·개시)한다.
- **[사실]** `<자료명, 버전>`, `<쪽·단락·도면 부호 / 파일 경로·함수·행>`: 대상물 자체의 용어로 쓴 사실.
- **[설명]** 사실이 한정의 (해석된) 의미를 충족하는 이유 — "왜냐하면 …".
- 금지: 결론만(결론적 기재), 청구항 문언 되풀이(흉내), 수십 쪽 통째 인용(덤핑), "e.g.·이에 한정되지 않는"(예시 나열), "추후 보완"(자리표시자), 다른 제품·모드 짜깁기(프랑켄차트), "청구항 1 참조"만 쓴 종속항.

## 4. 특수 법리 모듈 (`references/special-doctrines.md`)
- 기능식(§112(f)): 기능 일치만으로 부족. 명세서 SAM ↔ 대상물 구조의 같음·균등을 `sam_match`로.
- 균등론: 한정별 기능·방식·결과 + 차이가 사소한 이유 + 연결 증거. 금반언·공중헌납·형해화 점검 기록.
- 진보성: 문헌별 개시 위치 + 결합 동기 + 성공 기대(독립 섹션).
- 방법 청구항: 실제 수행·수행 주체. 실행되지 않는 코드는 증거가 아님.

## 5. 날짜·대칭성
- 머리말에 특허 우선일, 대상물 버전·일자를 적는다.
- 침해 증거가 우선일보다 앞서면 경고: 그 자료가 오히려 선행기술이 된다.
- 균등론·넓은 해석을 썼다면 같은 넓이로 선행기술을 다시 본다(`symmetry`).

## 6. 점검
- `python tools/chart_lint.py 차트.json` → 오류(E) 0건까지 수정, 경고(W)는 사람이 판단해 기록.
- `python tools/render_chart.py 차트.json` → 보고용 표. `--ledger`로 원장 9열.
