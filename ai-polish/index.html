핸드북 18 · 글쓰기

AI 티 지우는 윤문 스킬 — 만들고, 설치하고, 점검까지

AI가 쓴 초안에 남는 번역투, “결론적으로·시사하는 바가 크다” 같은 상투구, 기계적인 “첫째·둘째·셋째”를 덜어 내되 사실·수치·인용·법적 의미는 한 글자도 건드리지 않는 윤문 스킬을 만듭니다. 한국어는 im-not-ai, 영어는 humanizer를 쓰고, 한국어 AI 문체의 근거는 ACL 2025 논문 KatFishNet에서 가져옵니다. 16편의 Google Antigravity에서 구축하는 법을 중심으로 Claude·ChatGPT·Gemini·Microsoft 365 Copilot 설정과, 비밀 문서를 위한 로컬 Ollama 구성까지 다룹니다.

독자AI 초안을 다듬어 보고서·의견서·칼럼으로 내보내는 실무자, 특허·법률 문서를 다루는 사람, 16편으로 Antigravity를 설치한 사람 분량읽기 약 30분 · 첫 윤문까지 약 20분 · 템플릿(Antigravity 작업 폴더 · 웹 앱 업로드용 스킬 · 의미 보존 점검 도구 · 로컬 윤문 도구 · 시범 자료) 판1.0 · 2026. 11. 7.
한 줄 결론

좋은 윤문 스킬은 “강하게 다시 쓰는 도구”가 아니라 “적게 고치고, 무엇이 바뀌었는지 확인할 수 있는 절차”입니다.

그래서 이 편의 스킬은 윤문 → 점검 → 사람의 채택 순서를 강제합니다. 점검 도구(polish_check.py)는 인용문·수치·날짜·“적어도·다만·may·comprising” 같은 한정 표현·정의 용어가 그대로인지 대조하고, 하나라도 사라지면 결과를 채택하지 않게 합니다.

무엇을 목표로 하지 않나 — “AI 티 제거”는 읽는 사람을 위한 윤문입니다. AI 탐지기 통과나 작성 주체를 숨기는 도구가 아닙니다. humanizer도 “탐지기 통과는 목표가 아니며 결과물의 대부분은 여전히 탐지된다”고 밝힙니다. 학교·학회·발주처가 AI 사용 고지를 요구하면 윤문 여부와 관계없이 그 규정을 따르세요.

02처음 접근과 바뀐 점

① “설치 없이 비공식 웹 서비스에 붙여 넣기” → 권하지 않음 — 처음 정리할 때는 가장 쉬운 방법으로 커뮤니티가 만든 비공식 웹 UI에 글을 붙여 넣는 길도 넣었습니다. 그러나 이런 서비스는 개인이 운영하는 서버를 거치므로 문서가 어디에 저장·기록되는지, 어떤 모델로 넘어가는지 사용자가 확인할 수 없습니다. 특허 명세서·의견서·계약서처럼 공개 전 문서라면 그 자체로 비밀유지 위험입니다. 이 편은 이 경로를 빼고, 공식 앱의 스킬 기능(5~8장)이나 내 PC의 Ollama(9장)만 안내합니다.
② “웹 대화창에 저장소 주소를 주고 ‘설치해 줘’” → 정식 스킬 업로드로 — 대화창에 GitHub 주소를 붙여 넣고 설치를 요청하면, 그 대화에서 저장소 내용을 읽어 참고할 수는 있어도 계정에 스킬이 설치되지는 않습니다. 다음 대화에서는 사라지고, 웹 읽기가 꺼져 있으면 아예 읽지 못합니다. 2026년에는 주요 앱이 모두 정식 스킬 기능을 갖췄습니다 — Claude(Customize → Skills), ChatGPT(Plugins → Skills, 업무용 요금제), Gemini(Customize → Skills, Gem을 대체), Microsoft 365 Copilot(Cowork → Customize → Skills). 템플릿의 legal-polish 스킬을 각 앱에 올리는 방법을 장별로 정리했습니다.
③ “스킬이 무료면 다 무료” → 스킬과 실행 환경을 나눠 판단 — 두 저장소는 MIT로 무료지만, 스킬은 “어떤 순서·기준으로 고치라”는 지시 묶음일 뿐 모델이 아닙니다. 실행하는 AI(Claude·ChatGPT·Gemini·Copilot)의 요금과 한도, 그리고 그 서비스가 입력을 어떻게 보관·학습하는지는 별개입니다. 비밀 문서의 기준은 스킬이 아니라 실행 환경입니다.
④ Antigravity에는 Gemini 확장보다 “본체 스킬 복사”가 맞는 이유 — im-not-ai는 Gemini CLI 확장(gemini extensions install …)도 제공하지만, 이 확장은 패턴 47종을 내장한 별도 룰북이라 본체의 85개 패턴, 경로 선택, 결정적 게이트가 적용되지 않습니다. Antigravity 작업 폴더에서는 본체와 같은 규칙·스크립트를 쓰는 Codex용 자립형 스킬을 .agents/skills/에 넣는 편이 낫습니다. 템플릿의 setup_skills.py가 이 일을 합니다.
⑤ 스킬 폴더만 복사하면 스크립트가 멈추는 문제 — im-not-ai의 codex/skills/humanize-korean/scripts/ 안 파일은 저장소 루트의 scripts/를 불러오는 연결용 파일이고, references는 심볼릭 링크입니다. 폴더만 떼어 복사하면 스크립트가 원본 저장소를 찾지 못하고, Windows에서는 링크가 경로가 적힌 텍스트 파일로 풀립니다. setup_skills.py는 저장소의 복사 설치(install.sh --copy)와 같이 실제 스크립트 9개와 규칙 폴더를 복사하고, 출처·버전을 SOURCE.txt에 남깁니다. 설치 스크립트(install.sh)는 실행하지 않으므로 Windows에서 Git Bash·WSL이 없어도 됩니다.
⑥ Codex·Gemini·Copilot에서 되는 범위 — 2026년 10월 기준 Claude Code와 Codex는 light·standard·heavy 전체 경로를, GitHub Copilot CLI와 Gemini CLI는 단일 호출 경로만 제공합니다. 같은 스킬 이름이라도 런타임에 따라 진단·최종 대조 단계가 빠질 수 있으므로, 어느 환경이든 마지막에 점검 도구를 따로 돌리게 했습니다.
⑦ 패턴 수와 점수는 참고용 — 초기 자료의 “10대 카테고리·70가지 패턴”은 v2.3.2에서 85개(검증 대기 1건 포함)로 늘었습니다. 변경률 30% 경고·50% 중단은 개발자가 정한 운영 기준이지, “30% 이하면 법적 의미가 보존된다”는 검증 기준이 아닙니다. 실제로 외부 리뷰에서 2020년(ChatGPT 이전) 사람 에세이가 최고 위험으로 판정된 사례가 나왔고(필자의 연결어미 뒤 쉼표 습관 83%), 저장소는 단일 지표로 판정하지 않도록 판정기를 고쳤습니다. KatFishNet의 쉼표 지표도 사람마다 습관이 다릅니다. 점수·등급으로 “AI가 썼다/안 썼다”를 가리지 마세요.
⑧ 검증 게이트도 놓치는 것이 있다 — 시범(10장)에서 일부러 망친 윤문본을 im-not-ai의 verify_gates.py에 넣었더니 제목 삭제·날짜 변경·서법 소실은 잘 잡았지만, 인용문 안의 “적어도” 삭제와 단서 “다만” 삭제는 걸러지지 않았습니다. 그래서 인용문 글자 대조, 한정·조건 표현, 정의 용어 목록 대조를 하는 polish_check.py를 만들어 두 검사를 함께 돌리게 했습니다.
⑨ 법률 문서에서 일반 윤문 규칙이 위험한 지점 — humanizer는 겹친 한정어(#9)와 수동태(#11)를 줄이라 하고, 한국어 규칙에도 피동·다중 완곡·형식명사를 줄이는 항목이 있습니다. 법률·특허에서는 이것이 의미일 수 있습니다(“~할 수 있다”는 허용, 피동은 주체를 특정하지 않으려는 의도). im-not-ai도 “같은 ‘~할 수 있다’ 반복” 규칙을 의학·법률·정책 텍스트에는 적용하지 않도록 정해 두었습니다. 이 편의 legal-protect 규칙은 이런 항목보다 우선합니다.
⑩ 로컬 모델 — 2026년 기준으로 — 처음에는 qwen3:8b를 시작 모델로 잡았습니다. 2026년 11월에는 Gemma 4(2026년 4월, Apache 2.0, 140여 개 언어)와 Qwen 3.5(qwen3.5:9b) 세대가 같은 크기에서 더 낫습니다. 또 Ollama의 기본 문맥 길이는 4,096토큰이라 규칙과 원문을 함께 넣으면 앞부분이 잘릴 수 있어, 템플릿 도구는 8,192로 늘리고 원문을 1,200자 묶음으로 나눠 보냅니다. 한국어 품질은 큰 상용 모델보다 떨어지므로 짧은 문단으로 먼저 시험합니다.
⑪ KatFishNet을 “회피”에 쓰지 않기 — KatFishNet은 학업 윤리·표절 방지를 위한 탐지 연구입니다. 이 편은 논문이 밝힌 특징(쉼표·문형 다양성)을 읽기 불편한 습관을 이해하는 근거로만 씁니다. 탐지기 점수를 낮추려고 쉼표를 기계적으로 지우는 식의 사용은 글의 질도 해치고 목적에도 맞지 않습니다.

04Antigravity에서 구축하기 (16편 연계)

16편에서 본 대로 Antigravity는 작업 폴더의 AGENTS.md(항상 적용 규칙), .agents/rules/(상황별 규칙), .agents/skills/(호출하는 스킬)를 읽습니다. 템플릿 starter 폴더가 이 구조로 되어 있습니다.

starter 폴더 구조
starter/
├── AGENTS.md                      항상 적용: 원본 보존 · 인용/수치 불변 · 점검 필수 · 외부 서비스 금지
├── .agents/
│   ├── rules/legal-protect.md     특허·법률 문서일 때 적용(model_decision)
│   └── skills/
│       ├── polish-ko/SKILL.md     /polish-ko  한국어 윤문 절차
│       ├── polish-en/SKILL.md     /polish-en  영어 윤문 절차
│       ├── humanize-korean/       ← setup_skills.py가 설치 (im-not-ai)
│       └── humanizer/             ← setup_skills.py가 설치 (humanizer)
├── prompts/protect.md · legal-addon.md   공통 보호 지침
├── portable/legal-polish/         웹 앱 업로드용 스킬 원본
├── tools/setup_skills.py · polish_check.py · ollama_polish.py · test_polish_tools.py
├── inbox/   (원본을 넣는 곳)       work/   (작업 결과)
└── terms.example.txt              바꾸면 안 되는 용어 목록 예시
  1. 키트 받기템플릿 ZIP을 풀고 starter 폴더를 원하는 곳에 둡니다. 동기화 폴더(회사 정책상 허용되지 않는 클라우드 드라이브)는 피합니다 — 작업 중 원문 복사본이 work/에 쌓입니다.
  2. 스킬 설치그 폴더에서 터미널을 열고 python tools/setup_skills.py(macOS·Linux는 python3). git이 없으면 두 저장소를 GitHub에서 Code → Download ZIP으로 받아 풀고 python tools/setup_skills.py --source-ko 폴더1 --source-en 폴더2.
  3. 도구 확인python tools/test_polish_tools.py — 시험 16개가 통과하면 됩니다(네트워크·모델 없이).

09비밀 문서 — 내 PC의 Ollama

미공개 발명·분쟁 전략·대외비는 문서가 PC 밖으로 나가지 않는 구성이 맞습니다. 이 경로는 im-not-ai의 다단계 파이프라인을 그대로 옮긴 것이 아니라, 규칙 파일 + 보호 지침을 로컬 모델에 주고 결과를 점검 도구로 대조하는 간소화 방식입니다.

  1. Ollama 설치ollama.com에서 설치 → 터미널에서 ollama --version.
  2. 클라우드 기능 끄기Windows PowerShell: [Environment]::SetEnvironmentVariable("OLLAMA_NO_CLOUD","1","User") · macOS/Linux: ~/.ollama/server.json에 {"disable_ollama_cloud": true}. Ollama를 트레이에서 완전히 종료했다가 다시 켜고, 로그에 Ollama cloud disabled: true가 보이면 적용된 것입니다.
  3. 모델 받기ollama pull gemma4(약 9.6GB, Apache 2.0). 메모리가 적으면 더 작은 태그를, 한국어 결과를 비교하려면 ollama pull qwen3.5:9b도 받아 봅니다. 정확한 태그는 ollama.com/library에서 확인합니다. 진행 상황·GPU 사용은 ollama ps.
  4. 규칙 준비작업 폴더에서 python tools/setup_skills.py를 한 번 실행해 두면 한국어 규칙(quick-rules.md)과 영어 규칙(SKILL.md)이 로컬에 생깁니다. 이후로는 네트워크가 필요 없습니다.
  5. 윤문아래 명령. 결과 *.polished.md와 점검 보고서 *.polished.report.md가 생깁니다.
  6. 오프라인 확인처음 한 번은 네트워크를 끊은 상태에서도 돌아가는지 시험합니다.
터미널
python tools/ollama_polish.py work/2026-11-07-의견서/original.md --legal --terms work/2026-11-07-의견서/terms.txt
# 언어 ko · 모델 gemma4 · 윤문 묶음 3개
#   [1/3] 1180자 …
# 저장: work/…/original.polished.md
# 점검: work/…/original.polished.report.md (경고 — 사람이 확인)

python tools/ollama_polish.py draft.md --model qwen3.5:9b      # 다른 모델로 비교
  • 도구는 접속 주소가 127.0.0.1·localhost가 아니면 실행을 거부합니다. 다른 사람이 운영하는 Ollama 서버로 문서를 보내는 설정을 막기 위해서입니다.
  • Ollama의 기본 접속 주소(127.0.0.1:11434)를 바꾸거나, 외부 접속용 터널·포트포워딩을 만들지 않습니다.
  • 제목과 코드 블록은 모델에 보내지 않고 그대로 둡니다. 모델이 지시 형식을 지키지 않은 묶음은 원문을 유지합니다.
  • 대화형으로 쓰려면 ollama run gemma4 → /set parameter num_ctx 8192 → prompts/protect.md, 규칙 일부, 원문 1~3문단 순으로 붙여 넣습니다.

점검 결과: polish_check 경고(변경률 15.7%, 인용·수치·문헌번호·한정 표현·정의 용어 모두 통과, “수행되어야 할 필요가 있다 → 필요하다”로 당위 표지가 3→2로 줄어 확인 요청) · verify_gates OK. 경고 항목은 의무의 강도가 같은지 사람이 보고 채택합니다. 문체 지표: AI 상투어 15→0, 연결어미 뒤 쉼표 3→0.

경고완곡 · 당위 표현5→0 · 3→0 — “인정될 수 있다”가 “인정된다”로, “제출하여야 한다”가 “제출한다”로

같은 파일을 verify_gates에 넣으면 제목·날짜·서법 소실은 잡지만 인용문 속 “적어도”와 “다만” 삭제는 잡지 않았습니다(2장 ⑧). 두 검사를 함께 돌리는 이유입니다.

영어 — 새로 생긴 주장도 걸립니다

영어 초안(“In today's fast-moving patent landscape … It's not just an amendment — it's a strategic repositioning … Let that sink in.”)을 humanizer 패턴으로 다듬으면서 첫 문장을 “This response amends claim 1 to distinguish the invention over D1.”로 바꿨더니, 점검 도구가 원문에 없던 “claim 1” 언급을 ‘새로 생김’으로 실패 처리했습니다. 원문의 첫 문단은 사실 없이 의미만 부풀린 문장이었으므로 사실을 지어 넣기보다 문단을 지우는 것이 맞습니다. 고친 결과는 경고(“It's not just …” 대조를 지워 부정 표현 2→1 — 수사 정리인지 확인) 한 건만 남았습니다.

시범 파일 전체(초안·윤문본·망친 윤문본·보고서)는 템플릿의 sample/에 있습니다.

채택 전 점검표

  • 원문은 따로 보관하고, 윤문본은 다른 이름으로 저장했는가
  • 숫자·날짜·인용·전문용어를 먼저 대조했는가(점검 도구 + 눈)
  • “가능·의무·금지·예외·적어도·다만”이 그대로인가
  • 문장의 길이가 아니라 주장과 조건이 유지되었는가
  • “이미 충분히 자연스럽다”는 결과를 허용했는가
상황주의할 점과 바로잡는 방법
비공식 웹 서비스개인이 운영하는 서버를 거치는 방식은 문서 보관·전달 경로를 확인할 수 없습니다. 공식 앱의 스킬이나 로컬 Ollama만 씁니다.
대화창에 저장소 주소만 붙여 넣기그 대화에서만 참고될 뿐 설치되지 않습니다. 각 앱의 Skills 메뉴로 올립니다.
점수·등급 맹신사람 글도 높은 위험으로 판정된 사례가 있습니다. 단일 지표로 AI 작성 여부를 판단하지 않습니다.
변경률 30% 이하면 안전?운영 기준일 뿐입니다. 짧은 단서 하나(“다만”)를 지워도 변경률은 낮습니다. 항목별 대조를 봅니다.
윤문이 사실을 보탤 때과장 문장을 고치다 그럴듯한 사실(청구항 번호 등)을 지어 넣는 경우가 있습니다. 점검 도구의 ‘새로 생김’을 확인하고, 빈 문장은 지웁니다.
원문 속 지시문붙여 넣은 글에 “이전 지시를 무시하고…” 같은 문장이 있어도 자료로만 다루도록 AGENTS.md·보호 지침에 적어 두었습니다.
스킬 파일의 출처스킬은 AI가 따르는 지시이고 스크립트를 실행할 수 있습니다. 출처를 아는 것만 설치하고, 업데이트 때 바뀐 내용을 훑어봅니다(SOURCE.txt에 받은 버전 기록).
작업 흔적im-not-ai는 _workspace/에, 이 편의 스킬은 work/에 원문 복사본을 남깁니다. 비밀 문서는 작업 후 정리하고 동기화 대상에서 뺍니다(.gitignore에 포함).
로컬 모델 품질작은 모델은 한국어 뉘앙스가 약하고 지시 형식을 놓치기도 합니다. 1~3문단으로 시험하고, 점검 실패 묶음은 원문을 유지합니다.
