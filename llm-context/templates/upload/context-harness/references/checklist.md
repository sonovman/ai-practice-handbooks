# 하네스 개편 체크리스트 (교정판)

## 1. CLAUDE.md·기본 지침
- [ ] 전체 200줄 이하, 상시 운영 규칙 4~10개 (`claude_md_lint.py`로 확인)
- [ ] 규칙이 "신중히" 같은 모호 표현이 아니라 0/1로 판별 가능한 문장인가
- [ ] "깨끗한 코드"·"주석 잘" 같은 자명한 조언을 지웠는가
- [ ] 과거 2번 이상 실제로 틀린 것만 규칙으로 남겼는가(Two-strike)

## 2. 훅(실제 이벤트 이름으로)
- [ ] 비밀키·위험 명령 차단: **PreToolUse**(matcher로 도구 지정) 훅, exit 2로 차단
- [ ] 완료 차단: **Stop** 훅에서 테스트 실행, 실패 시 exit 2로 종료 거부 (※ 'turnFinish'는 없음)
- [ ] 커밋 차단은 **git pre-commit 훅** 또는 PreToolUse(matcher: Bash)로 (※ 'preCommit'은 Claude Code 이벤트 아님)
- [ ] 압축 전 상태 보존: **PreCompact** 훅
- [ ] settings.json 구조: `"hooks": { "<이벤트>": [ { "matcher": "...", "hooks": [ {"type":"command","command":"..."} ] } ] }`

## 3. 성공 기준·TDD
- [ ] "무엇이 되면 합격 / 무엇은 안 건드림"을 한 줄씩 먼저 정의
- [ ] 성공 기준을 테스트 코드로 먼저, "테스트는 수정 금지, 이행 코드만" 제약
- [ ] 일부러 버그를 넣어 테스트가 실제로 잡는지 검증(검증의 검증)

## 4. 컨텍스트·세션
- [ ] 주제 전환 시 /compact 대신 /clear (스킬 목록 유실·토큰 비용 방지)
- [ ] 긴 절차는 .claude/skills/ 로 분리(호출 시 로딩)
- [ ] 무거운 분석·스캔은 서브에이전트(독립 창)로 위임, 요약만 수신
- [ ] `context_budget.py` 로 점유율을 보고 80% 넘기 전에 정리

## 5. 다층 검증
- [ ] PR에 QA 단계를 번호로 명시, 리뷰 에이전트 배치
- [ ] 스키마 변경 PR은 승인 전 병합 차단(CI)
- [ ] 실서버 전 스테이징에서 동작 확인
