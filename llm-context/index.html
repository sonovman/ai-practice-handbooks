핸드북 26 · 개발 도구

LLM은 어떻게 작동하고, 왜 길어지면 맥락을 잃는가 — 원리와 하네스

LLM은 본질적으로 ‘다음에 올 가장 그럴듯한 조각’을 예측하는 정교한 자동 완성 엔진입니다. 그런데 한 단어씩 예측할 뿐인데 어떻게 긴 글의 기승전결을 유지하고, 또 왜 대화가 길어지면 처음 지침을 잊어버릴까요? 이 편은 토큰화부터 셀프 어텐션·추론 모델까지 원리를 초보자용으로 풀고, 그 원리에서 곧장 맥락을 잃는 이유와 이를 통제하는 하네스(훅·슬림 지침·세션 분리) 전략을, 직접 돌려 본 두 도구와 함께 단계별로 설명합니다.

독자AI가 왜 그렇게 동작하는지 이해하고, 긴 작업에서도 규칙을 지키게 만들고 싶은 사람 분량읽기 약 25분 · 템플릿(CLAUDE.md 린터 · 컨텍스트 예산 도구 · 하네스 스킬 · 프롬프트 5종 · 교정 훅 예시) 판1.0 · 2026. 11. 8.
한 줄 결론

AI는 매 턴 모든 걸 처음부터 다시 읽습니다 — 그래서 지침은 짧고 기계적으로, 중요한 규칙은 ‘부탁’이 아니라 ‘훅’으로 강제하세요.

원리를 알면 해법이 보입니다. 어텐션은 글 전체에 비중을 나눠 주는데, 양이 커지면 비중이 분산돼 초기 규칙을 놓칩니다. CLAUDE.md는 강제 설정이 아니라 매 턴 주입되는 참고 텍스트(부탁)라, 길고 모호하면 오히려 진짜 규칙이 묻힙니다. 그래서 ① 지침을 슬림하게, ② 위험 작업·완료 선언을 훅으로 막고, ③ 주제가 바뀌면 세션을 비웁니다.

무엇을 확인했나 — CLAUDE.md 린터(시험 7개)·컨텍스트 예산 도구(시험 5개)를 직접 만들어 돌렸습니다(6·8장 시범). 훅 부분은 원고의 예시(preCommit·turnFinish)가 실제 Claude Code 이벤트와 달라, 공식 이벤트(PreToolUse·Stop·PreCompact 등)로 교정했습니다(7장·부록). 특정 인물 발언·매출 수치 같은 주장은 근거를 단정하지 않고 ‘개념’으로 다룹니다. 이 편은 유튜브 링크가 제공되지 않아 영상 자료는 쓰지 않았습니다.

01LLM이 글을 만드는 4단계

AI는 글자를 직접 읽지 못합니다. 아래 네 단계로 ‘다음 토큰’을 하나씩 고릅니다.

1토큰화

글을 조각(토큰)으로 자르고 숫자 ID 부여(학번처럼 뜻은 없음)

숫자 ID → 의미 좌표
2임베딩

ID를 수백~수천 차원 좌표(벡터)로. 비슷한 뜻은 가까이

문맥 반영
3셀프 어텐션

주변 단어와의 관련도로 고정 벡터를 ‘문맥 벡터’로 재계산

사전과 대조
4다음 토큰 예측

확률이 가장 높은 토큰 1개 출력 → 뒤에 붙여 반복(자기회귀)

비유 — 토큰 ID는 학생의 ‘학번’(순번일 뿐 뜻 없음), 임베딩은 그 학생을 ‘수학 95·체육 25·미술 30’ 같은 성적 좌표로 바꾸는 것입니다. 좌표가 되면 성향이 비슷한 단어끼리 방향이 같아져 의미 유사도를 계산할 수 있습니다.

02셀프 어텐션과 추론 모델

“강에서 배를 탔다”와 “과수원에서 배를 먹었다”의 ‘배’는 글자는 같지만 뜻이 다릅니다. 예전 임베딩은 ‘배’에 고정 좌표 하나만 줘 구별하지 못했습니다.

  1. Q·K·V 변환 — 각 토큰이 ‘내가 찾는 것(Q)’, ‘나를 나타냄(K)’, ‘넘겨줄 내용(V)’으로 나뉩니다.
  2. 어텐션 스코어 — ‘배’의 Q와 앞 단어(‘강’/‘과수원’)의 K를 내적해 관련도를 구하고, 소프트맥스로 비중으로 바꿉니다.
  3. V 가중 합산 — 그 비중으로 앞 단어의 의미(V)를 ‘배’ 벡터에 섞어 넣습니다.
  4. 층별 이동 — 여러 층을 지날수록 같은 출발점의 ‘배’가 ‘탔다’ 방향 또는 ‘먹었다’ 방향의 문맥 벡터로 이동합니다.
추론 모델(생각하는 AI) — 기본 모델은 문제 뒤에 바로 답을 찍어 복잡한 문제에서 틀리기 쉽습니다. 추론 모델은 답 전에 <think> 구역을 열어 풀이 과정(CoT)을 길게 씁니다. 풀이를 적어 두면 그게 바로 앞 문맥이 되어, 다음 토큰을 고를 때 중간 계산값이 눈앞에 있으므로 정답 확률이 크게 오릅니다. 이런 능력은 추론 시 여러 번 풀어 다수결(추론 시간 확장), 정·오답 채점(강화학습), 큰 모델의 풀이 모방(증류)으로 키웁니다.

03한 단어씩인데 어떻게 기승전결을 유지하나

입문자가 가장 의아해하는 지점입니다. 네 가지가 결합해 긴 글의 방향을 잃지 않습니다.

요소하는 일
자기회귀 루프[처음 프롬프트 + 지금까지 쓴 모든 글]을 매번 처음부터 다시 읽고 다음 1단어를 고름
셀프 어텐션바로 앞 1단어만이 아니라 글 전체의 주제·뼈대에 비중을 부여해 맥락을 압축
학습된 서사 패턴“문제→원인→해결→결론”, “기-승-전-결”을 수천억 가중치로 익혀, 서론 뒤엔 본론 토큰 확률↑
추론 모델의 징검다리(CoT)“1단계…2단계…”처럼 논리 이정표를 미리 적어 두어 결론까지 방향 유지
비유 — 한 걸음씩 걷는 여행자 — 서울에서 부산까지 매 순간 ‘한 걸음(다음 토큰)’만 내딛지만, 머릿속엔 “부산(목표)” 방향이 있고 손엔 “지금까지 온 길과 지도(이전 문맥)”가 있습니다. 한 걸음마다 지도를 다시 보므로(어텐션·자기회귀) 산으로 새지 않고 결론에 닿습니다.

04왜 길어지면 맥락을 잃나 — 바로 이 원리 때문

위 원리는 그대로 약점이 됩니다. ‘매번 전체를 다시 읽는’ 구조라, 전체가 커질수록 문제가 생깁니다.

원인설명
재입력 구조대화를 가중치에 저장하지 않고 매 턴 전체를 다시 입력 → 길수록 창이 가득 참
어텐션 희석·위치적 유실양이 늘면 비중이 분산되고, 초기 규칙은 현재 생성 시점(끝)에서 멀어져 무시됨
CLAUDE.md는 ‘부탁’강제 설정이 아니라 참고 텍스트. 길고 모호하면 90%가 잡음이 되어 진짜 규칙을 묻어 버림
압축(/compact) 손실요약 과정에서 스킬 목록·세부 규칙을 잃을 수 있고 토큰 비용도 듦
핵심 — 긴 컨텍스트에서 성능이 떨어진다는 건 여러 벤치마크에서 반복 관찰됩니다(구체 수치는 연구마다 다릅니다). 그러니 ‘더 똑똑한 모델’을 기다리기보다, 창을 짧고 또렷하게 유지하는 설계가 현실적인 해법입니다.

05처음 접근과 바뀐 점

① “말로 잘 부탁” → 결정론적 훅 — “규칙 지켜줘”는 확률적이라 확정되지 않습니다. 위험 작업·완료 선언을 훅으로 막으면 어길 수 없습니다. 평소엔 컨텍스트를 전혀 차지하지 않습니다.
② “CLAUDE.md에 다 적기” → 슬림화 — 200줄을 넘기거나 “깨끗한 코드” 같은 자명한 말로 채우면 토큰만 낭비하고 진짜 지시를 무시하게 만듭니다. 상시 규칙은 4~10개, 과거 2번 이상 틀린 것만, 0/1로 판별 가능한 문장으로(6장 도구).
③ “/compact로 압축” → /clear로 비우기 — 압축은 스킬 목록을 잃고 비용도 듭니다. 주제가 바뀌면 비용이 0인 /clear로 비우고, 반복 교정은 메모리로 재주입합니다.
④ “preCommit·turnFinish 훅” → 실제 이벤트 이름 — 흔히 쓰는 이 이름들은 실제 Claude Code 이벤트가 아닙니다. 완료 차단은 Stop, 압축 전은 PreCompact, 도구 실행 직전은 PreToolUse입니다. 커밋 차단은 git의 pre-commit 훅이거나 PreToolUse(matcher: Bash)로 합니다(7장).
⑤ “‘다 됐습니다’를 믿기” → Stop 훅 + TDD — AI는 확인 안 된 것도 완료라고 말합니다. 성공 기준을 테스트로 먼저 고정하고(테스트는 수정 금지), Stop 훅에서 테스트가 통과해야만 턴을 끝내게 합니다.
⑥ “전부 메인 세션에” → 스킬·서브에이전트로 분원화 — 모든 절차·데이터를 한 창에 넣지 말고, 절차는 스킬로(호출 시 로딩), 무거운 분석은 서브에이전트(독립 창)에 맡겨 요약만 받습니다.

06CLAUDE.md 슬림화 — 직접 점검(시범)

claude_md_lint.py로 지침 파일이 ‘짧고 기계적으로 판별 가능한지’를 점검했습니다.

$ python tools/claude_md_lint.py sample/CLAUDE-bloated.md
- 상시 규칙(번호·불릿): 12개 (권장 10개 이하) ⚠️ 초과
- 판정: 미통과(다이어트 필요)
  모호한 표현: ‘신중’ ‘최대한’ ‘적절히’ ‘알아서’ …
  자명한 조언: ‘주석을 잘’ ‘가독성’ ‘보안에 유의’ …

$ python tools/claude_md_lint.py sample/CLAUDE-slim.md
- 전체 줄: 7줄 · 상시 규칙 5개 · 판정: 통과
무엇을 배우나 — 비대한 지침은 모호·자명한 말로 가득해 어겼는지 판별이 안 됩니다. 도구가 그런 표현과 규칙 과다를 짚어 줍니다. 슬림본은 “테스트 먼저(TDD)”, “비밀키 직접 작성 금지”처럼 0/1로 판별 가능한 규칙만 남겨 통과합니다. (전/후 전체: lint-demo.md)

07하네스 훅 — 실제 이벤트로 교정

훅은 특정 시점에만 작동하고 평소엔 컨텍스트를 차지하지 않는 강제 장치입니다. 원고의 예시 이름을 실제 Claude Code 이벤트로 바로잡았습니다.

하고 싶은 것실제 이벤트 · 방법
비밀키·위험 명령 차단PreToolUse(matcher: Write/Edit/Bash) — 감지 시 exit 2로 차단
완료 차단(‘turnFinish’ ✗)Stop 훅에서 테스트 실행 — 실패 시 exit 2로 종료 거부
커밋 차단(‘preCommit’ ✗)git의 pre-commit 훅, 또는 PreToolUse(matcher: Bash)
압축 전 상태 보존PreCompact 훅
 
// .claude/settings.json  (실제 구조)
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Write|Edit|MultiEdit",
        "hooks": [ { "type": "command", "command": ".claude/hooks/protect-secrets.sh" } ] }
    ],
    "Stop": [
      { "hooks": [ { "type": "command", "command": ".claude/hooks/run-tests.sh" } ] }
    ],
    "PreCompact": [
      { "hooks": [ { "type": "command", "command": ".claude/hooks/note-before-compact.sh" } ] }
    ]
  }
}
차단 원리 — 훅은 JSON을 stdin으로 받고, exit 2를 반환하면 동작을 막고 stderr를 Claude에게 돌려줘 스스로 고치게 합니다(exit 0은 허용). 교정한 전체 예시는 corrected-harness에 있습니다. 훅 이름·형식은 버전에 따라 바뀌니 적용 전 공식 문서로 확인하세요.

08컨텍스트 예산 — 언제 정리할지(시범)

context_budget.py로 각 구성요소가 창을 얼마나 차지하는지 추정했습니다.

$ python tools/context_budget.py sample/CLAUDE-slim.md --window 200000 \
     --text-tokens 시스템프롬프트=1500 --text-tokens 대화이력=90000
- 합계: 91,600 토큰 (점유 45.9%) · 판정: 여유
| 대화이력 | 90,000 | 45.0% |   ← 세션이 커지면 여기가 지배적
| 시스템프롬프트 | 1,500 | 0.8% |
무엇을 배우나 — 점유율을 보면 무엇이 창을 먹는지 보입니다. 보통 대화 이력이 지배적이므로, 80%를 넘기 전에 /clear로 비우거나 무거운 작업을 서브에이전트로 넘깁니다. 토큰 수는 토크나이저에 따라 다른 근사치지만, ‘언제 정리할지’ 감을 잡기엔 충분합니다.

09도구별 적용과 주의할 점

‘맥락을 잃는 문제’는 모든 LLM 도구에 공통입니다. 이름만 다를 뿐 전략은 같습니다. Antigravity에는 하네스 설정 파일 초안 작성을 맡기고 적용·검증은 사람이 합니다.

상황이렇게
말로 부탁위험 작업·완료 선언은 훅으로 강제(PreToolUse·Stop).
비대한 CLAUDE.md200줄 이하·상시 규칙 4~10개. claude_md_lint.py로 점검.
모호한 규칙“신중히” 대신 0/1로 판별 가능한 문장. 과거 2번 이상 틀린 것만.
/compact 남용주제 전환 시 /clear. 반복 교정은 메모리로.
훅 이름preCommit·turnFinish는 없음. PreToolUse·Stop·PreCompact 사용, 공식 문서로 확인.
‘다 됐습니다’Stop 훅 + TDD로 테스트 통과 시에만 완료.
전부 메인 세션에절차는 스킬, 무거운 작업은 서브에이전트(요약만 수신).
인물·수치 인용특정 발언·매출 등은 근거를 단정하지 말고 개념으로.
