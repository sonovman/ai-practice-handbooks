# 특허 공보 브리프

## 언제 쓰나
- "이 공보 요약해 줘", "이 특허 한 장으로 정리해 줘"처럼 공보 한 건을 정리할 때.
- 여러 건을 비교하는 일에는 쓰지 않는다. 한 건씩 브리프를 만든 뒤 따로 비교한다.

## 먼저 읽을 것
1. 같은 폴더의 `style.md` — 문체·디자인 규칙. 반드시 지킨다.
2. 같은 폴더의 `template.html` — 결과물의 뼈대. 구조와 클래스 이름을 바꾸지 않는다.
3. 작업 폴더에 `docs/회사_키워드.md` 가 있으면 읽는다. 관련성 판단의 기준이다. 없으면 관련성은 "판단 보류"로 둔다.

## 순서
1. 공보에서 아래 항목을 찾는다. 원문에 없으면 [확인 필요]라고 적고 지어내지 않는다.
   - 공보번호, 발명의 명칭, 출원인, 출원일, 공개·등록일, IPC
2. 독립항(보통 청구항 1)을 구성요소 E1, E2, E3 …으로 나눈다. 원문 표현을 그대로 옮긴다.
3. 발명의 효과를 3개 이내로 요약한다. 각 효과 끝에 근거 단락 번호(【0000】)를 단다.
4. 회사 키워드와 겹치는 구성요소를 찾아 관련성을 "높음·보통·낮음·판단 보류" 중 하나로 정하고, 이유를 한 줄로 쓴다.
5. 다음 할 일을 1~2개 제안한다. (예: "E3 관련 자사 제품 사양 확인")
6. `template.html` 의 {{ }} 자리를 채워 `output/YYYY-MM-DD_공보번호_brief.html` 로 저장한다. output 폴더가 없으면 화면에 보여 준다.

## 점검 (저장 전에)
- {{ }} 자리표시가 하나도 남지 않았는가.
- 구성요소가 원문 청구항과 같은 순서·표현인가.
- 효과마다 단락 번호가 있는가.
- 공보에 없는 내용을 보태지 않았는가.

## 스킬 고치기
- 사용자가 "스킬 업데이트"라고 하면, 이번 대화에서 지적받은 점을 이 파일이나 `style.md` 에 반영할 수정안을 먼저 보여 주고, 승인받은 뒤 고친다.
