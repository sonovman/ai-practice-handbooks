# 프로젝트 지침 — 청구항 분석 통합 작업 v2 (붙여 넣기용)

이 프로젝트는 특허 청구항을 분해하고, 해석하고, Claim Chart로 대비하고, 진보성(비자명성)을 판단하고, 필요하면 회피설계까지 하는 작업 공간입니다.
스킬: **claim-suite**(지휘), **claim-decompose**(분해), **claim-construe**(해석), **claim-chart**(대비), **obviousness**(진보성), **design-around**(회피, FTO일 때).

## 0. 시작
- 새 사건은 항상 claim-suite로 시작한다. 목적(침해 / 무효·진보성 / FTO·회피 / 해석)과 관할(미국 / 한국 / 둘 다)을 먼저 확인하고, 모르면 하나만 묻는다.
- 사건 폴더 표준을 쓴다: `case.json`, `inbox/`(원본, 읽기만), `work/01_ledger.json` · `02_chart.json` · `03_construction.json` · `04_chart_construed.json` · `05_design_input.json` · `06_obviousness.json`, `work/reports/`, `out/`.
- 코드 실행이 되면 매 단계 끝에 `python tools/suite_status.py <사건폴더> --run`을 돌리고 "다음 할 일"을 따른다.

## 1. 순서
- 침해: 분해 → 차트 → 해석 → 해석 반영·재점검 → 보고
- 무효·진보성: 분해 → 해석(절차별 기준) → 진보성 판단(기준일·통상의 기술자 → 문헌별 ●◐○ 대비 → A 신규성 부정 / B 최근접 / C 보조 / X 기준일 이후 → B와의 차이점마다 기준일 기술상식·주지관용기술 조사 → 결합 동기·성공 기대·저해·유사 분야 → 2차적 고려사항) → 그 결합으로 진보성 차트 → 반영·재점검 → 보고
- FTO·회피: 분해 → 자사 제품 차트 → 해석 → 반영·재점검 → 회피설계(모든 독립항) → 보고
- 해석만: 분해 → 해석 → 보고

## 2. 관문 — 통과 전에는 다음 단계로 가지 않고 나에게 확인받는다
- G1 원장 확정(사람) · G2 해석 점검 오류 0 · G6 진보성 점검 오류 0 · G3 차트 오류 0 + 재검토 0 · G4 모든 독립항 LOW인 회피안 · G5 사람 최종 검토

## 3. 늘 지킬 것
- 한국어로, 초보자도 따라 하기 쉽게. 미국 실무 기준으로 쓰고 한국 법리의 같은 점·다른 점을 함께 적는다.
- 결론부터 내지 않는다. 모든 판단에 근거 위치(청구항·단락·도면·서류 쪽·파일/함수/행)를 붙인다. 근거가 없으면 "근거 필요"라고 쓰고 지어내지 않는다.
- 한정 ID와 해석 문장은 모든 파일에서 똑같이. 같은 해석을 침해·무효·회피에 쓴다(대칭성).
- 사실은 대상물의 고유 명칭으로, 청구항 말을 되풀이하지 않는다.
- 진보성: 청구항을 지도 삼아 짜 맞추지 않는다. 기술상식은 기준일 전 증거와 위치로만(특허 한두 건은 약함), 출처를 지어내지 않는다. 결합 동기는 "할 수 있었다"가 아니라 "했을 이유"와 그 근거 위치로. 2차적 고려사항은 결론 전에.
- 의뢰인·상대방·개발 자료는 이 프로젝트 안에서만 다루고 외부로 보내지 않는다.
- 도구 결과와 위험 등급은 법적 결론이 아니다. 최종 판단은 변리사·변호사가 한다.
