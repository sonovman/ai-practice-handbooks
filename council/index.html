핸드북 11 · 에이전트

AI 합의 협의체 — 관점이 다른 에이전트들이 토론해 결론을 내게 하기

한 AI에게 묻고 한 답을 받으면 그 답이 좋은지 알 길이 없습니다. LLM Council은 여러 AI가 각자 답하고, 서로 익명으로 평가하고, 의장이 종합하는 방식입니다. 공개된 구현 6곳을 비교한 뒤, 보안상 안전하고 무료이며 만들고 쓰기 쉬운 방식을 골라 토론·합의 규칙을 더한 스킬·에이전트를 Claude·ChatGPT·Gemini·Copilot 네 가지 버전으로 만들었습니다.

독자중요한 결정·계획·문안을 다각도로 검증하고 싶은 실무자, IP·법무 담당자, 팀 리더 분량읽기 약 20분 · 배포 키트(4개 플랫폼 + Claude Code 위원·의장 에이전트 + 형식 점검기) 판1.0 · 2026. 11. 7.
한 줄 결론

효과는 모델 개수가 아니라 구조에서 나온다 — 독립, 익명 검토, 반박, 그리고 합의 규칙.

이미 쓰는 AI 하나 안에서 관점을 나눠 토론시키는 방식이 추가 키·중계 서버·설치 없이 가장 안전하고 쉽습니다. 같은 모델이라 생기는 ‘다양성 착시’는 사실 확인을 원문 대조로 분리하고, 중요한 결정만 다른 플랫폼에서 한 번 더 돌려 보완합니다.

01왜 협의체인가

안드레이 카파시(Andrej Karpathy)가 공개한 llm-council은 세 단계로 움직입니다. ① 여러 모델이 각자 답하고, ② 서로의 답을 이름을 가린 채 평가·순위를 매기고, ③ 의장 모델이 종합합니다. 이름을 가리는 이유는 특정 모델에 대한 선호가 평가를 흐리지 않게 하기 위해서입니다. 이후 이 아이디어를 스킬·CLI·패키지·로컬 앱으로 옮긴 구현들이 나왔습니다.

독립

서로 못 보고 먼저 쓴다

앞 사람 의견에 끌려가는 것(앵커링)을 막습니다.

익명 검토

누가 썼는지 모르고 평가

권위나 관점 선호 대신 내용으로 평가하게 합니다.

합의

합의 정도를 밝힌다

“모두 동의” “조건부” “합의 불가”를 구분해야 결론을 얼마나 믿을지 압니다.

03추천 방식과 이유

기준은 다섯 가지였습니다: ① 데이터가 제3자 중계를 거치지 않고 실행 권한이 안전할 것 ② 이미 쓰는 구독 외 추가 비용이 없을 것 ③ 구축이 쉬울 것 ④ 사용이 쉬울 것 ⑤ 네 플랫폼에서 재현될 것.

보안무료구축사용4개 플랫폼
여러 모델 웹앱 (karpathy·free)중계·로컬 서버크레딧 / 무료 모델어려움쉬움—
패키지·CLI (sherifkozman·am-will)설계 우수 / 설정 확인 필요API·구독어려움보통일부
플랫폼 내장 관점 분리 (추천)추가 키·중계 없음추가 없음파일 하나한 문장 요청모두

추천 방식은 aiwithremy·gist 계열의 ‘플랫폼 안에서 관점 나누기’를 바탕으로, 다른 구현의 장점을 더했습니다.

가져온 것

각 구현에서

  • 익명 상호 평가 (karpathy)
  • 반박·입장 변경 라운드 (free-llm-council의 다라운드 토론을 1회로)
  • 정해진 출력 형식과 점검 (am-will·sherifkozman의 구조화)
  • 자료 속 명령문을 실행하지 않는 원칙 (am-will의 “출력은 신뢰하지 않는 입력”)
새로 더한 것

합의 규칙

  • 합의 수준 4단계와 치명적 반대 규칙
  • 입장 변경에는 이유 필수(동조 방지)
  • 신뢰도 상·중·하, [확인 필요] 목록
  • 교차 플랫폼 단계(추가 키 없이 다른 회사 모델 의견 추가)

이 추천은 6장에서 협의체 자신에게 검증받았습니다. 결과는 강한 합의, 신뢰도 중이었습니다.

04협의체 설계

IN질문 정리

결정할 것 · 선택지 · 맥락 · 걸린 것 · 판단 기준 2~4개. 진행자의 의견은 넣지 않음

1독립 의견 — 위원 5인

레드팀 · 원점 질문자 · 기회 탐색자 · 외부인 · 실행가. 각 150~250단어, 서로 보지 않음

이름 지우고 순서 섞기
2익명 상호 검토 — 응답 A~E

가장 강한 응답 · 가장 큰 맹점 · 모두 놓친 것 · 확인 필요 사실

3반박과 수정 — 1회

각 위원이 변경 / 유지 + 이유. 이유 없는 동조 금지

4합의 판정 — 의장

전원 합의 / 강한 합의 / 조건부 합의 / 합의 불가 · 치명적 반대 · 신뢰도

OUT권고 하나 + 첫 번째 할 일 하나 + 확인 필요 사항

다수와 달라도 근거가 더 강한 쪽을 따름

위원묻는 질문맞서는 위원
레드팀어디서 실패하는가, 무엇을 빠뜨렸는가기회 탐색자
원점 질문자진짜 문제는 무엇인가, 질문이 맞는가실행가
기회 탐색자잘되면 얼마나 커지는가, 놓친 이점은레드팀
외부인배경 없이 보면 무엇이 이해되지 않는가모두를 점검
실행가무엇부터 하는가, 정말 할 수 있는가원점 질문자
합의 수준조건
전원 합의다섯 위원이 같은 결론
강한 합의넷 이상 같은 결론, 치명적 반대 없음
조건부 합의특정 조건(정보 확인·소규모 시험 등)을 충족하면 같은 결론
합의 불가위에 해당하지 않거나 치명적 반대가 남음

치명적 반대 = 사실 오류, 법적 위험, 되돌릴 수 없는 손실에 근거한 반대. 한 명이라도 있으면 다수여도 강한 합의가 되지 않습니다. 소수 의견이 무시되는 것을 막는 장치입니다.

06실 사용 예제 — 이 편의 추천을 협의체에 올리다

3장의 추천이 맞는지 협의체 자신에게 물었습니다. 질문은 “소규모 IP 조직이 다관점 토론·합의 도구를 도입할 때 저장소 계열 A~E 중 무엇을 추천할까”입니다(질문 전문). 이 글을 만든 Claude 세션이 단일 대화 순차 방식으로 진행했습니다.

1단계 독립 의견 — 한 명은 반대했다

위원한 줄 입장
레드팀D, 단 같은 모델이 다섯 관점을 연기해 오류가 닮는 ‘다양성 착시’ 때문에 사실 판단 도구로 쓰지 말 것
원점 질문자D — 효과는 모델 수가 아니라 구조(독립·익명·반대 역할·합의 규칙)에서 나온다
기회 탐색자D — 4개 플랫폼 이식, IP 실무 판단 문제에 반복 활용
외부인보류 — 결론을 얼마나 믿을지, ‘무료’가 어디까지인지 알 수 없다
실행가D — 직원 혼자 10분 안에 시작할 수 있는 유일한 길

2~3단계 익명 검토와 반박 — 두 명이 입장을 바꿨다

익명 검토에서 ‘다양성 착시’ 지적과 ‘구조가 효과의 원천’이라는 판단이 각 2표로 가장 강한 의견이 됐고, 교차 플랫폼의 번거로움을 가볍게 본 의견이 맹점으로 지목됐습니다. 반박 단계에서 외부인은 “결과에 합의 수준·신뢰도·확인 목록이 나온다면” 보류를 거두었고, 기회 탐색자는 교차 플랫폼을 기본이 아닌 ‘중요한 결정에만 쓰는 선택 단계’로 낮췄습니다. 둘 다 이유를 밝혔습니다(진행 기록 전문).

4단계 합의 판정

결론 발췌 (verdict.md)
- 합의 수준: 강한 합의
- 합의된 점: D(플랫폼 내장 관점 분리 협의체)를 기본으로 추천. 결과에 합의 수준·신뢰도·확인 필요 목록을
  반드시 표시. 사실 주장은 원문으로 따로 확인.
- 남은 이견: 무료 요금제에서 어디까지 되는지, 교차 플랫폼을 얼마나 자주 쓸지
- 치명적 반대: 없음 — 레드팀의 '다양성 착시'는 사용 범위 제한으로 해소
- 신뢰도: 중 (같은 모델의 순차 진행, 무료 범위 미확인)

## 6. 첫 번째 할 일
이번 주에 실제로 고민 중인 결정 하나를 Claude 스킬로 돌리고, 같은 질문을 Gemini Gem에서 다시 돌려
두 결론의 합의 수준을 비교한다.

눈여겨볼 점은 결론이 단순한 “D가 좋다”가 아니라는 것입니다. 레드팀의 경고가 사용 범위 제한(사실 판단에 쓰지 않기)으로 결론에 들어갔고, 외부인의 요구가 출력 형식(합의 수준·신뢰도·확인 목록)으로 반영됐습니다. 이 두 가지가 실제로 키트 설계에 들어가 있습니다. 결론 전문은 verdict.md, 형식 점검 결과는 check-result.txt입니다.

08주의할 점

주제주의할 점바르게 이해하기
다양성같은 모델의 다섯 관점을 서로 다른 다섯 전문가의 독립 검증으로 여기지 않는다오류가 닮을 수 있다. 사실은 원문으로, 중요한 결정은 교차 플랫폼으로 보완
합의의 의미‘강한 합의’를 정답 보증으로 읽지 않는다주어진 정보 안에서 관점들이 수렴했다는 뜻. 신뢰도와 확인 필요 사항을 함께 본다
중계 서비스여러 모델을 쓰려고 제3자 중계 API에 업무 자료를 보내지 않는다각 플랫폼에서 따로 돌리고 결과만 붙여 넣는 교차 플랫폼으로 충분하다
실행 권한CLI 기반 도구를 쓸 때 권한 확인을 끄는 설정을 그대로 두지 않는다도구를 끄거나 읽기 전용으로 제한된 실행인지 확인한다
라이선스LICENSE가 없는 저장소의 파일을 그대로 재배포하지 않는다아이디어를 참고해 새로 쓰거나 저작자에게 확인한다
출력 형식채팅 출력과 파일 저장 지시를 한 지침에 섞어 두지 않는다형식은 하나로 정하고, 저장은 요청이 있을 때만
토론 횟수합의가 안 된다고 토론을 계속 반복시키지 않는다반박은 1회. 합의가 안 되면 ‘합의 불가’와 필요한 정보를 적는 것이 결론이다
전문 판단법률·의료·투자 결정을 협의체 결론으로 대신하지 않는다초안으로 표시하고 전문가 확인을 거친다
