# 협의체 진행 기록 — 추천 방식 검증

> 진행 방식: **단일 대화 순차** (이 핸드북을 만든 Claude 세션이 위원을 한 명씩 작성). 각 위원은 앞 위원의 글을 보지 않고 정리한 질문만 보고 쓰도록 했으나, 같은 모델이 쓴 것이므로 병렬 서브에이전트보다 독립성이 낮습니다.
> 각 저장소에 대한 사실은 2026. 11. 7. 저장소 코드·README로 확인한 범위입니다.

## 0. 정리한 질문
소규모 IP 조직이 '다관점 토론·합의' 도구를 도입한다. 선택지 A~E(질문 파일 참조) 중 무엇을 추천할지. 판단 기준: 보안(제3자 중계 없음·안전한 실행 권한), 무료(추가 비용 없음), 구축 쉬움, 사용 쉬움, 4개 플랫폼 재현성.

## 1. 독립 의견

### 레드팀
A는 질문이 OpenRouter라는 제3자 중계 서비스를 거치고 크레딧을 사야 하며, 저자가 유지보수하지 않겠다고 밝혔다. C는 여러 코딩 CLI를 내 컴퓨터에서 직접 돌린다. Claude CLI는 권한 확인 생략 플래그와 함께 실행하되 도구를 모두 끄고 한 턴만 돌리도록 막아 두었지만, 다른 CLI는 각자의 기본 권한 설정과 사용자가 덧붙이는 옵션에 따라 달라지므로 직접 확인해야 한다. CLI마다 구독과 로그인도 필요하다. E는 질문 하나에 모델 호출이 25~40회이고 Python·Node·OpenCode를 모두 띄워야 한다. '무료'는 무료 모델이 어디서 어떻게 제공되느냐에 달려 있고, 공개 관심도가 아직 낮아 검증이 덜 됐다. B는 비밀값 가림·환경변수 제한·위험 플래그 차단 등 보안 설계가 가장 꼼꼼하지만 API 사용료와 설정 부담이 크다. D가 가장 안전하지만 치명적 약점이 있다: 같은 모델이 다섯 관점을 연기하므로 오류가 서로 닮는다(다양성 착시). D를 추천하되 사실 판단 도구로 쓰지 말고, 사실 주장은 반드시 원문으로 확인하게 해야 한다.

### 원점 질문자
우리가 원하는 것은 '여러 모델'이 아니라 '검증과 합의'다. 협의체의 효과는 모델 개수보다 구조에서 나온다: 서로 못 보는 독립 의견, 익명 상호 평가, 반대 의견을 강제하는 역할, 합의 수준을 숫자처럼 밝히는 규칙. 결정·전략 질문에서는 관점의 다양성이 핵심이고, 사실 확인에서는 모델 다양성보다 원문 대조가 핵심이다(07편). 그렇다면 구조를 가장 쉽게 가져갈 수 있는 D가 맞고, 부족한 모델 다양성은 같은 질문을 다른 플랫폼에 한 번 더 묻는 방식으로 보완하면 된다.

### 기회 탐색자
D의 큰 장점은 이식성이다. 지침 파일 하나를 Claude 스킬, ChatGPT 플러그인, Gemini Gem, Copilot 에이전트로 옮길 수 있다. 이미 쓰는 구독 안에서 돌기 때문에 조직 전체에 바로 퍼뜨릴 수 있고, 경고장 대응 전략, 청구항 해석 방향, 계약 협상안처럼 IP 실무의 판단 문제에 반복해서 쓸 수 있다. '교차 플랫폼' 단계를 넣으면 추가 키 없이도 서로 다른 회사의 모델 의견을 모을 수 있다. API 예산이 있는 팀은 나중에 B로 확장하면 된다.

### 외부인
OpenRouter, 서브에이전트, BYOK, CLI 같은 말이 무엇인지 모르겠다. 내가 알고 싶은 것은 두 가지다: 이 결론을 얼마나 믿어도 되는지, 그리고 무엇을 따로 확인해야 하는지. 결과물이 그것을 보여 주지 않으면 어느 방식이든 쓸모가 없다. 또 '무료'가 정확히 무엇인지 불분명하다. 각 AI의 무료 요금제에서도 되는지, 유료 구독이 있어야 되는지 알려 줘야 한다 [확인 필요]. 이 점이 정리되기 전에는 추천을 보류하고 싶다.

### 실행가
D는 오늘 10분이면 시작한다. Claude는 스킬 ZIP 업로드, 나머지는 지침 붙여 넣기다. A·E는 Python과 Node를 설치하고 서버 두 개를 띄워야 하고, C는 CLI 세 개에 로그인해야 하며, B는 패키지 설치와 키 설정이 필요하다. 사무소 직원이 혼자 할 수 있는 것은 D뿐이다. 첫걸음은 이번 주에 실제로 고민 중인 결정 하나를 Claude에서 D로 돌리고, 같은 질문을 Gemini Gem에서 한 번 더 돌려 결론이 같은지 보는 것이다.
