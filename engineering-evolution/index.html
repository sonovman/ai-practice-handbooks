핸드북 03 · 에이전트 활용

AI에게 일을 시키는
5가지 방법의 진화

프롬프트 엔지니어링에서 하네스·루프·그래프 엔지니어링까지, 지난 몇 년간 AI에게 일을 맡기는 방법이 어떻게 바뀌었는지 정리했습니다. 그리고 청구항 대비 분석이라는 실제 IP 업무에 다섯 단계를 차례로 적용해 봅니다.

독자“하네스 엔지니어링”이 궁금한 비개발 실무자, IP 분석 담당자 분량읽기 약 25분 · 템플릿 8종 판1.0 · 2026. 11. 6.
한 줄 결론

이제 성패는 AI를 더 똑똑하게 만드는 데가 아니라, 이미 똑똑한 AI가 안전하게 일할 판을 짜는 데 달려 있다.

다섯 단계는 서로를 대체하지 않고 쌓입니다. 좋은 프롬프트 위에 자료를 얹고(컨텍스트), 규칙과 차단 장치로 울타리를 치고(하네스), 스스로 검사·수정하게 하고(루프), 마지막으로 전체 업무 흐름과 사람의 승인을 설계합니다(그래프).

015단계 한눈에

각 단계는 바로 앞 단계의 한계를 메우려고 나왔습니다. 아래 계단을 누르면 해당 설명으로 갑니다. 1~2단계는 말로 시키는 법, 3~5단계는 일하는 환경을 짓는 법입니다.

1단계프롬프트잘 시키기 2단계컨텍스트자료 건네기 3단계하네스울타리 치기 4단계루프스스로 고치기 5단계그래프흐름 설계
단계더하는 것남는 한계 → 다음 단계로
프롬프트역할과 구체적 지시최신 정보·사내 사정을 모름
컨텍스트사내 문서·회의록 같은 자료자료를 매번 사람이 찾아 건네야 함
하네스업무 매뉴얼·도구·차단 장치틀린 결과를 사람이 일일이 다시 지시해야 함
루프성공 기준·검증자·종료 조건여러 단계와 사람이 얽힌 업무 전체는 못 다룸
그래프작업 단위·이동 조건·공유 정보·사람 승인—

02 · 1단계프롬프트 엔지니어링 — 잘 시키기

AI에게 역할을 주고 구체적으로 지시하는 방법입니다. “요약해 줘” 대신 “10년 차 마케터로서, 임원 보고용으로, 다섯 줄로”라고 쓰는 식입니다. 자세한 원칙은 02편 「프롬프트 5원칙」에 정리했습니다.

IP 적용

역할과 목표 정하기

“15년 차 변리사로서, 청구항을 구성요소별로 나누고 기술적·법적 관점에서 비교 분석하라.” 단순 요약이 아니라 분석의 틀을 정합니다.

한계

모르는 것은 모른다

AI는 학습한 시점까지의 지식만 압니다. 오늘 받은 선행문헌이나 우리 회사 사정은 알 수 없습니다.

03 · 2단계컨텍스트 엔지니어링 — 자료 건네기

지시와 함께 업무에 필요한 자료를 넣어 주는 방법입니다. AI가 넣어 준 자료 범위 안에서 판단하게 되어, 그럴듯하게 지어내는 오류(환각)가 크게 줄어듭니다.

IP 적용

세 가지 자료를 함께

  • 대상 특허의 청구범위와 발명의 상세한 설명
  • 비교할 선행문헌 전문
  • 특허법 제29조 제1항(신규성)·제2항(진보성) 관련 심사기준 발췌
한계

매번 사람이 챙겨야 한다

건마다 자료를 찾아 붙여 넣는 일이 사람 몫으로 남습니다. 빠뜨리면 그만큼 품질이 떨어집니다.

04 · 3단계하네스 엔지니어링 — 울타리 치기

하네스는 말이나 반려견에 채우는 마구입니다. 힘은 그대로 쓰게 하되 엉뚱한 길로 가지 않게 잡아 줍니다. AI에게는 일하는 환경 전체, 곧 업무 매뉴얼·쓸 수 있는 도구·자료 위치·금지 규칙을 미리 갖춰 두는 일입니다. 한 번 만들어 두면 매번 설명할 필요가 없습니다.

안내

업무 매뉴얼 CLAUDE.md

에이전트가 일을 시작할 때 가장 먼저 읽는 파일입니다. 역할, 자료 위치, 분석 규칙, 금지 사항을 적습니다. AGENTS.md라는 이름을 쓰는 도구도 있습니다.

강제

차단 장치 Hook

위험한 명령이 실행되기 직전에 자동으로 검사해 막는 장치입니다. 매뉴얼은 무시될 수 있지만, Hook은 프로그램이 막기 때문에 우회되지 않습니다.

IP 적용: 무엇을 매뉴얼에, 무엇을 Hook에

매뉴얼(CLAUDE.md)에 적을 것Hook으로 막을 것
분석 규칙구성요소 완비 원칙, 상세한 설명의 정의 우선, 용어 고정, 기술·법리 분리—
근거선행문헌 인용 시 단락 번호【0000】 필수인용 없는 대비표로는 작업을 끝내지 못하게
원본 보호원본 자료 수정·삭제 금지삭제·이동 명령 자체를 차단
유출 방지분석 자료 외부 전송 금지외부 전송 명령 차단

매뉴얼 전문은 CLAUDE.md, Hook 예시는 block_danger.py에 있습니다.

05 · 4단계루프 엔지니어링 — 스스로 고치기

결과에 문제가 있을 때 사람이 매번 확인하고 다시 지시하는 대신, AI가 검사 → 수정 → 재검사를 스스로 반복하게 만드는 방법입니다. 사람은 마지막 결과만 봅니다.

루프가 제대로 돌려면 세 가지가 꼭 있어야 합니다.

① 성공 기준

무엇이 통과인가

모든 구성요소가 1:1로 대응되고 인용 단락이 붙었는가. 진보성에 곤란성과 효과의 근거가 모두 있는가.

② 검증자

누가 검사하나

작성한 에이전트가 아닌 독립 IP 리뷰어. 형식은 검사 스크립트가 기계적으로 보조합니다.

③ 종료 조건

언제 멈추나

통과하면 종료. 3번 고쳐도 안 되면 멈추고 담당자에게 알립니다. 무한 반복과 비용 낭비를 막습니다.

작성→리뷰어 검수→ PASS →다음 단계/ FAIL → 지적대로 수정 → 재검수 (최대 3회)
검사기는 형식만 본다 — check_claim_chart.py는 인용 번호가 있는지, 빈칸이 남았는지 같은 형식을 봅니다. 그 단락에 정말 그 내용이 있는지, 진보성 판단이 타당한지는 리뷰어 에이전트와 사람이 봅니다.

06 · 5단계그래프 엔지니어링 — 흐름 설계

업무 전체를 지하철 노선도처럼 그리는 방법입니다. 루프가 한 작업의 품질을 다룬다면, 그래프는 여러 작업의 순서와 갈림길, 그리고 사람이 개입할 지점을 다룹니다.

노드 Node

작업 단위

역, 곧 하나의 일. “청구항 분해”, “대비 분석”, “팀장 승인”

엣지 Edge

이동 경로와 조건

선로. “검수 PASS면 승인으로, FAIL이면 수정으로”

상태 State

공유 정보

모든 역이 함께 보는 게시판. 구성요소 목록, 대응 결과, 검수 횟수

노드에는 AI 에이전트만 오는 것이 아닙니다. 일반 프로그램(검사 스크립트)도, 사람도 노드가 될 수 있습니다. 법적 책임이 따르는 판단 앞에 사람 승인 노드를 두는 설계를 Human-in-the-Loop라고 부릅니다.

노드끼리 주고받는 공유 정보의 예는 state-example.json에 있습니다.

07IP 분석 워크플로우 설계

다섯 단계를 모두 적용해 청구항 대비 분석 업무를 하나의 그래프로 설계하면 다음과 같습니다.

START입력: 대상 청구항 + 선행문헌

input/ 폴더에 넣기 (컨텍스트)

N1청구범위 해석·구성요소 분해

독립항을 E1, E2, E3 … 로 나누고 용어를 정의 (프롬프트 + 하네스)

상태: 구성요소 목록
N2선행문헌 대응 기재 추출

구성요소마다 대응 단락【0000】을 찾거나 “미개시” 표시

상태: 1:1 대응표
N3기술적·특허법적 대비 분석

구조·작용효과 비교, 신규성·진보성(곤란성·효과) 판단 초안

N4독립 IP 리뷰어 검수

FAIL → N3로 돌아가 지적 사항 수정 → 다시 N4 · 최대 3회
3회 초과 → 멈추고 담당자에게 보고
PASS

최종 판단과 책임은 사람에게 (Human-in-the-Loop)

승인
END청구항 대비표·분석 보고서 확정

output/claim-chart.md

01편과 함께 읽기 — N1~N3를 서로 다른 에이전트에게 나눠 맡기면 구성요소 이름과 용어가 단계마다 조금씩 바뀌는 “전화 게임”이 생기기 쉽습니다. 01편의 결론대로, N1~N3는 메인 에이전트 하나가 이어서 처리하고 N4 검수만 독립 리뷰어에게 맡기는 구성을 권합니다. 그래프는 사람이 흐름을 이해하고 통제하기 위한 설계도이지, 노드마다 에이전트를 따로 두라는 뜻이 아닙니다.

09따라 하기

처음에는 A. 기본만으로 충분합니다. 채팅형 AI(Claude, ChatGPT, Copilot 등)에서 바로 할 수 있습니다.

A. 기본 — 채팅창에서 (1~4단계 맛보기)

  1. 매뉴얼 붙이기CLAUDE.md 내용을 대화 첫머리에 붙여 넣습니다. 프로젝트 기능이 있는 도구라면 프로젝트 지침에 넣어 두면 매번 붙일 필요가 없습니다.
  2. 자료 올리기대상 특허 청구범위·상세한 설명, 선행문헌, 심사기준 발췌를 올립니다.
  3. 대비표 요청“대비표 양식대로 청구항 1항을 분석해 줘.” 완성본이 어떤 모양인지는 가상 예시를 보세요.
  4. 새 대화에서 검수새 대화(또는 다른 AI)를 열고 리뷰어 프롬프트와 결과물을 넣습니다. 작성한 대화와 분리해야 “제 눈의 들보”를 피할 수 있습니다.
  5. FAIL이면 되돌려 주기리뷰어의 지적 목록을 처음 대화에 붙여 고치게 합니다. 세 번 해도 안 되면 직접 봅니다. 이것이 사람이 손으로 돌리는 루프입니다.

B. 고급 — Claude Code로 자동화 (하네스·루프 자동 실행)

  1. 폴더 만들기템플릿 페이지의 권장 폴더 구성대로 만들고 CLAUDE.md를 맨 위에 둡니다.
  2. Hook 넣기.claude/hooks/에 두 Python 파일을, .claude/settings.json에 설정 예시를 넣습니다.
  3. 실행“input 자료로 청구항 1항 대비표를 output/claim-chart.md에 작성해 줘.”
  4. 자동 루프 확인에이전트가 작업을 끝내려 하면 검사기가 돌아갑니다. 빈칸이나 인용 누락이 있으면 끝내지 못하고 고치러 돌아가며, 3회 실패하면 output/REVIEW_NEEDED.txt를 남기고 멈춥니다.
  5. 사람 승인결과를 변리사·담당자가 검토하고 확정합니다.

Microsoft 365 환경이라면 같은 구조를 Copilot Studio(지침·지식)와 Power Automate(반복·승인)로 옮길 수 있습니다. 대응 관계는 01편 9장을 참고하세요.

10안전과 책임

격리

따로 떨어진 작업 공간

에이전트가 파일을 만들고 명령을 실행한다면 개인 PC가 아닌 별도 환경에서 돌립니다.

이중 안전망

매뉴얼 + Hook

매뉴얼로 안내하고, 원본 삭제·DB 삭제·외부 전송은 Hook으로 막습니다.

통제

횟수 제한 + 승인

루프는 3회로 끊고, 법적 판단이 담긴 보고서는 승인 뒤에만 저장·발송합니다.

책임의 위치 — AI가 만든 대비표와 특허성 의견은 초안입니다. 신규성·진보성·침해에 관한 최종 판단과 그 책임은 변리사와 담당자에게 있습니다. 출원 전 발명 내용, 의뢰인 자료는 회사가 승인한 AI 도구에만 넣으세요.

부록용어와 출처

환각AI가 사실이 아닌 내용을 그럴듯하게 만들어 내는 현상
하네스지침 문서·도구·자료 위치·차단 장치 등 에이전트가 일하는 환경 전체
Hook특정 동작 직전·직후에 자동 실행되는 검사 프로그램. 위험 명령을 막거나 작업 종료를 붙잡을 수 있음
