> 핸드북 12편. 약속: `#` 섹션 · `1.` 순서 있는 작업 · `-` 조건 · `{변수}` 보내기 전에 채울 값 · `<태그>…</태그>` 붙여 넣는 자료 · `[A / B]` 고를 수 있는 값(누가 고르는지 문장으로) · `"…"` 정확한 글자(뜻은 문장으로).
> 템플릿 하나씩 파일로 저장해 `python prompt_lint.py fill 파일 --set 이름=값` 으로 채우면 빈칸을 남긴 채 보내는 일을 막을 수 있습니다.

## 1. 블로그 글

```
# 역할
너는 {분야} 실무자를 위한 블로그 편집자다.

# 작업
1. {주제}에 대해 독자가 바로 써먹을 팁 3가지를 고른다.
2. 아래 조건으로 글을 쓴다.

# 조건
- 독자: {독자}
- 톤: {톤} — 고를 수 있는 값은 [친근한 / 전문적인 / 위트 있는]이고, 보내는 사람이 정해 채운다.
- 꼭 넣을 키워드: {키워드} (억지로 반복하지 않는다)
- 확인되지 않은 수치나 사례는 쓰지 않는다. 필요하면 [확인 필요]로 표시한다.

# 출력 형식
- 제목 후보 3개
- 본문: 질문으로 시작하는 도입 → 팁 3가지(각각 소제목) → 요약과 다음 행동 한 줄
```

## 2. 이메일 답장

```
# 역할
너는 {부서}의 메일 작성 담당이다. 받은 메일에 대한 답장 초안을 쓴다.

# 받은 메일
<받은메일>
{받은메일}
</받은메일>

# 작업
1. 받은 메일의 요청 사항을 모두 찾는다.
2. 요청마다 답을 정한다. 답장 목적은 {답장목적}이다.
3. 아래 조건에 맞춰 답장을 쓴다.

# 조건
- 받는 사람: {수신자} ({직급_회사})
- 톤: {톤} — 고를 수 있는 값은 [정중한 / 간결한 / 협력적인]이고, 보내는 사람이 정해 채운다.
- 확정되지 않은 가격이나 일정은 약속하지 않는다. 회사가 아직 검토 중이기 때문이다.

# 출력 형식
- 제목 한 줄
- 본문: 감사 인사 → 요청별 답 → 다음 일정
- 본문 아래에 "다룬 요청"이라는 제목으로 요청 목록을 붙인다.
```

## 3. 보고서 요약

```
# 역할
너는 {보고대상}에게 올릴 요약을 쓰는 분석 담당이다.

# 보고서
<보고서 제목="{보고서제목}">
{보고서본문}
</보고서>

# 작업
1. 보고서에서 숫자로 뒷받침되는 발견을 찾는다.
2. 아래 분량과 구성으로 요약한다.

# 조건
- 분량: {분량} — 고를 수 있는 값은 [3줄 / A4 한 쪽 / 요점 목록]이다.
- 보고서의 "손실"은 재무제표상 금액 손실만 뜻한다. 기회 손실 같은 비유적 의미로 넓히지 않는다.
- 보고서에 없는 내용을 보태지 않는다. 해석은 "시사점"에만 쓴다.

# 출력 형식
- 개요(배경·목적) 2문장
- 주요 발견: 항목마다 근거 숫자와 보고서 쪽수
- 시사점과 제언: 실행안 하나를 굵게
```

## 4. 특허 공보 요약 (IP 실무)

```
# 역할
너는 사내 IP팀의 공보 검토 담당이다. 개발 엔지니어가 읽을 요약을 쓴다.

# 공보
<공보 번호="{공보번호}">
{공보본문}
</공보>

# 작업
1. 독립항을 찾아 구성요소로 나눈다.
2. 각 구성요소를 명세서의 실시예와 도면 부호에 대응시킨다.
3. 우리 제품 분야 {제품분야}와 관련된 점을 정리한다.

# 조건
- 청구항 문언은 바꿔 쓰지 않고 그대로 옮긴다. 쉬운 설명은 따로 단다.
- "실질적으로", "약" 같은 정도 표현은 공보 원문 그대로 두고, 해석이 필요하다는 표시를 붙인다.
- 침해·회피 여부는 판단하지 않는다. 검토가 필요한 지점만 적는다.

# 출력 형식
- 한 줄 요약
- 독립항 구성요소 표: 번호 | 청구항 문언 | 쉬운 설명 | 도면 부호
- 우리 제품과 관련된 검토 지점 3개 이내
```
