# Korean Law MCP 실무 프롬프트 (도구 이름 바로잡은 판)

> 핸드북 08 「법제처를 Claude에 연결하는 Korean Law MCP 통합 가이드」의 복사용 프롬프트입니다.
> 기준: korean-law-mcp v4.15.23 (2026. 11. 7. 확인). 도구 이름은 버전에 따라 바뀔 수 있습니다.
> 연결 방식: 내 컴퓨터에 고정 설치한 서버 → 법제처 Open API 직접 (공개 서버·커넥터 주소는 쓰지 않음)
> [대괄호]만 바꿔 쓰세요. 실명·주소·계좌는 넣기 전에 가립니다.

**도구 이름 주의** — 떠도는 자료에 나오는 `get_statute`, `get_precedent`는 이 서버에 없는 이름입니다.
실제 노출 도구는 `search_law`, `get_law_text`, `get_annexes`, `search_decisions`, `get_decision_text`,
`legal_research`, `legal_analysis`, `ordinance_radar`, `discover_tools`, `execute_tool` 10개입니다.
도구 이름을 몰라도 "Korean Law MCP로 조회하라"고만 해도 Claude가 고릅니다.

## 0. 연동 확인 (설치 직후 한 번)

```
Korean Law MCP를 사용해 현재 시행 중인 특허법 제127조를 찾아 주세요. 반드시 다음을 포함해 주세요.
1. 법령명과 조문번호, 조문 제목
2. 현재 시행 여부와 시행일
3. 확인한 법제처 원문 링크
4. 사용한 MCP 도구 이름
5. 도구로 찾지 못한 경우 추측하지 말고 실패한 이유
```

성공 기준: 답변 전에 도구 호출 표시가 보이고, 4번에 실제 도구 이름(`get_law_text` 등)이 나옵니다.
도구 호출 없이 바로 답하면 연동이 안 된 것입니다.

## 1. 공통 규칙 (모든 프롬프트 앞에 붙이기)

```
[규칙]
- 법령·판례·해석례는 반드시 Korean Law MCP 도구로 조회한 결과만 근거로 쓴다. 기억으로 번호를 쓰지 않는다.
- 도구 결과에 [NOT_FOUND], [CONTENT_MISMATCH], [REPEALED], ⚠[연혁] 같은 표시가 나오면 그대로 옮겨 적는다.
- 조회에 실패한 근거는 "확인 실패"로 남기고, 다른 번호로 바꿔 채우지 않는다.
- 근거마다 (도구 이름 · 법령/사건번호 · 시행일 또는 선고일)을 괄호로 붙인다.
- 결론은 초안이다. 판단에 필요한 사실이 빠졌으면 무엇이 빠졌는지 적는다.
```

## 2. 계약서 검토 (legal_research · document_review)

```
[공통 규칙 붙이기]

당신은 [회사 쪽 / 상대방 쪽] 입장에서 계약서를 검토하는 사내 법무 담당자다.
Korean Law MCP의 legal_research 도구를 task="document_review"로 실행해 아래 계약서를 분석하라.
필요하면 get_law_text로 조문 원문을, search_decisions로 판례를 추가 조회하라.

[출력] 위험 조항마다
1. 조항 번호와 원문
2. 위험 내용 (누구에게 어떻게 불리한가)
3. 근거 — 조회한 조문 원문 한 줄과 출처 표시. 판례는 사건번호와 요지
4. 대안 조항 (바로 바꿔 넣을 문구)
5. 확인 필요 — 도구로 확인하지 못한 점

<contract_text>
[계약서 본문 — 당사자 이름은 갑·을로]
</contract_text>
```

```

내용증명 초안을 작성하라.

[구성] 발신인·수신인 / 제목 / 1 계약과 사실관계 / 2 상대방의 불이행 / 3 권리 근거(조회한 조문) / 4 이행 기한과 미이행 시 조치
[문체] 감정 없이 사실과 요구만. 법정이율·지연손해금률은 조회한 조문으로만 쓰고, 조회하지 못했으면 빈칸으로 둔다.

<facts>
- 관계: [임대인-임차인 / 원사업자-수급사업자 등]
- 계약일·만료일: [ ]
- 금액: [ ]
- 지금까지 한 통지와 날짜: [ ]
- 요구 사항과 기한: [ ]
</facts>
```

## 4. 인용 검증 게이트 (legal_analysis · verify_citations / cite_check)

초안이 나오면 제출·발송 전에 반드시 돌립니다.

```
아래 초안의 법령 조문과 판례 인용을 Korean Law MCP의 legal_analysis 도구로 검증하라.
1. mode="verify_citations"로 초안 전체를 넣어 조문·판례 실존, 항 번호, 조문 제목 일치를 확인하라.
2. 판례마다 mode="cite_check"로 이후 판례에 의해 변경·폐기 신호가 있는지 확인하라.
3. 결과를 표로: 인용 | 결과 표시(✓ ✗ ⚠ ⌛) | 도구가 준 설명 | 내가 할 일
4. 도구가 '판례가 그 말을 했는지'까지 확인하지는 않는다. 따옴표 인용문은 get_decision_text로 전문을 열어
   그 문장이 실제로 있는지 따로 확인하고, 없으면 "원문에 없음"으로 표시하라.

<draft>
[초안]
</draft>
```

- 인용이 15건을 넘으면 나눠서 넣습니다(기본 검증 상한 15건).
- 결과는 07편의 `citation-log.csv`에 옮겨 적고, 상태(확인됨/폐기)는 사람이 정합니다.

## 5. 행위시법 확인 (legal_analysis · applicable_law)

```
Korean Law MCP의 legal_analysis 도구를 mode="applicable_law"로 실행해
[법령명] [제N조]가 [YYYY-MM-DD](사건 발생일/출원일/행위일) 당시 어떤 문언이었는지 확인하라.
1. 그날 시행 중이던 버전과 시행일
2. 그 시점 조문 원문
3. 현행 조문과 다른 부분
4. 이후 개정의 부칙(적용례·경과조치)
```

IP 실무 예: "특허법 제29조 제2항을 [출원일] 기준으로" — 판례가 "구 특허법(… 개정되기 전의 것)"을 적용한 경우 문언 차이를 확인할 때.


## 7. 이 서버로 안 되는 것

- 특허심판원 심결, 특허·실용신안 공보 → KIPRIS에서 확인
- 하급심 판결 전부 → 법제처 수록 범위 밖은 판결서 인터넷 열람
- 법률 판단·제출 → 사람
