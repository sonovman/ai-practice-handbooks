핸드북 08 · Claude 활용

법제처에 직접 연결해 Claude로 법령·판례 리서치하기

오픈소스 Korean Law MCP를 내 컴퓨터에 설치하면, Claude가 중간 서버 없이 법제처 국가법령정보 Open API에 내 인증키로 직접 조회합니다. 인터넷에 많이 소개된 ‘주소 한 줄’ 방식은 개인이 운영하는 공개 서버를 거치므로 이 편에서는 쓰지 않습니다. 설치, 연결, 사용법, 그리고 검증의 범위를 소스 코드와 실행 시험으로 확인해 정리했습니다.

독자Claude에 법령·판례 조회를 붙이려는 사내 법무·IP 담당자, 실무자 분량읽기 약 20분 · 설치 30분 · 템플릿(프롬프트·지침·설정 예시·설정 점검기·자료 검증표) 판1.0 · 2026. 11. 7. · 기준 korean-law-mcp v4.15.23
한 줄 결론

서버는 내 컴퓨터에, 인증키는 내 것으로, 버전은 고정해서.

이렇게 하면 법제처로는 조회어와 내 인증키만 나가고, 제3자 서버는 끼지 않습니다. 법제처가 직접 내놓은 공식 MCP는 확인되지 않아, 공개 소스인 Korean Law MCP를 검증한 버전으로 고정 설치하는 것이 현재 가장 안전한 길입니다. MCP는 원문을 가져오는 손일 뿐이고, 판단은 여전히 사람이 원문을 읽고 합니다.

확인 방법(2026. 11. 7.): ① v4.15.23 소스 전체에서 접속 주소를 추출 — 실제 호출 대상은 www.law.go.kr·open.law.go.kr·taxlaw.nts.go.kr, 공개 서버 주소(gomdori)는 없음. ② 패키지를 설치해 로컬로 띄우고 도구 목록(10개)과 법령 검색을 호출 — www.law.go.kr로 바로 접속을 시도함(이 작업 환경은 외부망이 막혀 응답은 받지 못함).

공식 법제처 MCP는? — 법제처가 직접 배포하는 MCP 서버는 이 글을 쓰는 시점에 찾지 못했습니다. 검색되는 법령 MCP는 모두 개인·민간 오픈소스입니다. 그래서 ‘공식 API에 직접 연결’은 가능하지만, 그 사이를 잇는 프로그램은 제3자 코드라는 점을 10장에서 관리합니다.

02쓰지 않는 방법

Korean Law MCP 안내 글과 저장소 첫 화면은 아래 방법을 “가장 쉬운 길”로 소개합니다. 모두 개인이 운영하는 공개 서버(mcp.gomdori.app)를 거칩니다. 넣은 질문과 계약서 본문, 인증키가 그 서버를 지나므로 업무에는 쓰지 않습니다.

안내되는 방법왜 공개 서버를 거치나이 편의 대안
Claude.ai 커스텀 커넥터에 주소 입력주소 자체가 공개 서버웹·모바일에서는 쓰지 않음. 데스크톱 앱이나 Claude Code에서
Claude Code 플러그인 (/plugin install)v4.15.13부터 플러그인이 공개 서버에 연결5장의 claude mcp add로 로컬 등록
데스크톱 설정에 mcp-remote + 주소원격 주소로 중계5장의 로컬 설정
VS Code·Cursor 설치 버튼버튼 설정이 공개 서버 주소로컬 설정 직접 작성
자동 설치 마법사도 그대로 쓰지 않습니다 — npx korean-law-mcp setup은 로컬 방식이지만, 설정 파일에 npx -y korean-law-mcp를 넣어 Claude를 켤 때마다 npm의 최신판을 내려받아 실행합니다. 검토하지 않은 새 버전이 자동으로 돌아가는 구조라, 이 편은 버전을 고정해 수동 설치합니다.

03인증키(OC) 받기

로컬 설치는 본인 인증키가 꼭 있어야 합니다. 무료입니다.

  1. 포털 가입국가법령정보 공동활용(open.law.go.kr)에 회원가입·로그인합니다.
  2. Open API 사용 신청인증키(OC)로 쓸 아이디를 정합니다. 예: honggildong. 이 문자열이 곧 키입니다.
  3. 도메인·데이터웹사이트 없이 쓰면 ‘도메인 없음’으로 적은 사례가 많습니다. 법령·판례·자치법규 등 쓸 항목을 모두 고릅니다.
  4. 사용목적실제 용도를 짧게 씁니다.
사용목적 예시
업무 참고용으로 국가법령정보 Open API를 이용해 현행 법령·판례를 조회하고, AI가 작성한 문서 초안의 법령 인용을 공식 원문과 대조하려고 합니다. 조회 결과는 그대로 외부에 제공하거나 자동 제출하지 않으며, 공식 원문 확인과 담당자 검토를 거칩니다.

인증키는 발급받은 본인만 씁니다(법제처 정책, 저장소 NOTICE). 팀은 각자 받습니다. 키는 설정 파일에 평문으로 들어가므로 그 파일을 공유하거나 저장소에 올리지 않습니다.

04설치

  1. Node.js 20.19 이상명령 프롬프트(Windows: 시작 → cmd)에서 node -v. 없거나 낮으면 nodejs.org에서 LTS를 설치합니다(22.12 이상 권장).
  2. 버전을 고정해 설치아래 명령을 그대로 붙여 넣습니다. @4.15.23이 이 글에서 확인한 버전입니다. --ignore-scripts는 설치 중 스크립트 실행을 막습니다.
  3. 설치 확인korean-law-mcp가 설치된 위치와 버전을 봅니다.
명령 프롬프트 · 터미널
npm install -g korean-law-mcp@4.15.23 --ignore-scripts --omit=optional
npm ls -g korean-law-mcp
npm root -g

npm ls -g에 korean-law-mcp@4.15.23이 보이면 됩니다. npm root -g가 알려 주는 폴더(Windows는 보통 C:\Users\사용자이름\AppData\Roaming\npm\node_modules)는 5장에서 씁니다.

업데이트도 직접 — 새 버전은 CHANGELOG에서 바뀐 점을 읽고, 필요할 때만 같은 명령의 버전 번호를 바꿔 다시 설치합니다. 사내 배포라면 보안 담당이 확인한 버전 번호를 공지하는 방식이 좋습니다.

05Claude에 연결

Claude Desktop

Claude Desktop의 설정 → 개발자 → 설정 편집으로 claude_desktop_config.json을 엽니다(Windows %APPDATA%\Claude\, Mac ~/Library/Application Support/Claude/). 다른 MCP 서버가 이미 있으면 "korean-law": {…} 묶음만 mcpServers 안에 쉼표로 이어 넣습니다.

claude_desktop_config.json (Mac · 기본형)
{
  "mcpServers": {
    "korean-law": {
      "command": "korean-law-mcp",
      "env": { "LAW_OC": "본인의_인증키" }
    }
  }
}

Windows에서 기본형이 실행되지 않으면, 설치된 파일을 node로 직접 지정합니다. 경로는 4장 npm root -g 결과 뒤에 \korean-law-mcp\build\index.js를 붙인 것이고, JSON 안에서는 \를 \\로 두 번 씁니다.

claude_desktop_config.json (Windows · 경로 지정형)
{
  "mcpServers": {
    "korean-law": {
      "command": "node",
      "args": ["C:\\Users\\내사용자이름\\AppData\\Roaming\\npm\\node_modules\\korean-law-mcp\\build\\index.js"],
      "env": { "LAW_OC": "본인의_인증키" }
    }
  }
}

저장한 뒤 Claude Desktop을 완전히 종료합니다. 창의 X는 종료가 아닙니다. Windows는 작업 표시줄 오른쪽 숨겨진 아이콘(▲) → Claude 아이콘 우클릭 → Quit, Mac은 Cmd+Q. 다시 켜면 도구가 보입니다.

Claude Code

플러그인 대신 로컬 서버를 직접 등록합니다. --scope user는 모든 프로젝트에서 쓰도록, 키는 -e로 넘깁니다.

터미널
claude mcp add korean-law --scope user -e LAW_OC=본인의_인증키 -- korean-law-mcp
claude mcp list

프로젝트 폴더의 .mcp.json에 넣는 방식은 키가 git에 함께 올라갈 수 있으니 피합니다.

터미널에서 바로 (선택)

Windows 명령 프롬프트
set LAW_OC=본인의_인증키
korean-law "특허법 제127조"
korean-law list

사내망에서 법제처 HTTPS 인증서 검증이 막히면 env에 "LAW_API_PROTOCOL": "http"를 넣을 수 있다고 저장소는 안내합니다. 보안 담당과 먼저 상의하세요.

06연결 확인과 문제 해결

연동 확인 프롬프트
Korean Law MCP를 사용해 현재 시행 중인 특허법 제127조를 찾아 주세요. 반드시 다음을 포함해 주세요.
1. 법령명과 조문번호, 조문 제목
2. 현재 시행 여부와 시행일
3. 확인한 법제처 원문 링크
4. 사용한 MCP 도구 이름
5. 도구로 찾지 못한 경우 추측하지 말고 실패한 이유

성공: 답 전에 도구 호출 표시가 보이고 4번에 get_law_text 같은 실제 도구 이름이 나옵니다. 실패: 도구 호출 없이 바로 답하면 Claude가 기억으로 답한 것입니다.

설정 점검기

check_setup.py는 데스크톱 설정 파일을 읽기만 하고, 원인 대부분을 한 화면에 보여 줍니다. 공개 서버를 거치는 설정은 실패, 실행할 때마다 최신판을 받는 npx -y 설정은 주의로 표시합니다.

명령 프롬프트
python check_setup.py
증상점검기 표시해결
도구가 안 보임JSON 문법 실패 (N번째 줄)쉼표·중괄호. 다른 서버 묶음 사이 쉼표 누락이 가장 흔함
도구가 안 보임 (Windows)실행 파일 경로 없음npm root -g로 위치 확인 후 경로 지정형으로
도구는 보이는데 오류인증키 자리표시·누락‘본인의_인증키’를 실제 키로
실행 안 됨Node.js 버전 부족·없음20.19 이상 설치
고쳤는데 그대로통과트레이에서 완전히 종료 후 재실행

점검기는 로컬 기본형·경로 지정형(정상·경로 오류), npx 자동 최신형, 공개 서버형, 문법 오류, 항목 누락으로 시험했습니다(2026. 11. 7.).

07사용법

도구 이름을 외울 필요는 없습니다. “Korean Law MCP로 조회해서”라고 하면 Claude가 고릅니다. 다만 무엇을 할 수 있는지 알면 질문이 좋아집니다. 화면에 보이는 도구는 10개이고, 뒤에 전문 도구가 더 있습니다(CLI 기준 100개, discover_tools → execute_tool).

하고 싶은 일도구이렇게 묻기
조문 찾기search_law → get_law_text“특허법 제29조 제2항 현행 조문과 시행일”
사건 당시 법legal_analysis · applicable_law“특허법 제29조를 2015-03-01 기준으로, 이후 부칙 경과규정까지”
개정 비교legal_research · amendment_track“발명진흥법 최근 개정 신구대조”
판례·결정 찾기search_decisions → get_decision_text“직무발명 보상금 산정 대법원 판례, 본문 검색 포함”
판례가 아직 유효한지legal_analysis · cite_check“2007후3660 이후 변경·폐기 신호 확인”
초안 인용 검증legal_analysis · verify_citations“아래 초안의 조문·판례 인용 전부 검증” + 초안
별표·서식get_annexes“특허료 등의 징수규칙 별표 내용을 표로”
계약서 검토legal_research · document_review“아래 계약서 위험 조항과 근거, 대안 문구” + 본문(실명 가림)
여러 법령 개정 감시execute_tool · search_law_bulk“IP 관련 6개 법령의 시행일과 시행예정 개정”

모든 질문 앞에는 아래 공통 규칙을 붙입니다. 상황별 전체 프롬프트는 prompts.md, 프로젝트에 넣어 두는 지침은 CLAUDE.md에 있습니다.

공통 규칙
[규칙]
- 법령·판례·해석례는 반드시 Korean Law MCP 도구로 조회한 결과만 근거로 쓴다. 기억으로 번호를 쓰지 않는다.
- 도구 결과의 [NOT_FOUND] [CONTENT_MISMATCH] [REPEALED] ⚠[연혁] 표시는 그대로 옮겨 적는다.
- 조회에 실패한 근거는 "확인 실패"로 남기고, 다른 번호로 바꿔 채우지 않는다.
- 근거마다 (도구 이름 · 법령/사건번호 · 시행일 또는 선고일)을 붙인다.
- 결론은 초안이다. 판단에 필요한 사실이 빠졌으면 무엇이 빠졌는지 적는다.
IP 실무자 주의 — 조회되지 않는 것 — 특허심판원 심결과 특허·실용신안 공보는 이 도구 범위가 아닙니다(KIPRIS에서 확인). 법제처에 수록되지 않은 하급심 판결도 판결서 인터넷 열람으로 확인합니다. 떠도는 프롬프트의 get_statute·get_precedent는 이 서버에 없는 도구 이름입니다.

08검증은 어디까지

소스 코드(verify-citations.ts, cite-check.ts)로 확인한 검증 기능의 범위입니다.

기능확인하는 것확인하지 않는 것
verify_citations조문 실존(✓/✗, 범위 제시) · 없는 항 번호 · 인용에 붙인 조문 제목과 실제 제목 불일치 [CONTENT_MISMATCH] · 폐지 [REPEALED] · 옛 법령명 [RENAMED] · 판례 사건번호판례가 인용한 문장·법리를 실제로 말했는지 · 사안에 맞는지 · 기본 15건을 넘는 인용(나눠 넣기)
cite_check그 사건번호를 인용한 후속 판례 역추적, 전원합의체의 “변경하기로 한다” 문구 감지법제처 수록 범위(대법원 중심) 밖 판례 · 신호가 없다고 사안에 맞는다는 뜻은 아님
applicable_law기준일 시행 버전, 그 시점 조문, 이후 부칙의 적용례·경과조치경과규정을 사안에 어떻게 적용할지의 판단

07편과 합친 흐름

  1. 쟁점 정리 (인용 금지)07편 1단계 그대로.
  2. 원문 확보 — MCP가 대신 찾음search_law·search_decisions로 원문을 대화에 가져옵니다.
  3. 미검증 표Claude가 꺼낸 근거를 citation-log.csv에 ‘미검증’으로.
  4. 자동 검증 + 사람 확인verify_citations·cite_check 결과를 존재·효력 칸에, 따옴표 인용은 get_decision_text 전문에서 사람이 찾아 원문발췌 칸에. 상태(확인됨/폐기)는 사람이 정합니다.
  5. 확인됨만으로 메모 → cite_check.py07편 점검 스크립트로 마지막 대조.
07편 사례에 대어 보면 — “2007후3660 = 암시·동기 법리”처럼 번호·날짜·주제가 맞고 내용만 틀린 인용은 verify_citations에서 실존(✓)으로 나옵니다. 잡으려면 전문을 열어 문장을 찾아야 합니다.

09떠도는 자료를 검증해 보니

이 편은 AI로 만든 Korean Law MCP 안내 자료 5종을 바탕으로 했습니다. 주장마다 원문을 대조했더니 15건 가운데 그대로 맞은 것은 2건이었습니다. 설치를 다룬 3종 가운데 2종은 공개 서버를 거치는 방법을 먼저 소개했고, 나머지 1종(1쪽 매뉴얼)의 자동 설치 마법사는 Claude를 켤 때마다 최신판을 받는 구조입니다. 어느 자료도 공개 서버를 누가 운영하는지 말하지 않았습니다.

자료의 주장확인 결과판정
도구 get_statute·get_precedent로 조회서버에 없는 이름. 노출 도구는 7장의 10개틀림
통합 검색 18개 도메인v4.15.22부터 23개오래됨
컨텍스트 약 110KB를 50% 이상 절감저장소 기록은 도구 목록 ~15.1KB → ~7.2KB(52%)부분 일치
판결 이유 축약으로 토큰 74% 절감v3.4.0 기록과 같음일치
Claude Code 플러그인 = 로컬 설치v4.15.13부터 공개 서버 연결오래됨
원격 Node 18+, 로컬 20.19+저장소·npm과 같음일치
환각을 “완벽히 차단·정화”실존·항·제목 대조까지. 원작자도 법적 판단에는 원문 확인 권고과장
즉시 자동 승인, “공식 통과 문구”확인하지 못함확인 불가
하도급법 제12조의3 = 지식재산권 귀속제목은 ‘기술자료 제공 요구 금지 등’틀림
민법 제398조 ‘위약정리’제목은 ‘배상액의 예정’부정확
지체상금률 “통상 1000분의 2.5” / “0.75~1.5”국가계약법 시행규칙 제75조: 공사 0.5 · 물품 0.75 · 용역 등 1.25 · 군용 음식료품 1.5 · 운송·보관 2.5 (1000분의). 국가계약 기준이며 민간 하도급에 바로 적용되지 않음서로 모순
원상복구 근거 민법 제615조사용대차 조문. 임대차에는 제654조로 준용부분 일치
내용증명 = e-그린우편, 3년 보관메뉴 이름·보관 기간 확인하지 못함 → 인터넷우체국에서 확인확인 불가
데스크톱 JSON 주소원문이 “[suspicious link removed]”로 손상손상
테스트 프롬프트오타(찾어주새요·뭔문), 취지는 유효수정

전체 검증표: source-check.csv · 도구·버전은 공개 저장소와 npm 패키지 v4.15.23, 조문 제목은 공개 법령 DB로 확인(2026. 11. 7.). 이 작업 환경은 법제처 API에 접속할 수 없어 실제 조회 결과 화면은 싣지 못했습니다. 설치 후 6장 프롬프트로 직접 확인하세요.

10남는 위험과 관리

로컬 설치로 제3자 서버는 빠지지만, 위험이 0이 되지는 않습니다. 남는 세 지점과 관리 방법입니다.

코드

제3자 오픈소스

내 컴퓨터에서 도는 프로그램은 개인이 만든 MIT 코드입니다. 버전 고정 설치, --ignore-scripts, 업데이트 전 CHANGELOG 확인. 사내 배포는 보안 담당 검토 후 버전 공지.

Claude

대화는 Claude로

MCP와 무관하게, Claude에 넣은 내용은 Claude 사용 환경의 정책을 따릅니다. 의뢰인 자료·출원 전 발명은 회사가 승인한 Claude 환경에서만, 실명·금액은 가려서.

법제처

조회어는 법제처로

법령명·조문·사건번호·검색어와 인증키가 공공기관 서버로 갑니다. 계약서 본문을 넣는 도구(document_review, verify_citations)는 문장 일부가 검색어로 쓰일 수 있으니 가린 뒤 씁니다.

판단은 여전히 사람이 — 저장소 스스로 “조회 결과를 가공·요약할 수 있으므로 법적 효력이 필요한 판단에는 국가법령정보센터 원문을 확인”하라고 적고 있습니다.
