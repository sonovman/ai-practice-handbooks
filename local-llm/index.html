로컬 LLM 추론 장비 구축·운영 — VRAM부터 전력 안전까지

클라우드 API는 편하지만 데이터 유출 우려, 지속 비용, 인프라 제어권 부재라는 한계가 있습니다. 모델을 내 하드웨어에서 직접 서빙하면 이를 넘어설 수 있습니다. 다만 이 길은 전기와 고가 하드웨어를 다루므로 안전이 먼저입니다. 이 편은 VRAM 최우선 부품 선정부터 전력·회로 안전, PCIe P2P, BIOS·커널 튜닝, Docker/vLLM 서빙까지, 사기 전에 숫자로 확인하는 두 계산 도구와 함께 초보자도 따라 하기 쉽게 단계별로 안내합니다.

독자클라우드 비용·프라이버시 때문에 로컬 LLM 추론 장비를 처음 구축하려는 사람 분량읽기 약 25분 · 템플릿(전력 예산 계산기 · VRAM 적합성 계산기 · 구축 스킬 · 프롬프트 5종 · 시범) 판1.0 · 2026. 11. 8.
한 줄 결론

돈은 VRAM에, 안전은 전기에 — 사기 전에 ‘모델이 VRAM에 들어가는지’와 ‘전력이 회로를 넘지 않는지’를 숫자로 확인하세요.

로컬 추론의 절대 병목은 VRAM 용량·대역폭입니다. 모델이 VRAM을 넘어 시스템 RAM으로 넘치면(Spillover) 속도가 급락합니다. 그래서 최신 메인보드가 아니라 VRAM에 예산을 집중하고, 여러 GPU는 PCIe 스위치로 직접 통신하게 합니다. 그리고 고출력 GPU는 일반 전기 회로를 쉽게 넘기므로 전력 계산과 제한이 필수입니다.

⚠️ 안전 먼저 — 이 편에는 수천 W급 전력과 iommu·ACS 비활성화 같은 설정이 나옵니다. 실제 배선·전용 회로·접지는 반드시 자격 있는 전기 기술자와 확인하고, iommu=off·ACS off는 외부와 분리된 전용 추론 머신에서만 쓰세요. 고출력 기기를 콘센트 1구에 몰아 쓰지 마세요.
무엇을 확인했나 — 전력 계산기는 시험 7개, VRAM 계산기는 시험 9개로 동작을 확인했고, 4·5장 시범은 작성 환경에서 직접 돌린 결과입니다. 원고의 기술 내용(부품·BIOS/커널·P2P·전력 제한·모델 구성)은 참조 저장소 jamesob/local-llm과 대조해 일치함을 확인했습니다(부록). 등장하는 모델 이름·버전(594B·27B·STT 등)은 저장소의 특정 시점 예시이므로, 현재 최적 모델은 그때 다시 확인하도록 ‘역할’로 설명합니다. 이 편은 유튜브 링크가 제공되지 않아 영상 자료는 쓰지 않았습니다.

02VRAM 최우선과 예산 3단계

가장 흔한 실수는 최신 CPU·DDR5·PCIe 5.0 메인보드에 예산을 쓰는 것입니다. 추론 성능을 결정하는 것은 VRAM입니다. 중고 구세대 EPYC+DDR4 ECC로 호스트를 아끼고, 그 돈을 VRAM GPU에 집중합니다.

단계구성(예)VRAM쓰임
입문 (~$2,000)RTX 3090 2장(중고)48GB중형 오픈소스 모델(양자화)·로컬 음성 인식
중간 (~$20,000)워크스테이션 GPU 2장 / 클러스터128~192GB중대형 모델·파이프라인 실험
최고 (~$40,000+)워크스테이션 GPU 4장(각 96GB)384GB초거대 모델을 긴 컨텍스트로 서빙
핵심 — $2,000 수준의 입문 구성으로도 좋은 오픈소스 모델과 로컬 음성 인식을 충분히 돌릴 수 있습니다. 최상위 구성은 지능은 높지만 전력·비용·소음이 크므로 소수에게만 맞습니다. 대부분은 입문부터 시작하세요. 모델 이름·버전은 자주 바뀌니 ‘파라미터 수·역할’로 기억합니다.

03처음 접근과 바뀐 점

① “최신 플랫폼부터” → VRAM에 집중 — 최신 메인보드·DDR5·PCIe 5.0에 돈을 쓰면 정작 VRAM이 부족해집니다. 호스트는 중고 EPYC+DDR4로 아끼고(약 1만 달러 절감 사례), 그 예산을 고용량 VRAM GPU에 몰아줍니다. 사기 전에 vram_fit.py로 확인합니다.
② “NVLink·PCIe5라야” → Gen4 스위치 P2P — 여러 GPU로 한 모델을 나눠 추론하면 GPU끼리 쉴 새 없이 통신합니다. 비싼 NVLink나 PCIe5 메인보드 대신 독립 PCIe Gen4 스위치를 쓰면, CPU를 거치지 않고 스위치 내부에서 P2P로 직접 통신해 병목을 없앱니다.
③ “꽂으면 끝” → BIOS·커널 튜닝 — 기본 설정으로는 P2P가 막히거나 속도가 떨어집니다. BIOS에서 PCIe를 x16·Gen4로 고정하고 ASPM을 끄고 Re-Size BAR를 켭니다. 커널은 iommu=off가 없으면 다중 GPU 통신(NCCL)이 멈춥니다.
④ “그냥 다중 GPU면 빠름” → ACS를 꺼야 P2P — PCIe ACS가 켜져 있으면 GPU 간 트래픽이 스위치를 못 쓰고 CPU로 우회합니다. 런타임에 ACS를 비활성화해야 스위치의 이점이 살아납니다. 단, iommu·ACS off는 격리를 약화하므로 외부와 분리된 전용 추론 머신에서만 적용합니다.
⑤ “기본 전력 그대로” → 전력 제한이 안전 — GPU 4장을 기본 전력으로 돌리면 일반 110V 회로를 훌쩍 넘겨 차단기 다운·과열 위험이 생깁니다. nvidia-smi -pl로 카드당 전력을 제한하고, 부팅 시 자동 적용합니다. 4장 시범에서 기본값이면 회로 정격을 넘지만, 제한하면 안전 범위로 들어옵니다.
⑥ “이 모델이 정답” → 이름보다 역할·현재 확인 — 최적 모델·양자화 방식은 빠르게 바뀝니다. 특정 시점의 모델 이름에 묶이지 말고, ‘파라미터 수·용도(추론/음성 인식 등)’로 계획하고 구축 시점의 최신 모델을 그때 확인합니다.

04전력·회로 안전 — 사기 전에 계산(시범)

전기는 되돌릴 수 없는 사고로 이어집니다. 동봉한 power_budget.py로 벽에서 끌어가는 전력이 회로의 연속 허용치(차단기 정격의 80%)를 넘는지 계산했습니다.

$ python tools/power_budget.py --gpus 4 --gpu-watts 600 --volts 120 --amps 15
판정: 정격 초과(위험) — 벽 2978W / 연속 허용 1440W (회로 대비 165%)
→ GPU당 약 254W로 제한하거나 220V 전용 회로 필요

$ python tools/power_budget.py --gpus 4 --gpu-watts 350 --volts 120 --amps 15
판정: 정격 초과(위험) — 벽 1867W / 정격 1800W (104%)   ← 제한해도 단일 15A론 빠듯

$ python tools/power_budget.py --gpus 4 --gpu-watts 350 --volts 220 --amps 16
판정: 안전 범위 — 벽 1867W / 연속 허용 2816W (53%)       ← 전용 회로면 여유
무엇을 배우나 — 기본 전력(600W×4)이면 일반 120V·15A 회로의 1.6배를 넘습니다. 350W로 제한해도 단일 15A 회로엔 빠듯하고, 220V 전용 회로라야 여유가 생깁니다. 계산은 계획 보조일 뿐, 실제 배선·차단기·접지는 전기 기술자와 확인하세요.

05VRAM 적합성 — 스필오버 막기(시범)

vram_fit.py로 모델이 VRAM에 들어가는지(넘쳐 RAM으로 가지 않는지) 계산했습니다. 판정은 가장 믿을 만한 가중치 기준(params × bits/8)입니다.

$ python tools/vram_fit.py --params 27 --bits 8  --vram 48    → 여유 있음 (29GB/48GB, 61%)
$ python tools/vram_fit.py --params 27 --bits 16 --vram 48    → VRAM 초과(RAM으로 넘침) (58GB/48GB)
$ python tools/vram_fit.py --params 594 --bits 4 --vram 384   → 여유 있음 (321GB/384GB, 84%)
무엇을 배우나 — 27B 모델도 fp16(16비트)이면 48GB에 안 들어갑니다. 8비트로 양자화하면 들어갑니다. 즉 양자화로 비트를 낮추는 것이 VRAM을 맞추는 가장 쉬운 방법입니다. KV 캐시는 모델 구조(GQA 등)·KV 양자화에 따라 크게 달라지므로, 정확한 값은 추론 엔진 로그로 확인해 --kv-gb로 넣습니다(도구는 참고용 ‘최악 상한’만 따로 보여 줍니다).

06실작업 예시 — 특허분석 업무를 로컬 LLM으로

왜 특허분석이 로컬에 잘 맞을까요? ① 미공개 발명·명세서 초안은 외부로 내보내기 민감합니다. ② 선행문헌 조사·청구항 대조·요지 추출은 문서가 많고 길어 사용량이 커 클라우드 비용이 누적됩니다. ③ 명세서는 길어서 긴 컨텍스트가 유리합니다. 아래는 가상의 특허사무소 환경을 예로, 앞의 두 도구로 구성을 정하는 과정입니다.

업무로컬 LLM 활용(예)
선행문헌 1차 스크리닝검색된 공보 수십 건을 요지·기술분야로 요약·분류
청구항 대조본 발명 청구항 vs 인용문헌 구성요소 매핑(표로)
명세서 초안 보조발명 설명 초안·용어 통일(사람이 최종 검토·서명)
음성 메모 전사발명자 인터뷰를 로컬 STT로 전사(외부 유출 없이)

1) 구성 정하기 — 민감하지만 대규모 학습이 아닌 ‘추론·보조’이므로 입문 단계로 충분합니다. 중형 모델(예: 27B급)을 8비트로, 긴 명세서를 위해 컨텍스트에 여유를 둡니다. 두 도구로 확인합니다.

# VRAM: 27B 8bit + KV 6GB / RTX 3090 2장(48GB)
$ python tools/vram_fit.py --params 27 --bits 8 --vram 48 --kv-gb 6
→ 여유 있음 (35GB/48GB, 73%)   ← 긴 명세서·동시 요청 여지 확보

# 전력: GPU 2장×350W + 호스트 200W / 120V·15A
$ python tools/power_budget.py --gpus 2 --gpu-watts 350 --host-watts 200 --volts 120 --amps 15
→ 안전 범위 (벽 1000W / 연속 허용 1440W, 56%)   ← 일반 사무실 회로로도 운용 가능

2) 모델·서빙 설정 — 모델은 ‘역할’로 고릅니다(추론용 중형 + 전사용 STT). 긴 명세서를 위해 --max-model-len을 넉넉히, GPU 2장이면 --tensor-parallel-size 2로.

# vLLM 서빙(요지) — 특허분석용 중형 모델
command: >
  --model /model
  --tensor-parallel-size 2        # GPU 2장에 분산
  --quantization awq              # 8bit급 양자화로 VRAM 절약(엔진·모델에 맞춰)
  --max-model-len 32768           # 긴 명세서 대응(길면 KV가 커지니 vram_fit로 재확인)
  --port 5000
# 전사용 STT는 별도 컨테이너(runners/stt)로 11GB 안팎 VRAM에 분리 배치

3) 활용 프롬프트(예) — 로컬 서버(http://추론머신:5000/v1)에 붙여 청구항을 대조합니다.

[역할] 너는 특허 분석 보조자다. 아래 '본 발명 청구항 1'과 '인용문헌 D1'을
구성요소 단위로 매핑하고, D1에 없는(신규로 보이는) 구성요소를 표로 정리하라.
- 각 구성요소: 청구항 문구 → D1 대응 위치(문단/도면) → 일치/불일치/불명 판정
- 판단 근거가 문헌에 없으면 '불명'으로 표시(추측 금지)
[입력] 청구항: <...>  / D1 발췌: <...>
현실 점검 — ① 결과는 사람(변리사)이 최종 검토·판단합니다. AI 매핑은 초안일 뿐 법적 판단이 아닙니다. ② 명세서를 길게 넣으면 KV 캐시가 커져 VRAM이 빠듯해질 수 있으니, 실제 컨텍스트 길이로 vram_fit.py를 다시 돌려 확인합니다. ③ 미공개 발명 정보는 로컬에 머무르게 하고, 외부 노출 시 인증·방화벽을 둡니다. 모델 이름은 바뀌니 구축 시점의 추론용·STT 최적 모델을 그때 확인하세요.

07서빙과 검증

가중치를 ZFS 미러로 보관하고, 컨테이너에 읽기 전용(:ro)으로 마운트해 손상을 막습니다. vLLM OpenAI 호환 서버를 띄우고 텐서 병렬 크기를 GPU 수에 맞춥니다.

# docker-compose.yml (요지)
services:
  vllm-server:
    image: vllm/vllm-openai:latest
    runtime: nvidia
    volumes:
      - ~/storage/MODEL:/model:ro        # 가중치는 읽기 전용
    command: >
      --model /model --tensor-parallel-size 4 --port 5000
증상원인 → 조치
topo -m 가 PHB/NODEACS가 켜짐 → ACS 비활성화 스크립트·서비스 점검(정상은 PIX)
NCCL이 멈춤(Hang)커널 IOMMU 간섭 → GRUB iommu=off amd_iommu=off 후 재부팅
링크 속도 2.5GT/s유휴 시 ASPM 절전 → BIOS에서 ASPM Disabled로 고정
통신 저하·덤프케이블 규격 불일치·신호 감쇠 → 전용 케이블·Redriver 게인 조정
부하 급증 시 차단기 다운전력 초과 → nvidia-smi -pl 로 제한, systemd 자동 적용(안전 재점검)

08로컬 vs 클라우드, 그리고 여러 도구

로컬 서버는 OpenAI 호환 API(http://<추론머신-IP>:5000/v1)를 제공합니다. 이 주소를 코드·에이전트에 꽂아 씁니다.

로컬이 유리클라우드가 유리
언제데이터가 밖으로 나가면 안 될 때, 사용량이 많아 장기 비용이 클 때초기 투자·전기·소음·유지보수를 피하고 싶을 때
