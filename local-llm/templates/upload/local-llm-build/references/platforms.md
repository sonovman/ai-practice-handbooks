# 로컬 LLM 서버를 여러 도구에서 쓰기 (선택)

로컬 vLLM 서버는 OpenAI 호환 API(`http://<추론머신-IP>:5000/v1`)를 제공한다. 이 주소를 각 도구에 꽂는다.
단, 상용 앱마다 '외부 베이스 URL 지정'을 허용하는 범위가 다르니 설정에서 직접 확인한다.

| 쓰임 | 방법(개념) |
|---|---|
| ChatGPT·Claude·Gemini 공식 앱 | 기본적으로 자사 모델에 연결 — 임의의 로컬 서버로 바꾸는 건 제한적. 코드/SDK에서 OpenAI 호환 base_url로 연결 |
| 코딩 에이전트(opencode 등) | base_url을 로컬 서버로 지정해 로컬 모델로 코딩·자동화 |
| 사내 도구·스크립트 | OpenAI 호환 클라이언트에 base_url·api_key만 바꿔 연결 |
| Microsoft 365 Copilot | 조직 정책에 종속 — 로컬 모델 치환은 일반적으로 불가. 별도 사내 앱으로 연동 |

## Google Antigravity로 구축(선택)
- Antigravity는 에이전트가 폴더·코드를 직접 만드는 플랫폼이다(핸드북 16편). 서버·도커·시스템 설정 파일 초안을 맡기기 좋다.
- "이 부품 목록으로 docker-compose와 systemd 서비스 초안을 만들고, 전력 제한·ACS 비활성화 스크립트를 넣어 줘"처럼
  반복되는 설정 파일 작성을 에이전트에게 맡기고, 실제 적용·검증은 사람이 한다.

## 로컬 vs 클라우드 — 언제 무엇을
- 로컬이 유리: 데이터가 밖으로 안 나가야 할 때, 사용량이 많아 장기 비용이 클 때, 인프라 제어가 필요할 때.
- 클라우드가 유리: 초기 투자·전기·소음·유지보수를 피하고 싶을 때, 최상위 지능이 가끔만 필요할 때.
- 많은 경우 '둘 다': 민감·대량 작업은 로컬, 가끔의 최상위 작업은 클라우드로 나눈다.

## 주의
- 모델 제품·버전명(예: 특정 594B·27B·STT 모델)은 자주 바뀐다. '역할'로 기억하고 현재 최적 모델을 그때 확인한다.
- 로컬 서버를 외부에 노출할 때는 인증·방화벽을 둔다. 개인이 운영하는 불명의 중계 서버로 데이터를 보내지 않는다.
