# 품질 게이트 vs 취향 루브릭 — 구분과 체크리스트

## 둘을 왜 나누나
섞으면 검수가 흐려진다. 객관적인 건 기계처럼 걸러 내고(Pass/Fail), 정답 없는 스타일은 가이드로만 환기한다.

| | 품질 게이트(Quality Gate) | 취향 루브릭(Taste Rubric) |
|---|---|---|
| 정의 | 최소 기준 통과 여부를 객관 검수 | 정답 없는 스타일·맥락 가이드 |
| 판정 | Pass / Fail | 재현도 평가(디자인.md 기준) |
| 대상 | 맞춤법·어문, 사실관계(수치), 요구사항, 청중, 출처 | 레이아웃 다양성, 강약 전개, 색 절제, 폰트 비율, 정보 밀도 |
| 도구 | `slide_lint.py`(일부 자동) | 사람 + 비주얼 QA(`deck_html.py`로 미리보기) |

## 품질 게이트 체크리스트(통과해야 함)
- [ ] 슬라이드 수가 요구와 같은가
- [ ] 핵심 요구 키워드(3대 전략·로드맵·기대효과 등)가 모두 있는가
- [ ] 슬라이드의 수치·연도가 본문에 실제로 있는가(없는 수치 = 검토)
- [ ] 'A가 아니라 B' 등 AI 클리셰가 없는가
- [ ] 청중(보고용 격식 등)에 맞는 어조인가, 출처가 필요한 곳에 있는가

## 취향 루브릭 체크리스트(사람이 본다)
- [ ] 한 레이아웃 Type만 반복하지 않고 다양하게 섞였는가
- [ ] 슬라이드 1장의 정보가 과하지 않고 여백이 있는가
- [ ] 글자 겹침·줄바꿈 어색함·여백 쏠림이 없는가(비주얼 QA)
- [ ] 수치·키워드가 먼저 눈에 들어오는가(강약 전개)

## 흔한 실수(초기 접근 → 개선)
- "예쁘게 만들어줘" 한 줄 → AI가 단순 패턴만 반복. 디자인.md로 스타일을 명세한다.
- 품질과 취향을 한 번에 평가 → 기준이 흐려짐. 게이트(객관)와 루브릭(스타일)을 분리한다.
- 1차 결과를 그대로 사용 → 품질 게이트 + 비주얼 QA 루프를 거친 뒤 사람이 리터치한다.
