핸드북 01 · 에이전트 활용

에이전트는 한 명이면 충분하다

단독 에이전트와 멀티 에이전트 팀을 실제 테스트 결과로 비교하고, 기업 일반 업무와 지식재산(IP) 업무에 맞게 구축·운영하는 방법을 정리했습니다.

독자AI 에이전트를 업무에 들이려는 기업 실무자, IP 부서 담당자 분량읽기 약 20분 · 템플릿 2종 포함 판1.0 · 2026. 11. 6.
한 줄 결론

메인 일은 단독 에이전트 하나에 맡기고, 검수·대규모 조사가 필요한 순간에만 보조 에이전트를 부른다.

같은 과제에서 5인 에이전트 팀은 단독보다 최대 7배 느렸고 토큰은 약 2배 썼으며, 정답률도 높지 않았습니다. 단독 에이전트에 리뷰어 1명을 붙인 2인 체제가 속도와 완성도를 모두 챙겼습니다.

01실험 결과: 같은 과제, 세 가지 팀 구성

같은 개발 과제를 세 가지 구성에 맡기고 시간·토큰·완성도를 비교한 실험입니다.

품질은 비슷했지만 팀 구성의 토큰 사용량이 약 2배였습니다. 단독 에이전트는 필요할 때 스스로 탐색용 보조 에이전트를 불러 썼습니다.

읽을 때 주의 — 위 수치는 한 채널이 진행한 개발 과제 실험의 결과입니다. 업무 종류와 도구에 따라 차이는 달라질 수 있으니, 방향을 잡는 근거로 쓰고 절대 수치로 인용하지는 마세요.

02팀으로 쪼개면 왜 느려질까

① 같은 일을 여러 번 한다

단계마다 인수인계 문서를 쓰고, 같은 자료를 에이전트마다 다시 읽습니다. 시간과 토큰이 2~3배로 늘어납니다.

② 전화 게임이 일어난다

작은 일까지 쪼개 넘기면, 맥락이 전달되면서 조금씩 빠지고 바뀝니다. 마지막 에이전트는 처음 의도와 다른 일을 하게 됩니다.

기획→ 요약 →개발→ 요약 →검수→ 요약 →보안= 맥락 손실 누적

사람 조직도 마찬가지입니다. 한 사람이 처음부터 끝까지 맡는 편이 빠른 일이 있고, 그런 일은 나눌수록 손해입니다.

03언제 무엇을 쓰나

기본값

단독 에이전트

  • 기획→작성→점검까지 맥락이 이어져야 하는 일
  • 작은 수정, 대화하며 다듬는 일
  • 순서대로 진행되는 일
필요할 때만

보조(서브) 에이전트

  • 독립 검수: 끝난 결과를 새 눈으로 점검
  • 대규모 사전 조사: 넓은 범위를 나눠 동시에 훑기
  • 서로 무관한 병렬 작업

Anthropic의 Claude Code 문서도 비슷하게 안내합니다. 에이전트 팀은 조율 비용과 토큰이 더 들고, 순서대로 하는 일이나 같은 파일을 고치는 일은 단일 세션이 낫다는 것입니다.

04구축 3단계

  1. 하네스 세팅: 에이전트 한 명의 업무 환경 만들기 에이전트를 늘리기 전에, 메인 에이전트가 읽을 업무 매뉴얼(CLAUDE.md 또는 AGENTS.md)을 씁니다. 지켜야 할 규칙, 쓸 도구, “원본 삭제 금지” 같은 안전 규칙을 먼저 정합니다. 이렇게 환경을 갖추는 일을 하네스 엔지니어링이라고 부릅니다.
  2. 2인 체제: 메인 + 핀포인트 리뷰어 기획과 작성은 메인 에이전트가 끝까지 맡습니다. 다 끝난 뒤에만 독립된 리뷰어 1명(또는 /code-review 같은 검수 명령)을 불러 놓친 오류를 잡습니다.
  3. 루프: 기준을 통과할 때까지 스스로 고치게 하기 사람이 매번 확인하는 대신, “검수 → 수정 → 재검수”를 자동으로 돌립니다. 끝없이 돌지 않도록 ① 성공 기준, ② 검증자, ③ 최대 횟수(3~5회)를 미리 정해 둡니다.
메인 작성→리뷰어 검수→ 통과? →완료/ 아니면 수정 후 재검수 (최대 3회)

05바로 쓰는 템플릿

아래 두 파일은 템플릿 폴더에서 파일로도 받을 수 있습니다. [프로젝트명] 같은 괄호 부분만 바꿔 쓰세요.

템플릿 A · 업무 지침 문서 CLAUDE.md
# [프로젝트명] 업무 지침 (CLAUDE.md)

## 1. 역할과 목표
- 너는 이 프로젝트의 메인 에이전트다. 기획부터 작성, 기본 점검까지
  하나의 맥락을 유지하며 처리한다.

## 2. 작업 원칙
- 맥락 유지: 같은 세션의 이전 대화와 결과를 이어받아 작업한다.
- 길잡이 먼저: 자료를 찾을 때는 index.md 또는 docs/ 폴더를 먼저 본다.
- 작게 확인: 수정할 때마다 그 부분이 제대로 되는지 먼저 확인한다.

## 3. 안전 규칙
- 원본 보존: 원본 데이터와 설정 파일은 직접 지우지 않는다.
- 위험 명령: 삭제·초기화 명령은 실행 전에 사용자 승인을 받는다.
- 오류 반복: 같은 오류가 3번 반복되면 멈추고 상황을 보고한다.

## 4. 마무리 절차
- 작업이 끝나면 바로 종료하지 말고, 검수 프롬프트로 남은 오류를 점검한다.

06안전 장치 3겹

1겹 · 격리

따로 떨어진 작업 공간

개인 문서·비밀번호·금융 정보가 있는 PC와 분리된 가상 서버나 실습 환경에서 돌립니다.

2겹 · 규칙 + 차단

매뉴얼과 Hook

CLAUDE.md로 “삭제 금지”를 안내하고, Hook으로 위험 명령 자체를 막습니다. 안내는 무시될 수 있지만 차단은 무시되지 않습니다.

3겹 · 종료 조건

루프 상한

성공 기준과 최대 시도 횟수(3~5회)를 정해 시간과 비용이 새지 않게 합니다.

회사 자료 — 고객 정보, 미공개 실적, 출원 전 발명 내용은 회사가 승인한 AI 도구에만 넣으세요.

07일반 업무에 적용하기

기획·마케팅·영업 지원 같은 일은 빠른 처리, 낮은 비용, 일관된 맥락이 핵심입니다. 단독 에이전트 하나에 업무 지침과 스킬, 예약 실행을 붙이는 구성이면 충분합니다.

단독 에이전트+업무 지침·양식+예약 실행+메신저 알림
사례구축운영
아침 브리핑메일·캘린더 커넥터 연결매일 아침 정해진 시각에 메일과 일정을 훑어 핵심만 메신저로 보냄
견적서·제안서 초안사업자 정보·단가표·양식을 스킬로 등록“A사 맞춤 제안서” 한 줄 요청으로 양식에 맞춘 초안 생성
경쟁사 모니터링웹 검색 도구 + 모니터링 스킬6시간마다 확인하고 변동이 있을 때만 보고

08IP 업무에 적용하기

선행기술 조사, 명세서 작성, 침해 분석은 기술 맥락의 일관성과 엄격한 검증이 모두 필요합니다. 그래서 단독 메인 에이전트를 중심에 두고, 조사·검수·사람 승인을 필요한 지점에만 붙입니다.

메인 에이전트+병렬 조사+IP 리뷰어+담당자 승인

① 선행기술 조사·특허 맵 → 병렬 조사

메인 에이전트가 조사 방향을 잡으면, 보조 에이전트들이 IPC 분류별로 문헌을 동시에 모읍니다. 서로 겹치지 않는 조사라 병렬이 효과를 봅니다. 마지막 합성은 메인 에이전트가 맡아 맥락을 하나로 묶습니다.

② 명세서·청구항 작성 → 단독 전담

기술 개요부터 청구범위까지 에이전트 하나가 끝까지 씁니다. 나눠 맡기면 청구항과 상세한 설명 사이에 용어가 어긋나는 전화 게임이 생기기 쉽습니다.

③ 청구항 검토 → 리뷰어 루프

  1. 메인 에이전트가 쓴 청구항을 IP 리뷰어에게 넘깁니다.
  2. 리뷰어가 “신규성·진보성 부정 가능성 2건”처럼 지적합니다.
  3. 메인 에이전트가 고치고 다시 검수받습니다. 지적이 0건이 되거나 3회에 이르면 멈춥니다.

④ FTO 분석·출원 결재 → 사람 승인 단계

법적 책임이 따르는 판단은 AI가 혼자 내보내지 못하게 합니다. 보고서가 검수를 통과해도 IP 팀장이 승인해야만 외부 사무소로 전달되도록 흐름을 짭니다(Human-in-the-Loop).

초안 작성→리뷰어 루프→팀장 승인→외부 전달
책임의 위치 — AI의 검토 결과는 초안입니다. 특허성, 침해 여부에 대한 최종 판단은 변리사와 담당자가 합니다.

09MS Copilot Studio · Power Automate로 구현하기

Microsoft 365를 쓰는 회사라면 Copilot Studio로 에이전트의 역할과 지침을 만들고, Power Automate로 예약 실행·반복·승인을 연결하면 됩니다.

개념MS 기능하는 일
하네스Copilot Studio 지침·지식역할, 업무 매뉴얼, 사내 파일을 연결해 작업 환경과 규칙을 세팅
스킬·커넥터Copilot 작업(Actions)·커스텀 커넥터자주 쓰는 양식과 외부 API·DB 연동
예약 실행Power Automate 예약 트리거매일 아침 브리핑, 6시간 간격 모니터링
루프Power Automate 조건 반복검수 통과까지 수정 반복, 최대 횟수 제한
사람 승인Power Automate 승인(Approvals)Teams·Outlook으로 승인 카드 발송, 승인 시에만 다음 단계 진행

예: 아침 브리핑 흐름

  1. 예약 트리거매일 08:30에 Power Automate 흐름이 시작됩니다.
  2. 수집Outlook 메일과 캘린더에서 오늘 항목을 가져옵니다.
  3. 요약Copilot 에이전트가 업무 지침에 따라 우선순위를 매겨 요약합니다.
  4. 알림Teams 채팅으로 담당자에게 보냅니다.
