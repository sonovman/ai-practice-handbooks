# 경영진 브리핑 요약 (논문·보고서)

판례·판결문이면 `case-brief` 스킬을 씁니다. 모델의 생각 설정(노력·Thinking)은 높게 둡니다.

## 0. 준비 — 세 가지를 먼저 확인
1. **누가 읽나**: CEO / CFO / CTO / 연구 책임자 / 외부 전문가. 없으면 "실무 책임자".
2. **무엇을 결정하나**: 이 요약을 읽고 내릴 결정 한 문장(예: "이 기술을 내년 시범 도입할지"). 없으면 되묻고, 그래도 없으면 "정보 공유용"으로 표시.
3. **문서 종류와 분야**: 논문(의학·생명 / AI·컴퓨터 / 사회과학·정책 / 기타) 또는 보고서. 판별 근거 한 줄을 보이고 애매하면 확인받습니다.
기밀 여부를 묻고, 기밀이면 사용자가 승인한 환경인지 확인합니다.

## 1. 추출 — 원문 사실표 (요약하기 전에)
- `references/fact-sheet.md` 형식으로 사실을 뽑습니다: 주장 | 원문 구절(그대로) | 위치(쪽·절·표) | 수치·단위.
- 긴 문서는 **절(section)마다** 사실표를 만든 뒤 합칩니다. 한 번에 전체를 요약하지 않습니다(긴 문맥의 가운데 정보를 놓치기 쉬움).
- 표·그림의 수치는 본문과 다르면 둘 다 적고 '불일치'로 표시합니다.

## 2. 점검 — 증거의 한계 (Slow Think)
| 핵심 주장 | 근거 강도(강/중/약) | 한계·의심 | 원문이 말하지 않는 것 |
- 분야별로 먼저 의심할 것은 `references/frame-*.md`의 '먼저 의심할 것'.
- 저자의 결론 문장이 데이터보다 강하게 쓰였으면 표시합니다(예: 상관을 인과로, 대리 지표를 임상 결과로).

## 3. 작성 — 결론 먼저, 1쪽
`references/brief-template.md`를 따릅니다: 한 줄 결론과 신뢰도 → 결정에 주는 의미 → 핵심 근거 3개 [원문] → 기존 대비 → 위험·한계 → 선택지와 권고 [해석] → 확인할 사실·다음 행동 → 부록(분야별 상세).
- 신뢰도·영향 범위는 `references/impact-rubric.md`의 정의로만 매깁니다.
- 원문에 비교 대상이 없으면 '기존 대비'에 "원문에 비교 없음"이라고 씁니다. 외부 지식으로 채우지 않습니다.

## 4. 밀도 조정 (선택)
더 짧게 요청받으면 같은 길이에서 빠진 핵심 개체(수치·대상·조건)를 넣고 군더더기를 빼는 과정을 **최대 2회**만 합니다. 너무 빽빽하면 경영진이 읽기 어렵습니다.

## 5. 검증 (생략 금지)
1. 틀리기 쉬운 주장 5개를 골라 원문에서 근거를 다시 찾고, 못 찾으면 지웁니다.
2. 작업 폴더가 있으면:
   - `python tools/evidence_check.py <원문> <브리핑.md> --report work/…/evidence.md`
   - `python tools/term_check.py <브리핑.md> --glossary glossary/*.csv --source <원문> --report work/…/terms.md`
3. 실패 항목을 고친 뒤, 브리핑 끝에 `검증: 인용 n/n 확인 · 수치 이상 없음 · 용어 경고 n` 한 줄을 붙입니다.
