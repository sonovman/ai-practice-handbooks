# 판례·규제 결정 브리핑

모델의 생각 설정은 높게 둡니다. **판결문 원문이 없으면 요약하지 않습니다.** 사용자가 사건번호만 주면 원문(공식 DB 내려받기, 8편의 법제처 연결 등)을 먼저 요청합니다.

## 0. 준비
1. 읽는 사람(CEO / CLO·법무 / 사업부 / 변리사·변호사)과 결정할 것(예: 우리 제품의 설계 변경 필요 여부)
2. **관할과 심급**: 국가, 법원, 심급, 선고일, 사건번호 — 원문 그대로. `references/jurisdictions.md`에서 그 관할의 구조를 확인합니다.
3. 우리 상황과 비교할 사실(제품·계약·행위)을 사용자에게 받습니다. 없으면 [해석]은 일반론으로만.

## 1. 추출 — 판결 사실표
| 항목 | 원문 구절(그대로) | 위치(쪽·단락) |
- 사건 표지 / 당사자 / 사실관계 / 절차 경과 / 쟁점 / 법원의 판단(결론) / 판단 이유 / 별개·반대의견 / 주문 / 참조 조문 / 원문이 인용한 판례
- 한국 공보 판례는 법원이 작성한 판시사항·판결요지가 있으면 그대로 옮기고, 본문 판단과 구분합니다.

## 2. 점검
- 이 판단은 **어떤 사실관계 위에서** 나왔는가 — 결론을 뒷받침하는 핵심 사실 3개
- 판단 중 결론에 필요한 부분과 덧붙인 말(방론·obiter·dicta)의 구분
- 선례 가치: 상급심인가, 전원합의체·en banc인가, 비공개·비선례(non-precedential)인가, 기존 판례를 변경했다고 **원문이 말하는가**
- 이후 파기·변경·후속 판결 여부는 모델이 알 수 없음 → 확인할 사실로

## 3. 작성 — `references/case-template.md`
한 줄 결론과 위험 등급 → 사건 표지 → 사실·쟁점 → 판단과 이유 [원문] → 별개·반대의견 → 선례 가치 → 우리에게 주는 의미 [해석] → 대응 선택지 [해석] → 확인할 사실.
- 위험 등급은 `references/risk-rubric.md`로만.
- 원문이 인용하지 않은 판례를 기억으로 덧붙이지 않습니다. 필요하면 "공식 DB에서 확인할 후보: 쟁점 ○○ 관련 대법원 판례"처럼 번호 없이 적습니다.

## 4. 검증 (생략 금지)
- `python tools/cite_check.py <브리핑.md> --source <판결문.txt> [다른 원문…] --report work/…/cite.md`
- `python tools/evidence_check.py <판결문.txt> <브리핑.md> --report work/…/evidence.md`
- `python tools/term_check.py <브리핑.md> --glossary glossary/patent-legal.csv --source <판결문>` (영문 판결일 때)
- 실패 항목을 고치고, 끝에 `검증: 판례 인용 n건(원문 밖 0) · 인용 n/n · 용어 경고 n` 한 줄.
- 서면·대외 문서에 쓰기 전 모든 판례를 공식 DB에서 열어 확인하라는 문장을 남깁니다.
