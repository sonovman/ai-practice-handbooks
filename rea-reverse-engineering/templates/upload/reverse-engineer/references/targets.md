# 대상별 분석 메모 (적법 범위 전제)

| 대상 | REA 접근 | 근거로 받는 것 | 적법 범위 예 |
|---|---|---|---|
| 네이티브 바이너리(.exe/.dll/ELF/Mach-O) | Ghidra·IDA·Hopper 연결, procedure_pseudo_code/assembly/xrefs | 어셈블리, 의사코드, 메모리 상수, 호출 관계 | 내가 만든 바이너리의 계산 규칙 복원, 내가 소유한 레트로 게임의 수식 학습 |
| Electron/JS 앱(.asar·번들) | analyze-javascript-application, IPC·모듈·소스맵 | preload/main 소스 위치, IPC 채널명, 모듈 의존성 | 내가 만든 Electron 앱 구조 파악, 오픈소스 앱(라이선스 확인) 학습 |
| Android APK | JADX 계열 연동 | 디컴파일 Java/Kotlin, 매니페스트, 권한 | 내 앱의 난독화 전 동작 확인, 보안 연구(허가된 대상) |
| 파일 포맷 | 바이너리/문자열 분석 | 헤더·필드 배치, 인코딩 | 내 데이터가 든 독자 포맷에서 내 데이터 꺼내기(이식) |
| 웹앱/HAR | inspect_web_page(수동), .har | 엔드포인트·헤더·페이로드 스키마, JS 소스 범위 | 내 웹앱 디버깅, 공개 API 호환 클라이언트 |

## 공통 원칙
- 아이디어·원리·사실(수식, 바이트 배치, 프로토콜)은 배우고 재구현 가능. 표현(소스·리소스·그래픽·UI)은 복사 금지.
- 서버 측 로직, 암호화 실시간 피드, 보호조치 뒤의 내용은 분석 대상에서 제외.
- 각 단계의 근거를 evidence_log 에 남기고, 미확인은 미확인으로.
