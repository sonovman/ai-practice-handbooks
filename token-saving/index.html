클로드 코드 토큰·비용 절약 — 어디서 돈이 나가는지부터 숫자로

최신 모델은 강력한 만큼 토큰을 많이 씁니다. 잠깐 방심하면 비용이 훌쩍 커질 수 있습니다. 핵심은 ‘아껴 쓰라’는 당부가 아니라, 어디서 돈이 나가는지를 먼저 숫자로 보고 구조적으로 통제하는 것입니다. 이 편은 토큰이 급증하는 원인과 프롬프트 캐시의 원리를 풀고, 세션·입력·출력을 통제하는 방법을, 직접 돌려 본 비용 계산기와 세션 시뮬레이터와 함께 초보자도 따라 하기 쉽게 설명합니다.

독자클로드 코드를 쓰며 토큰 비용이 부담스러운 사람, 비용을 통제하고 싶은 초보자 분량읽기 약 20분 · 템플릿(토큰 비용 계산기 · 세션 시뮬레이터 · 절약 스킬 · 프롬프트 5종 · 시범) 판1.0 · 2026. 11. 8.
한 줄 결론

AI는 매 턴 ‘그동안의 전체’를 다시 보냅니다 — 그래서 세션을 짧게 비우고(/clear), 앞부분은 캐시로 고정하고, 출력은 간결하게 하는 것만으로 비용이 크게 줄어듭니다.

40번째 턴에서는 앞선 39턴 전체가 다시 전송됩니다. 그래서 길수록 비용이 급증합니다. 해법은 세 가지입니다. ① 작업이 바뀌면 세션을 비우고, ② 시스템·프로젝트 정보 같은 앞부분을 바꾸지 않아 캐시가 유지되게 하고, ③ 흔히 더 비싼 출력·사고 토큰을 간결하게 통제합니다.

무엇을 확인했나 — 토큰 비용 계산기(시험 5개)·세션 시뮬레이터(시험 5개)를 직접 만들어 돌렸습니다(4·5장 시범). 슬래시 명령(/context·/rewind·/usage)과 프롬프트 캐시(앞부분 재사용·캐시 읽기 할인)는 공식 자료로 확인했습니다(부록). 단가·비율(출력이 더 비쌈, 캐시 읽기가 쌈)은 모델·시점마다 달라 ‘현재 공식 단가로 확인’을 전제로 예시만 씁니다. 원고가 소개한 외부 스킬(Caveman·Ponytail)의 구체 수치·설치법은 독립 검증이 어려워 개념·보안 중심으로 다룹니다. 이 편은 유튜브 링크가 제공되지 않아 영상 자료는 쓰지 않았습니다.

01왜 비용이 급증하나 — 4가지 원인

원인설명
매 턴 전체 재전송읽은 파일·로그·대화가 ‘남은 모든 턴마다’ 다시 전송됨. 40턴째엔 39턴 전체가 재전송 → 급증
노이즈 누적안 보는 파일, 수백 줄 테스트 로그, 안 쓰는 MCP·플러그인이 매 턴 함께 실림
출력·사고 토큰출력은 입력보다 비싸고(모델별, 흔히 수 배), 내부 ‘사고(thinking)’도 출력으로 계산됨
캐시 깨짐세션 중간에 모델·에포트를 바꾸면 프롬프트 캐시가 무효화돼 처음부터 다시 계산
한눈에 — 비용의 뿌리는 ‘AI는 기억하지 않고 매번 전체를 다시 읽는다’입니다. 그러니 다시 읽을 양을 줄이는 것(세션 비우기·노이즈 제거)과 다시 읽을 때 싸게 하는 것(캐시)이 두 축입니다. 원리는 26편에서 더 깊이 다룹니다.

02프롬프트 캐시 — 앞부분을 싸게

프롬프트 캐시는 요청의 앞부분이 이전과 같으면 서버가 계산해 둔 결과를 재활용하는 기술입니다.

A시스템 프롬프트

그다음 칸

그다음 칸

여기만 새로 계산

기차 칸처럼 — 캐시는 앞칸부터 순서대로 대조합니다. 앞칸 하나라도 바뀌면 뒤 칸이 전부 무효화됩니다. 그래서 세션 중간에 모델·에포트를 바꾸면 캐시가 깨져 처음부터 다시 계산합니다. 반대로 앞부분(시스템·프로젝트 정보)을 고정하면 캐시 읽기로 훨씬 싸게 재사용합니다(4장에서 숫자로). 모델·에포트는 세션 시작에 고정하세요.

03처음 접근과 바뀐 점

① “한 세션에서 계속” → 작업 바뀌면 /clear — 세션이 길수록 매 턴 재전송량이 눈덩이처럼 커지고 품질도 떨어집니다. 작업·주제가 바뀌면 비용이 0인 /clear로 비웁니다. 반복 배경은 하네스로 재사용해 자주 비워도 이어집니다.
② “싼 모델로 중간에 변경” → 설정은 시작에 고정 — 세션 도중 하이쿠 같은 저렴한 모델로 바꾸면 그 모델용 캐시를 새로 만들어야 해 오히려 더 비쌀 수 있습니다. 모델·에포트는 세션 시작에 정합니다.
③ “출력은 공짜 같다” → 출력·사고가 큰 몫 — 출력은 입력보다 비싸고, 눈에 안 보이는 ‘사고 토큰’도 출력으로 계산됩니다. 단순 작업은 사고 예산을 낮추고 출력을 간결하게 유도합니다.
④ “오류 수정해 줘” → 파일·위치를 정확히 — 모호하게 시키면 AI가 파일을 뒤지며 토큰을 씁니다. 파일은 @멘션으로 지목하고 문제 위치를 정확히 주면 탐색 토큰이 줄어듭니다.
⑤ “긴 로그를 그대로” → 필요한 것만 짧게 — 수백 줄 테스트 로그가 컨텍스트에 남아 매 턴 재전송됩니다. 요약 옵션·스크립트로 핵심만 출력하고, 안 쓰는 MCP·플러그인은 /context로 정리합니다.
⑥ “절약 스킬이면 무조건 이득” → 한계·보안 확인 — 출력을 줄이는 외부 스킬은 입력·사고 토큰은 못 줄이고 지침 자체가 매 턴 입력을 더해 짧은 대화엔 역효과입니다. 미검증 외부 스킬은 보안 위험도 있으니 출처·효과를 확인하고 씁니다(7장).

04비용 진단 — 캐시 전후 비교(시범)

token_cost.py로 같은 요청을 캐시 전후로 계산했습니다(예시 단가: 입력 $3, 출력 $15 / 100만 토큰).

$ python tools/token_cost.py --in 50000 --out 3000 --in-price 3 --out-price 15
입력(비캐시) 50,000 → $0.1500 (77%) · 출력 3,000 → $0.0450 (23%) · 합계 $0.1950

$ python tools/token_cost.py --cache-read 48000 --in 2000 --out 3000 --in-price 3 --out-price 15
캐시읽기 48,000 → $0.0144 · 새 입력 2,000 → $0.0060 · 출력 3,000 → $0.0450 · 합계 $0.0654
무엇을 배우나 — 앞부분 4.8만 토큰을 캐시 읽기로 재사용하자 같은 요청이 $0.195 → $0.065로 3분의 1이 됐습니다. 캐시가 들어오니 이번엔 출력이 비용의 가장 큰 몫(69%)이 됩니다 — 그래서 출력·사고 토큰 통제가 다음 레버입니다. 단가는 모델·시점마다 다르니 현재 공식 단가로 확인하세요.

05세션 경제성 — 40턴이면 얼마?(시범)

session_sim.py로 40턴 세션의 누적 비용을 세 시나리오로 비교했습니다(턴당 입력·출력 1,500, 시작 고정분 1.2만, 예시 단가).

$ python tools/session_sim.py --turns 40 --turn-input 1500 --turn-output 1500 \
     --start-context 12000 --in-price 3 --out-price 15 --clear-every 10

| 캐시 없음, /clear 없음      | $9.540 | 100% |
| 캐시 사용, /clear 없음      | $1.926 |  20% |
| 캐시 + 10턴마다 /clear      | $1.386 |  15% |
무엇을 배우나 — 같은 40턴이라도 캐시만으로 1/5, 거기에 /clear까지 하면 약 1/7로 줄었습니다. ‘매 턴 전체 재전송’ 때문에 비용은 턴 수에 비례하는 게 아니라 더 가파르게 늘어납니다. 그래서 길게 끌지 말고 비우는 습관이 돈을 아낍니다. (수치는 구조적 경향을 보는 근사입니다.)

06세션·입력 관리 — 슬래시 명령과 습관

명령/습관용도
/clear대화·컨텍스트 비우기 — 작업/주제 전환 시
/context무엇이 창을 차지하나 확인 · 안 쓰는 MCP·플러그인 정리
/rewind방향이 틀어졌을 때 이전 턴으로 되돌리기(재시작 없이)
/usage최근 토큰 소모(스킬·MCP·플러그인별) 분석
@멘션파일을 직접 지목 → 불필요한 탐색 토큰 절감
설정 고정모델·에포트는 세션 시작에 — 중간 변경은 캐시 깨짐
습관으로 — 오류는 “테스트 실패” 대신 파일·위치를 정확히, 터미널 출력은 요약 옵션·스크립트로 짧게, 반복 배경은 슬림 CLAUDE.md·스킬로 재사용 구조화(하네스)합니다. 슬래시 명령·동작은 버전에 따라 바뀌니 /help로 현재 명령을 확인하세요.

07외부 ‘출력절감’ 스킬 — 개념·한계·보안

설명·코드 출력을 줄여 출력 토큰을 아끼려는 커뮤니티 스킬이 있습니다(원고가 소개한 Caveman·Ponytail 등). 개념은 유용하지만 그대로 믿기보다 한계와 보안을 먼저 봅니다.

구분내용
개념불필요한 사설·과잉 설계를 줄여 출력/생성 코드를 간결하게
한계입력·사고 토큰은 못 줄임 · 스킬 지침이 매 턴 입력 오버헤드를 더함 → 짧은 대화엔 역효과
학습설명을 잘라내므로 초보자·학습자에겐 교육 효과↓
보안검증 안 된 외부 스킬·curl|bash는 프롬프트 주입·.env 등 정보 유출 위험
안전하게 쓰려면 — 출처(저장소·제작자)를 확인하고, .claude/settings.json의 deny 규칙·샌드박스 설정으로 파일·환경변수 접근을 제한합니다. 구체 절감 수치는 환경마다 다르니, 먼저 token_cost.py로 ‘내 경우’에 이득인지 확인한 뒤 적용하세요. 설치 명령·옵션은 각 저장소의 현재 안내를 따릅니다.

08도구별 적용과 주의할 점

‘매 턴 전체를 다시 본다’는 구조는 대부분의 LLM 도구에 공통입니다. Antigravity에는 슬림 CLAUDE.md·출력 요약·세션 체크리스트를 갖춘 하네스 초안 작성을 맡기고 적용·검증은 사람이 합니다.

상황이렇게
긴 세션작업 전환 시 /clear. 반복 배경은 하네스로 재사용.
중간 설정 변경모델·에포트는 시작에 고정(캐시 깨짐 방지).
출력·사고 비용간결 출력·낮은 사고 예산. token_cost.py로 먼저 확인.
모호한 지시@멘션으로 파일 지목, 오류는 위치까지.
긴 로그·안 쓰는 MCP출력 요약, /context로 정리.
외부 절감 스킬한계·보안 확인 후. 짧은 대화엔 역효과.
단가·명령자주 바뀜. 공식 단가·/help로 확인.
미검증 스크립트프롬프트 주입·유출 위험. deny·샌드박스 설정.
