# 클로드 코드 토큰·비용 절약

최신 모델은 강력한 만큼 토큰을 많이 씁니다. 방심하면 비용이 크게 나올 수 있으니 구조적으로 통제합니다.

## 왜 급증하나 (원인)
- 매 턴 전체 재전송: 읽은 파일·로그·대화가 '남은 모든 턴마다' 다시 전송돼 길수록 급증.
- 노이즈 누적: 안 보는 파일, 긴 테스트 로그, 안 쓰는 MCP·플러그인이 매 턴 얹힘.
- 출력·사고 토큰: 출력은 입력보다 비싸고(모델별, 흔히 수 배), 내부 사고도 출력으로 계산됨.
- 캐시 깨짐: 세션 중간에 모델·에포트를 바꾸면 프롬프트 캐시가 무효화돼 처음부터 다시 계산.

## 통제법
1. **세션을 짧게·/clear**: 작업/주제가 바뀌면 /clear 로 비운다(길면 비용↑·품질↓). `session_sim.py`로 효과 확인.
2. **설정은 시작 시 고정**: 모델·에포트는 세션 시작에 정한다(중간 변경 = 캐시 깨짐).
3. **캐시 활용**: 앞부분(시스템·프로젝트 정보·CLAUDE.md)을 자주 바꾸지 않으면 캐시 읽기로 싸진다. `token_cost.py`로 비교.
4. **슬래시 명령**: /context(무엇이 창을 먹나·안 쓰는 MCP 끄기), /rewind(방향 틀어지면 되돌리기), /usage(최근 소모 분석).
5. **입력 최적화**: 파일은 @멘션으로 지목, 오류는 파일·위치를 정확히, 터미널 출력은 필요한 것만 짧게.
6. **하네스**: 반복 배경·규칙을 CLAUDE.md(슬림)·스킬로 재사용 구조화 → 세션을 자주 비워도 연속성 유지.

## 외부 '출력 절감' 스킬 (Caveman·Ponytail 등)
- 설명/코드 출력을 줄여 출력 토큰을 아끼려는 커뮤니티 스킬이 있다. 효과·수치는 환경마다 다르니 맹신 금지.
- 한계: 입력·사고 토큰은 못 줄이고, 스킬 지침 자체가 매 턴 입력 오버헤드를 더한다. 짧은 대화엔 역효과.
- 초보자에겐 설명이 사라져 학습에 불리. **보안**: 검증 안 된 외부 스킬·`curl|bash`는 프롬프트 주입·정보 유출 위험 →
  출처 확인, .claude/settings.json 의 deny·샌드박스 설정으로 제한.
